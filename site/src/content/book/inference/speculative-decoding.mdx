上一章用量化减少每步读取的字节数。本章换一个角度：**让每次读取产出更多 token**。[成本模型](/inference/inference-cost/)说明，批大小为 1 的 decode 步算术强度只有约 1 FLOP/B，远低于 H100 的拐点 295 FLOP/B，GPU 的算力几乎全部闲置。既然多算几个 token 几乎不增加时间——权重只读一遍，对 $k+1$ 个 token 一起算——那能不能先**猜**出后面几个 token，再用大模型一次性验证？

猜对的 token 就是白赚的；猜错了，也只是退回到大模型自己的下一个 token，没有损失。这就是投机解码（speculative decoding，Leviathan 等 2022；Chen 等 2023）。它真正令人惊讶之处在于：**只要验证规则选对，输出的分布与只用大模型采样完全相同**——它是无损的加速。本章先给出验证规则并完整证明这一点，再推导能快多少，实现它，然后讨论“谁来猜”：独立的小模型、n-gram、Medusa、EAGLE 和多 token 预测（MTP）。

## 草稿与验证

记大模型（目标模型，target）在前缀 $x_{<t}$ 之后的下一 token 分布为 $p(\cdot)$，小模型（草稿模型，draft）的分布为 $q(\cdot)$，两者共用词表。一轮投机解码包括：

1. **草稿**：小模型自回归地采样 $k$ 个 token $\tilde x_1,\dots,\tilde x_k$，同时记下每一步的分布 $q_1,\dots,q_k$。
2. **验证**：把 $[\,x_{<t},\tilde x_1,\dots,\tilde x_k\,]$ 送入大模型做**一次前向**，因果注意力使得它同时给出 $k+1$ 个位置的分布 $p_1,\dots,p_{k+1}$（$p_i$ 是在已接受前缀加上前 $i-1$ 个草稿之后的下一 token 分布）。
3. **接受或拒绝**：从左到右依次处理，第 $i$ 个草稿以概率 $\min(1,\,p_i(\tilde x_i)/q_i(\tilde x_i))$ 被接受。遇到第一个被拒绝的位置 $i$，丢弃它和之后所有草稿，改从**残差分布**重新采样一个 token；若 $k$ 个都被接受，则再从 $p_{k+1}$ 采样一个“奖励 token”。

为什么验证 $k+1$ 个位置和验证一个位置几乎一样快？Llama-3-8B 在 H100 上，批大小 1，单步算术强度约 1 FLOP/B；一次处理 $k+1=5$ 个 token，FLOPs 变成 5 倍，权重读取量不变，算术强度约 5 FLOP/B，仍然远低于拐点 295。时间由读取权重决定，并没有变。

## 接受-拒绝采样不改变分布

下面的证明是整章的核心。先考虑一个位置，目标分布 $p$，草稿分布 $q$。草稿 $\tilde x\sim q$，以概率 $\min(1,p(\tilde x)/q(\tilde x))$ 接受；被拒绝时从

$$
p'(x)=\frac{\max\big(0,\,p(x)-q(x)\big)}{\sum_{y}\max\big(0,\,p(y)-q(y)\big)}
$$

采样。记最终输出为 $X$。

<Definition term="接受-拒绝采样的正确性" kind="定理" source="https://arxiv.org/abs/2211.17192">

对任意分布 $p,q$（$q(x)=0$ 时 $p(x)$ 也可以非零，此时该 token 只会来自残差分布），最终输出 $X$ 服从 $p$。

</Definition>

**证明。** 对固定的 token $x$，$X=x$ 有两种互斥的发生方式：草稿恰好是 $x$ 且被接受，或草稿被拒绝且重采样得到 $x$。

第一种：草稿是 $x$ 的概率是 $q(x)$，被接受的概率是 $\min(1,p(x)/q(x))$，乘起来

$$
P(\text{草稿}=x,\ \text{接受})=q(x)\min\!\Big(1,\frac{p(x)}{q(x)}\Big)=\min\big(p(x),\,q(x)\big).
$$

对所有 $x$ 求和得到总接受概率 $\beta=\sum_x\min(p(x),q(x))$。

第二种：总拒绝概率是 $1-\beta$。再看残差分布的归一化常数。因为 $\sum_x p(x)=\sum_x q(x)=1$，

$$
\sum_x\max\big(0,p(x)-q(x)\big)=\sum_x\big(p(x)-\min(p(x),q(x))\big)=1-\beta ,
$$

这用到了恒等式 $\max(0,a-b)=a-\min(a,b)$。所以残差分布的分母**恰好等于拒绝概率** $1-\beta$，于是

$$
P(\text{拒绝},\ \text{重采样}=x)=(1-\beta)\cdot\frac{\max(0,p(x)-q(x))}{1-\beta}=\max\big(0,\,p(x)-q(x)\big).
$$

两种方式相加：

<KeyEq label="单位置的无损性">

$$
P(X=x)=\min\big(p(x),q(x)\big)+\max\big(0,p(x)-q(x)\big)=p(x).\qquad\blacksquare
$$

</KeyEq>

最后一步还是那条恒等式：$\min(a,b)+\max(0,a-b)=a$。另一个副产品是接受率 $\beta=\sum_x\min(p,q)=1-\mathrm{TV}(p,q)$，其中 $\mathrm{TV}$ 是总变差距离——草稿分布越接近目标分布，接受率越高；$q=p$ 时 $\beta=1$，永远不拒绝。

**扩展到 $k$ 个 token。** 把整个多步过程看成链式法则。第一个位置的输出分布是 $p_1$（上面刚证明）。如果第一个草稿被接受，输出就是 $\tilde x_1$，此时第二个位置的前缀是 $(x_{<t},\tilde x_1)$，而 $p_2$ 正是目标模型在这个前缀下的分布；被拒绝时，输出是残差分布采出的 token，后面的草稿全部丢弃，下一轮从这个新前缀重新开始。因此在每个位置，“以前缀为条件，输出分布等于目标分布”都成立，由链式法则 $P(x_1,x_2,\dots)=\prod_i P(x_i\mid x_{<i})$，整个序列的联合分布与直接从目标模型采样一致。全部接受时的奖励 token 直接取自 $p_{k+1}$，同样满足。

## 能快多少

### 期望产出

设每个位置的接受概率相互独立，均为 $\alpha=\beta$（这是个理想化假设；实际上接受率随上下文变化）。一轮产出的 token 数 $N$ 等于“第一次拒绝之前被接受的草稿数”加 1（拒绝位置的修正 token，或全部接受时的奖励 token）。$P(N=n)=\alpha^{n-1}(1-\alpha)$（$n=1,\dots,k$），$P(N=k+1)=\alpha^k$。期望是

$$
\mathbb E[N]=\sum_{n=1}^{k}n\,\alpha^{n-1}(1-\alpha)+(k+1)\alpha^k=\sum_{i=0}^{k}\alpha^i=\frac{1-\alpha^{k+1}}{1-\alpha}.
$$

最后一步用了一个技巧：$\mathbb E[N]=\sum_{n\ge1}P(N\ge n)$，而 $P(N\ge n)=\alpha^{n-1}$（前 $n-1$ 个草稿都被接受），$n$ 从 1 到 $k+1$，正好是 $1+\alpha+\dots+\alpha^k$。

### 加速比

设草稿模型一步耗时是目标模型的 $c$ 倍（独立小模型通常 $c\approx0.02$—$0.1$），一轮的耗时是 $k$ 次草稿加一次验证，约 $kc+1$ 个目标步（忽略验证 $k+1$ 个位置比 1 个位置略慢）。普通解码每个目标步产出 1 个 token，所以

<KeyEq label="投机解码的加速比">

$$
S(\alpha,k,c)=\frac{\mathbb E[N]}{kc+1}=\frac{1-\alpha^{k+1}}{(1-\alpha)(kc+1)}.
$$

</KeyEq>

## 树形草稿

单条草稿链的弱点在于：第一个错误就让后面的所有草稿作废。更好的办法是在“可能出错”的位置提出**多个候选**，组成一棵树，让目标模型一次验证整棵树，选出最长的被接受路径。

树中的每个节点是一个候选 token，它的父节点是它之前的那个 token。一次前向要处理树中所有 $n$ 个节点，每个节点只能看到自己和它的祖先（以及已确认的前缀），不能看到兄弟或其他分支。这需要一个**树形注意力掩码**，位置编码也不再是“前缀长度 + 序号”，而是“前缀长度 + 深度”。

几处值得说明的细节：

- **KV Cache 的回滚。** 目标模型的缓存在验证时写入了 $k+1$ 个位置的 K/V，但只有被接受的那部分有效。不需要真正擦除——我们只维护“有效长度”`t_len`，被拒绝位置的旧内容会在下次写入时被覆盖（因为下一轮的输入从 `seq[t_len:]` 开始，位置从 `t_len` 起）。在 PagedAttention 里对应的是只把有效长度往回拨，必要时释放整块。
- **草稿缓存的补齐。** 草稿模型只前向了前 $k-1$ 个草稿 token（最后一个草稿 token 不需要再送入草稿模型，它的 K/V 在下一轮才有用）。如果目标模型修正了某个位置，草稿缓存里该位置之后的内容作废；下一轮开始时先用 `seq[d_len:]` 补齐缺的 token。
- **上下文边界。** `kk = min(k, max_new_tokens - produced - 1, ctx - len(seq))` 保证最后一轮不会超出所需的 token 数或模型的上下文长度。

## 谁来猜：草稿的来源

投机解码的工程难点是草稿——它必须足够快（$c$ 小）、足够准（$\alpha$ 高），还要容易部署。

### 独立的小模型

最直接的做法：用同一系列的小模型（Llama-3-70B 配 Llama-3-8B 或 1B）。要求词表相同。缺点是两个模型都要占显存和 KV Cache，草稿模型的开销 $c$ 不容忽视（$c\approx0.1$），而且它与大模型是分别训练的，接受率只有中等水平（$\alpha\approx0.6$—$0.8$）。

### 没有模型的草稿：n-gram 与提示查找

很多场景下，输出中大量内容是提示里已有的片段（摘要、代码编辑、RAG 问答的引用）。**提示查找解码**（prompt lookup decoding）直接在上下文里找当前后缀的 n-gram 匹配，把匹配之后的几个 token 当作草稿，$c\approx0$。vLLM 的 `ngram` 方法就是如此。它没有训练成本，对重复度高的任务可达 2—3 倍加速，其他任务则接受率接近 0，但也几乎不亏。

### Medusa：在目标模型上加多个预测头

Medusa（Cai 等，2024）不用另一个模型，而是在目标模型最后一层隐状态上加 $m$ 个额外的小 MLP 头，第 $i$ 个头预测第 $t+i$ 个 token。这样草稿**只需一次前向**（读目标模型的隐状态），没有第二个模型和第二套 KV Cache。每个头给出 top-$s$ 个候选，笛卡尔积组成一棵树，用上一节的树形注意力验证。缺点是各头相互独立预测，没有考虑前面已经猜了什么，所以越靠后的头准确率越低。

### EAGLE：在特征层面自回归

EAGLE（Li 等，2024）的观察是：预测下一个 token 的**特征**（倒数第二层的隐状态）比直接预测 token 更容易，但特征序列的不确定性主要来自采样出的 token。因此草稿模型是一个只有一层 Transformer 的小网络，输入是目标模型上一步的特征**以及已采样 token 的嵌入**，自回归地预测下一步特征，再复用目标模型的 LM head 得到 token 分布。它比 Medusa 的接受率高得多。EAGLE-2（2024）根据草稿模型自己的置信度动态调整树的形状：置信度高的分支展开得更深。EAGLE-3（2025）取消了特征预测，改为融合目标模型的低、中、高三层特征，并在训练时把草稿自己的预测喂回去（training-time test），论文报告在 Llama 3.1 8B 等模型上最高约 6.5 倍的加速比。

### 多 token 预测（MTP）

DeepSeek-V3 在预训练时就加入了多 token 预测目标：主干之外增加一个额外的 Transformer 模块，预测再往后一个 token。训练的目的主要是提高数据效率，但同一个模块在推理时可以直接作为投机解码的草稿。V3 技术报告称第二个 token 的接受率在 85%—90% 之间，解码速度提高约 1.8 倍。这让“草稿模型”成为目标模型训练的一部分：不存在分布失配，也没有额外的部署对象。Qwen3-Next 等新一代模型同样内置 MTP 头，vLLM 的 `mtp` 方法会直接使用它们。

## 投机解码在引擎里

第 $k$ 个草稿位置的验证需要计算，只在**批较小**时才是免费的。批大小 $B$、草稿长度 $k$，验证一步要处理 $B(k+1)$ 个 token。当 $B(k+1)$ 逼近算力拐点（H100 约 100—300 个 token，见[成本模型](/inference/inference-cost/)），每多验证一个草稿 token 就多占一份计算，被拒绝的草稿全是浪费。所以投机解码主要用于**低延迟、小批量**的场景；在吞吐优先的大批量服务中，通常关闭或把 $k$ 调小。

在 vLLM V1 中，投机 token 与普通 token 同等对待：调度器的注释写道，每个请求只有 `num_computed_tokens` 与 `num_tokens_with_spec`（提示、已生成与草稿 token 的总数），每一步让前者追赶后者，这同样覆盖 chunked prefill、前缀缓存和投机解码，没有“prefill 阶段”和“decode 阶段”之分。这是[批处理与调度](/inference/batching-scheduling/)一章里 token 预算思想的延伸：草稿 token 也要计入预算。模型运行器一侧，`vllm/v1/spec_decode/` 中有 `ngram_proposer.py`、`medusa.py`、`eagle.py` 与 `draft_model.py` 等提议器，`vllm/v1/sample/rejection_sampler.py` 实现了本章的接受-拒绝规则（以 Triton kernel 批量完成）。[vLLM 架构剖析](/inference/vllm/)一章会沿着请求的生命周期再看一遍它们的位置。

## 小结

- 投机解码用小代价提出 $k$ 个草稿，让大模型一次前向验证 $k+1$ 个位置；decode 受带宽限制，所以验证几乎不增加时间。
- 以 $\min(1,p/q)$ 接受、被拒绝时从 $\mathrm{norm}(\max(0,p-q))$ 重采样，输出分布严格等于目标分布：两种发生方式的概率之和是 $\min(p,q)+\max(0,p-q)=p$，关键是残差的分母恰好等于拒绝概率。
- 每轮期望产出 $(1-\alpha^{k+1})/(1-\alpha)$ 个 token，加速比为它除以 $kc+1$。接受率比草稿速度更重要，最佳的 $k$ 随 $\alpha$ 增大。
- 树形草稿用树形注意力掩码并行验证多个候选；每个节点只看祖先，位置取前缀长度加深度。
- 草稿来源决定 $\alpha$ 与 $c$：独立小模型、n-gram、Medusa 头、EAGLE 的特征级草稿、MTP。批大小增大后，验证开销不再免费，投机解码的收益消失。
- 下一章转向多卡与多机：[分布式推理](/inference/distributed-inference/)。

## 练习

1. 草稿分布 $q=(0.5,0.5,0)$，目标分布 $p=(0.2,0.3,0.5)$。求接受率 $\beta$ 和残差分布，并验证单位置输出分布为 $p$。
2. 在 $\alpha=0.8,c=0.1$ 时，$k=3$ 与 $k=6$ 哪个加速比更高？求使 $S$ 最大的整数 $k$。
3. 为什么草稿阶段的 $q$ 必须是**实际用于采样草稿 token 的那个分布**（包括温度、top-$k$ 之后的结果）？如果用未截断的分布会怎样？
4. 贪心解码下，目标模型与草稿模型的 argmax 完全不同，投机解码比普通解码慢多少？
5. 树形草稿中，节点 $i$ 的位置编码为什么用“前缀长度 + 深度”而不是它在树中的序号？

<details>
<summary>答案</summary>

1. $\beta=\sum\min(p,q)=\min(0.2,0.5)+\min(0.3,0.5)+0=0.5$。残差未归一化为 $(\max(0,-0.3),\max(0,-0.2),0.5)=(0,0,0.5)$，和为 $0.5=1-\beta$，归一化后 $p'=(0,0,1)$。输出为 token 0 的概率：$q_0\min(1,p_0/q_0)=0.2$；token 1：$0.3$；token 2：被拒绝的概率 $0.5$ 乘以 $p'_2=1$，等于 0.5。结果 $(0.2,0.3,0.5)=p$。

2. $S(k)=\dfrac{1-0.8^{k+1}}{0.2\,(0.1k+1)}$。$k=3$：$(1-0.4096)/(0.2\times1.3)=2.27$；$k=6$：$(1-0.2097)/(0.2\times1.6)=2.47$。继续算 $k=8$：$(1-0.1342)/(0.2\times1.8)=2.405$，$k=7$：$(1-0.1678)/(0.2\times1.7)=2.448$，$k=5$：$(1-0.2621)/(0.2\times1.5)=2.46$，所以最优 $k=6$，$S\approx2.47$。

3. 证明依赖 $\tilde x\sim q$ 且接受概率用同一个 $q$：这样第一种方式的概率才是 $\min(p,q)$。如果实际采样用了 top-$k$ 截断而公式里用未截断的分布，接受概率与采样分布不匹配，输出分布不再等于 $p$（会偏向被截断后概率被放大的 token）。

4. 每轮只被接受 0 个草稿，产出 1 个 token（目标自己的 argmax），耗时 $kc+1$ 个目标步，是普通解码一步的 $1+kc$ 倍，$c=0.05,k=4$ 时慢约 20%。这是接受率极低时的最坏情形，所以工程上要监控接受率并在过低时关闭。

5. RoPE 等位置编码描述的是 token 在**序列中的位置**。树中节点 $i$ 若被接受，它在最终序列里的位置是前缀长度加上它的深度（从根数到它的路径长度），与它的兄弟节点占据同一个位置。用树中的序号会让同一深度的不同分支得到不同位置，与它们真实被接受后的位置不一致。

</details>
