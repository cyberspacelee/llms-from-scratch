[数据并行、ZeRO 与 FSDP](/distributed/data-parallel/) 把**批**切开，ZeRO-3 进一步把参数的**存储**切开，但每一层的计算仍然在一张卡上完整地进行：FSDP 计算某一层之前，要先把这一层的完整参数 all-gather 到本地。如果单层的权重本身就很大，或者单卡上一个微批的激活已经放不下，就需要把**一层的计算本身**分给多张卡。这就是**张量并行（tensor parallelism, TP）**，也叫层内模型并行。

本章的主线来自 Megatron-LM（Shoeybi 等，2019）：一个矩阵乘可以按列切或按行切，两种切法前后配对，使得一个 MLP 或一个注意力子层只需要一次 all-reduce。我们会推导这两种切法及其反向传播中的“共轭”通信算子，实现 SwiGLU 与 GQA 注意力的张量并行版本，并与单卡逐元素比较；然后处理输出层的大词表（词表并行交叉熵），再把张量并行没有切开的那部分激活沿序列维切开（序列并行），最后讨论长序列下沿序列切分注意力本身的上下文并行与 Ring Attention。

## 矩阵乘的两种切法

为了与 Megatron 论文一致，本节把线性层写成 $Y = XA$，$X\in\mathbb R^{N\times d_\text{in}}$ 按行存放 $N$ 个 token，$A\in\mathbb R^{d_\text{in}\times d_\text{out}}$。PyTorch 的 `nn.Linear` 存的是 $W = A^\top$，形状 `[d_out, d_in]`，所以下文“对 $A$ 按列切”在代码里是“对 `weight` 按行（第 0 维）切”。设张量并行度为 $t$。

**列切分（column parallel）**：$A = [A_1, A_2, \dots, A_t]$，每个 rank 持有 $A_i\in\mathbb R^{d_\text{in}\times d_\text{out}/t}$。每个 rank 需要完整的 $X$，算出 $Y_i = XA_i$，得到输出的第 $i$ 段列。完整的 $Y = [Y_1,\dots,Y_t]$ 是**拼接**。

**行切分（row parallel）**：$A = \begin{bmatrix}A_1\\ \vdots\\ A_t\end{bmatrix}$，每个 rank 持有 $A_i\in\mathbb R^{d_\text{in}/t\times d_\text{out}}$，并且只需要输入的对应一段列 $X_i\in\mathbb R^{N\times d_\text{in}/t}$。每个 rank 算出 $X_iA_i$，它的形状已经是完整的 $N\times d_\text{out}$，但只是**部分和**：$Y = \sum_i X_iA_i$，需要一次 all-reduce。

用一个具体的例子：$x = [1,2,3,4]$，$A$ 是 $0$ 到 $15$ 按行排成的 $4\times4$ 矩阵，$y = xA = [80, 90, 100, 110]$。两卡列切分时 rank 0 用前两列得到 $[80,90]$，rank 1 得到 $[100,110]$；行切分时 rank 0 用 $x_1=[1,2]$ 与前两行得到 $[8,11,14,17]$，rank 1 用 $x_2=[3,4]$ 与后两行得到 $[72,79,86,93]$，逐元素相加才是 $y$。

两种切法的输入输出布局正好互补：列切分的**输出**是按列切开的，而行切分需要的**输入**恰好是按列切开的。所以“先列切、后行切”可以直接首尾相接，中间不需要任何通信。

## f 与 g：前向与反向的通信是共轭的

张量并行要在反向传播中保持正确，必须写出每个通信步骤的反向。设损失为 $\mathcal L$。

**列切分的输入梯度。** 每个 rank 都用完整的 $X$ 算出了 $Y_i = XA_i$，所以 $X$ 被“复制”给了 $t$ 个 rank，每个副本都对损失有贡献：

$$
\frac{\partial\mathcal L}{\partial X} = \sum_{i=1}^t \frac{\partial\mathcal L}{\partial Y_i}A_i^\top .
$$

rank $i$ 只能算出求和中的第 $i$ 项，所以**反向**需要一次 all-reduce。权重梯度 $\partial\mathcal L/\partial A_i = X^\top\,\partial\mathcal L/\partial Y_i$ 则完全在本地。

**行切分的输出。** 前向的 all-reduce $Y=\sum_i Y^{(i)}$ 对每个部分和的导数都是 1，所以反向只需把 $\partial\mathcal L/\partial Y$ 原样交给每个 rank——它本来就在每个 rank 上（因为前向之后每个 rank 都有完整的 $Y$）。

Megatron 把这两件事包装成一对算子：

<KeyEq label="共轭的通信算子">

$$
f:\ \ \text{forward} = \text{identity},\ \ \text{backward} = \text{all-reduce};
\qquad
g:\ \ \text{forward} = \text{all-reduce},\ \ \text{backward} = \text{identity}.
$$

</KeyEq>

$f$ 放在张量并行区的入口（列切分之前），$g$ 放在出口（行切分之后）。它们互为转置：$f$ 把一个张量“复制”到 $t$ 个 rank，转置就是把 $t$ 份梯度加起来；$g$ 把 $t$ 份部分和加起来，转置就是复制梯度。实现就是两个自定义 autograd 函数：

## MLP：一次 all-reduce

一个 GeLU 的 MLP 是 $Z = \mathrm{GeLU}(XA)B$。Megatron 的切法是 $A$ 列切、$B$ 行切：

$$
Z = \sum_{i=1}^t \mathrm{GeLU}(XA_i)\,B_i .
$$

关键在于非线性。$A$ 列切后，每个 rank 拿到的是 $XA$ 的**完整的一段列**，逐元素的 GeLU 可以直接在本地作用，$\mathrm{GeLU}(XA) = [\mathrm{GeLU}(XA_1),\dots]$。如果反过来先行切 $A$，每个 rank 拿到的是部分和，而 $\mathrm{GeLU}(\sum_i P_i)\ne\sum_i\mathrm{GeLU}(P_i)$，必须在非线性之前 all-reduce，就多了一次通信。

本书模型用的是 SwiGLU：$\mathrm{FFN}(X) = \big(\mathrm{SiLU}(XW_1^\top)\odot XW_3^\top\big)W_2^\top$。门控是逐元素乘法，所以 $W_1$ 与 $W_3$ **用同样的方式列切**（第 $i$ 个 rank 拿到中间维的同一段），$W_2$ 行切，整个前馈层仍然只在出口处 all-reduce 一次。中间激活 $[N, d_\text{ff}/t]$ 自始至终留在本地，这也是张量并行节省激活显存的来源。

## 注意力：按头切分

多头注意力天然可以切：各个头的计算彼此独立，只在最后的输出投影处汇合。把 $h$ 个查询头分给 $t$ 个 rank，每个 rank 负责 $h/t$ 个头：$W_Q, W_K, W_V$ 按头列切，每个 rank 在本地完成这些头的 RoPE、注意力分数、softmax 和加权求和，得到 $[N, (h/t)\,d_h]$ 的输出；输出投影 $W_O$ 按输入维（即按头）行切，产生部分和，经 $g$ all-reduce。与 MLP 一样，整个注意力子层只有一次 all-reduce。

对 GQA（见[注意力变体：MQA、GQA 与 MLA](/architecture/attention-variants/)），KV 头也要按同样的方式切：查询头 $i$ 使用 KV 头 $\lfloor i/(h/h_{kv})\rfloor$，连续地切查询头时，每个 rank 恰好需要连续的 $h_{kv}/t$ 个 KV 头。这要求 $h_{kv}$ 能被 $t$ 整除；当 $t > h_{kv}$ 时（例如 8 个 KV 头、16 路张量并行），实践中的做法是把 KV 头复制到多个 rank 上。

### 通信与计算之比

一个 Transformer 层在前向有 2 次 all-reduce（注意力与 MLP 出口的 $g$），反向有 2 次（入口的 $f$），每次的数据是 $[b, s, h]$ 的 BF16 激活，$2bsh$ 字节。前向一层的矩阵乘约 $24bsh^2$ FLOPs（注意力投影 $8bsh^2$、$4h$ 中间维的 MLP $16bsh^2$），分到 $t$ 张卡上。设每卡算力 $F$、链路带宽 $B$，前向通信与计算的时间比约为

$$
\frac{2\cdot 2\frac{t-1}{t}\cdot 2bsh / B}{24bsh^2/(tF)} \approx \frac{(t-1)\,F}{3hB}.
$$

代入 $h = 8192$、$F = 989$ TFLOP/s（H100 BF16），节点内 NVLink $B = 450$ GB/s、$t = 8$ 时比值约 $0.63$：通信时间已经接近计算时间的三分之二；换成跨节点的 $50$ GB/s，比值变成约 $5.6$，通信远比计算慢。这就是张量并行几乎总是限制在一个 NVLink 域（8 卡）之内的原因。比值与批大小、序列长度无关，只随 $h$ 增大而下降——模型越宽，张量并行越划算。

## 词表并行：嵌入与交叉熵

语言模型的首尾两层与词表大小 $V$ 成正比，现代模型的词表在 10 万到 25 万之间，这两层不能留在单卡上。

**输入嵌入**按词表（行）切：rank $i$ 持有 token id 在 $[iV/t, (i+1)V/t)$ 之间的嵌入行。每个 rank 只为落在自己区间的 token 查表，其余位置填 0，再 all-reduce——每个位置恰好有一个 rank 给出了非零值。

**输出层**是列切分：rank $i$ 得到 logits 的第 $i$ 段 $[N, V/t]$。如果把 logits all-gather 成完整的 $[N, V]$ 再算交叉熵，代价很大：8192 个 token × 128K 词表 × 4 字节就是 4 GB。注意交叉熵

$$
\ell = \log\sum_{v} e^{z_v} - z_{y} = \log\sum_v e^{z_v - m} - (z_y - m),\qquad m = \max_v z_v
$$

只需要每个 token 的三个标量：全局最大值 $m$、指数和 $\sum_v e^{z_v-m}$、目标 logit $z_y$。它们都可以分段计算后归约：$m$ 是各段最大值的 all-reduce(MAX)；指数和是各段指数和的 all-reduce(SUM)；目标 logit 只落在一个 rank 的分片里，其他 rank 贡献 0，再 all-reduce(SUM)。每个 token 只通信 3 个数，而不是 $V$ 个。

反向同样只需本地信息：$\partial\ell/\partial z_v = \mathrm{softmax}(z)_v - \mathbb 1[v = y]$，每个 rank 用已经归约好的 $m$ 与指数和就能算出自己那一段的 softmax，再在目标 token 所在的 rank 上减 1。

## 序列并行：切开剩下的激活

张量并行切开了注意力和 MLP 内部的激活，但每个子层的**入口与出口**仍然是完整的 $[b, s, h]$：RMSNorm 的输入与输出、残差、dropout 的掩码在 $t$ 个 rank 上被重复保存。Korthikanti 等（2022）统计了 GPT 式层为反向保存的激活（16 位激活、1 字节 dropout 掩码）：

$$
\text{no parallelism: } sbh\Big(34 + \frac{5as}{h}\Big),\qquad
\text{tensor parallel: } sbh\Big(10 + \frac{24}{t} + \frac{5as}{ht}\Big),
$$

其中 $a$ 是头数。张量并行只切开了 34 中的 24，剩下 $10sbh$（两个 LayerNorm 的输入 $4sbh$、两个 dropout 掩码 $2sbh$、注意力与 MLP 入口的输入 $4sbh$）在每个 rank 上原样保存。

这些操作都是**逐 token** 的：LayerNorm/RMSNorm、dropout、残差相加对序列中的每个位置独立计算。所以可以在这些区域沿**序列维**切分：每个 rank 只持有 $[b, s/t, h]$。进入张量并行区时需要完整序列，用 all-gather 把序列拼起来；离开时，行切分产生的部分和不再 all-reduce，而是 **reduce-scatter**：既完成求和，又顺便把结果沿序列切开。

这里有一个容易漏掉的细节：RMSNorm 的权重 $\gamma$ 在每个 rank 上是**复制**的，但每个 rank 只用它处理了 $s/t$ 个位置，所以本地算出的 $\partial\mathcal L/\partial\gamma$ 只是部分和，必须在张量并行组内 all-reduce（Megatron 中这类参数被标记为 `sequence_parallel`，在梯度同步时额外处理）。测试 `SequenceParallelFFN` 时，输出与输入梯度沿序列切开后与单卡一致，归一化权重的梯度在 all-reduce 之后与单卡一致。

### 选择性重计算

序列并行之后，激活里剩下的大头是 $\frac{5as}{ht}$ 项：注意力分数矩阵 $QK^\top$ 的 softmax 输出与 dropout 掩码，它们的大小随 $s^2$ 增长。以 GPT-3 175B 为例（$a=96$、$s=2048$、$h=12288$），$5as/h = 80$，比其余的 34 还大。Korthikanti 等的**选择性重计算**只在反向时重算这一部分：它的 FLOPs 很少（只是逐元素的 softmax 与 dropout），激活却最多。此时每层激活降到 $34\,sbh/t$。今天的 FlashAttention 本身就不保存 $s\times s$ 的矩阵（见[FlashAttention：IO 感知的注意力](/gpu/flash-attention/)），等价于自带了选择性重计算。激活与重计算的完整核算放在[组合并行：显存规划与训练配置](/distributed/parallelism-in-practice/)。

## 上下文并行与 Ring Attention

序列并行只切开了逐 token 的操作，注意力本身仍要在每个 rank 上处理完整序列。当序列长到 128K 甚至 1M 时，即使有 FlashAttention，单卡的注意力计算量（$\propto s^2$）和 KV 也成了瓶颈。**上下文并行（context parallelism, CP）**把整个层——包括注意力——沿序列切开：rank $i$ 只持有第 $i$ 段 token 的 $Q_i, K_i, V_i$。线性层、归一化本来就逐 token，无需通信；唯一的问题是注意力：$Q_i$ 需要和所有 $K_j, V_j$（因果时是 $j\le i$）交互。

**Ring Attention**（Liu 等，2023）把 rank 排成环，让 K/V 块沿环流动。第 $s$ 步，rank $i$ 手里有第 $j = (i - s)\bmod t$ 段的 $K_j, V_j$，计算 $Q_i$ 对这一块的注意力，同时把这块 K/V 发给右邻居、从左邻居接收下一块。$t$ 步之后，$Q_i$ 见过了所有的 K/V。

问题是怎样把各块的结果合并起来。每块得到的是只在这一块内部归一化的 softmax，而正确的结果要在所有块上一起归一化。这正是 FlashAttention 的**在线 softmax**：对每个查询行，维护到目前为止的输出 $o$ 与 log-sum-exp $\ell = \log\sum_j e^{s_j}$；新来一块，块内的结果是 $(o_b, \ell_b)$，合并为

$$
\ell' = \log\big(e^{\ell} + e^{\ell_b}\big),\qquad
o' = e^{\ell - \ell'}\,o + e^{\ell_b - \ell'}\,o_b .
$$

两个系数恰好把旧的归一化分母换成新的。因为合并是满足结合律的，块的到达顺序无关紧要——这也是它能在环上工作的原因。

我们的实现只做前向（Ring Attention 的反向需要再沿环传递 K/V 与它们的梯度，结构相同），测试在 2 个和 4 个 rank 上把各 rank 的输出拼起来，与完整序列上的 `scaled_dot_product_attention(is_causal=True)` 比较。真实实现中，“发送下一块 K/V”与“计算当前块”同时进行；只要一块的计算时间长于传输时间（序列足够长时总是成立），通信就完全被掩盖。

图中暴露了因果注意力下的**负载不均**：按顺序切分时，持有序列末尾的 rank 要和所有块交互，持有开头的 rank 几乎无事可做。常见的修正是 zigzag 切分：把序列切成 $2t$ 段，rank $i$ 持有第 $i$ 段和第 $2t-1-i$ 段，每个 rank 的计算量相等。Llama 3 的长上下文训练使用上下文并行，但它没有采用环形传递，而是先 all-gather 所有 K/V 再计算本地查询的注意力：在 GQA 下 K/V 比 Q 小得多，all-gather 的通信量可以接受，实现也更灵活（Llama 3 技术报告 3.3.2 节）。

## 小结

- 线性层可以按输出列切（输入完整、输出拼接）或按输入行切（输入切分、输出部分和需 all-reduce）；先列后行，中间无需通信。
- 共轭算子 $f$（前向恒等、反向 all-reduce）与 $g$（前向 all-reduce、反向恒等）把通信放在张量并行区的出入口；MLP 与注意力各只需一次前向 all-reduce，一层共 4 次（前向 2、反向 2）。
- 注意力按头切分；GQA 要求 KV 头数能被 $t$ 整除或复制 KV 头。通信与计算之比约 $(t-1)F/(3hB)$，决定了张量并行限于 NVLink 域内。
- 词表并行交叉熵每个 token 只交换最大值、指数和、目标 logit 三个标量。
- 序列并行把 all-reduce 拆成 reduce-scatter 与 all-gather，通信量不变，激活显存从 $sbh(10+24/t+\cdot)$ 降到全部除以 $t$；复制的归一化参数的梯度需要额外 all-reduce。
- 上下文并行沿序列切开整个层，Ring Attention 让 K/V 沿环流动，用在线 softmax 合并各块；因果掩码下需要 zigzag 切分来平衡负载。

## 练习

1. 如果把 MLP 的第一个矩阵行切、第二个矩阵列切，前向需要几次通信？分别是什么原语？

<details>
<summary>答案</summary>

行切第一个矩阵，每个 rank 得到 $XA$ 的部分和，而 GeLU 是非线性的，必须先 all-reduce 得到完整的 $XA$ 才能做 GeLU（第 1 次）。此时每个 rank 都有完整的 $\mathrm{GeLU}(XA)$，第二个矩阵列切，得到输出的一段列；下一个子层（残差相加、归一化）需要完整的输出，所以还要 all-gather（第 2 次）。两次通信，而且第一次 all-reduce 的数据是 $[N, 4h]$，是 Megatron 方案的 4 倍。

</details>

2. 证明词表并行交叉熵的梯度：设 rank $i$ 持有 logits 的第 $i$ 段 $z^{(i)}$，写出 $\partial\ell/\partial z^{(i)}_v$，并说明 rank $i$ 计算它需要哪些已归约的量。

<details>
<summary>答案</summary>

$\ell = \log\sum_{u}e^{z_u} - z_y$，对任意 $v$ 有 $\partial\ell/\partial z_v = e^{z_v}/\sum_u e^{z_u} - \mathbb 1[v=y]$。对 rank $i$ 持有的 $v$，$e^{z_v}/\sum_u e^{z_u} = e^{z_v - m}/S$，其中 $m$ 是全局最大值、$S=\sum_u e^{z_u-m}$ 是全局指数和——这两个量在前向已经 all-reduce 过，保存下来即可。减 1 只在 $y$ 落在本 rank 区间时发生。所以反向不需要任何额外通信。

</details>

3. 一个 $h=4096$ 的模型用 $t=8$ 的张量并行，按本章的通信计算比公式，在 NVLink（450 GB/s）上比值是多少？如果 $t=4$ 呢？这对选择张量并行度有什么启示？

<details>
<summary>答案</summary>

$t=8$：$(7\times989\times10^{12})/(3\times4096\times4.5\times10^{11}) \approx 1.25$，通信比计算还慢。$t=4$：$3/7$ 倍，约 $0.54$。较窄的模型应使用较小的张量并行度，把剩下的卡交给数据并行或流水线并行；只有在单卡放不下（或者需要切开激活）时才值得用更大的 $t$。实际系统还会把张量并行的通信与相邻的矩阵乘重叠（例如把 all-gather 与 GEMM 分块流水），可以部分缓解。

</details>

4. 在序列并行中，为什么 RMSNorm 的权重梯度需要 all-reduce，而 `TPSwiGLU` 中 $W_1$ 分片的梯度不需要？

<details>
<summary>答案</summary>

$W_1$ 的第 $i$ 片只存在于 rank $i$，前向时它作用于**完整序列**（all-gather 之后），所以 rank $i$ 本地算出的梯度已经包含了所有 token 的贡献，是完整的。RMSNorm 的 $\gamma$ 在每个 rank 上都有一份，但每份只作用于 $s/t$ 个 token，本地梯度只包含这些 token 的贡献，真正的梯度是 $t$ 份之和。规律是：被复制的参数如果只看到了部分数据，就要像数据并行那样同步梯度。

</details>

5. 修改 `ring_attention` 支持 zigzag 切分：序列切成 $2t$ 段，rank $i$ 持有第 $i$ 段与第 $2t-1-i$ 段。在 $t=4$ 时，每个 rank 需要计算多少个“半块”（段对段）的注意力？与顺序切分时最忙的 rank 比较。

<details>
<summary>答案</summary>

把序列看成 8 段，因果注意力中段 $a$ 对段 $b$ 可见当且仅当 $b\le a$。rank $i$ 的查询段是 $i$ 和 $7-i$：段 $i$ 可见 $i+1$ 个段，段 $7-i$ 可见 $8-i$ 个段，合计 $9$ 个段对，与 $i$ 无关，所以负载完全均衡（其中 2 个是对角块，需要块内掩码）。顺序切分时 rank 3 持有段 6、7，要算 $7 + 8 = 15$ 个段对，rank 0 只有 $1+2=3$ 个；总量 $36$ 在 zigzag 下被均分为每个 rank 9 个。

</details>
