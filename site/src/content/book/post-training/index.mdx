前五部分训练出来的是一个基座模型（base model）：它在海量文本上学会了预测下一个 token，掌握了大量知识，却只会“续写”。给它一个问题，它可能接着写出更多的问题；给它一道数学题，它可能写出半个解答然后转去讨论别的事情。从基座模型到 ChatGPT、DeepSeek-R1 这样的助手，中间隔着的就是后训练（post-training）。

后训练的计算量通常只有预训练的一小部分，却决定了模型“怎样被使用”：用什么格式对话、何时停止、拒绝什么请求、如何一步步推理、回答是否符合人的偏好。InstructGPT 中 13 亿参数的模型在人类评测中胜过 1750 亿参数的 GPT-3，DeepSeek-R1-Zero 只靠规则奖励的强化学习就把 AIME 的正确率从 15.6% 提高到 77.9%，都说明了这一点。

**示范。** [监督微调与对话模板](/post-training/sft/)用“提示—理想回复”的示范做最大似然，教会模型对话格式与行为模式。它简单有效，但只能模仿，上限是示范的质量。[LoRA 与参数高效微调](/post-training/lora/)回答一个实际的问题：怎样用一张显卡微调一个大模型。低秩更新与 4-bit 量化把可训练状态压到全参数微调的百分之一。

**比较。** 判断两个回答哪个更好比写出理想回答容易得多。[RLHF：奖励模型与 PPO](/post-training/rlhf/)从人类比较中学一个奖励模型，再用策略梯度与 PPO 让模型在自己的采样上最大化奖励；这一章完整推导了策略梯度定理、PPO 的裁剪与 GAE，它们是后面所有 RL 方法的基础。[直接偏好优化 DPO](/post-training/dpo/)发现 KL 正则目标有闭式解，于是可以跳过奖励模型与采样，直接在偏好数据上做监督式训练。

**规则。** 对数学与代码，答案可以被程序检查。[GRPO 与推理模型](/post-training/grpo/)用组内相对优势代替价值网络，在可验证奖励上做强化学习，并梳理 DeepSeek-R1-Zero 与 R1 的训练流程；我们会在小 GPT 上从随机初始化出发，只靠 0/1 奖励学会个位数加法。[大规模强化学习的工程与改进](/post-training/rl-at-scale/)讨论把它放大到长思维链时出现的问题：长度与难度偏置、熵坍缩、训练与推理的数值不一致，以及异步 rollout 的系统设计。

**教师。** [知识蒸馏](/post-training/distillation/)让小模型向大模型学习：从软标签与温度，到前向与反向 KL 的区别，再到让学生自己采样、教师逐 token 打分的在线策略蒸馏。它把 SFT 的稠密信号与 RL 的在线采样结合在一起。

## 与前后部分的关系

这一部分直接建立在[从零实现 Transformer](/transformer/)的 GPT 之上：所有实现都 import 全书共用的 `transformer/model.py`，不复制模型代码。需要自定义注意力掩码与位置（样本打包、奖励模型读出隐藏状态）时，我们复用模型的各个子模块重新组织前向，而不修改模型本身。[概率、最大似然与交叉熵](/math/probability/)中的 KL 散度与最大似然是本部分最常用的数学工具；[特征分解、SVD 与低秩近似](/math/linear-algebra-advanced/)是 LoRA 的背景；[混合精度训练：从 FP16 到 FP8](/pretraining/mixed-precision/)中的显存核算会在 LoRA 一章中再次用到。

强化学习部分会频繁涉及生成。生成的成本、KV Cache、连续批处理与 vLLM 的架构在[推理系统](/inference/)中详细讨论；大规模 RL 系统的瓶颈恰恰在于生成，读完第九部分再回头看 RL 系统的设计会更清楚。NF4 只是众多量化方法之一，更系统的讨论在[量化：权重、激活与 KV Cache](/inference/quantization/)。

## 阅读与动手建议

如果时间有限，最核心的三章是 SFT、RLHF 与 GRPO：它们分别建立了“掩码交叉熵”“策略梯度与 PPO”“组内优势与可验证奖励”三个基本概念，DPO、大规模 RL 与蒸馏都是在它们之上的变形。RLHF 一章的数学最多，建议对照测试代码阅读：策略梯度的方差、PPO 的裁剪、GAE 的递推都有逐项可核对的手算例子。

所有代码都在 `src/llms_from_scratch/post_training/` 下，测试在 `tests/post_training/` 下，全部在 CPU 上几秒内运行完：

```sh
uv run pytest tests/post_training
uv run python -m llms_from_scratch.post_training.grpo   # 在个位数加法上从零跑 GRPO，约一分钟
```

实验都使用约两万参数的极小 GPT 与可自动判定的玩具任务（个位数加法、字符串反转），目的是验证机制的正确性，而不是复现论文的数字。每一章都标注了真实系统中的规模与设置，以及它们的出处。读完之后，一个很好的练习是把 GRPO 的训练循环换成 Dr. GRPO 或 DAPO 的损失聚合方式，观察玩具任务上回复长度与奖励曲线的变化。
