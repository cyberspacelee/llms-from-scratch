前两章已经具备了反向传播需要的全部数学：链式法则告诉我们沿计算图把局部导数相乘、在汇合处相加；VJP 告诉我们每个算子怎样把输出梯度变成输入梯度。但到目前为止，每个网络的反向传递都是手写的——[链式法则](/math/chain-rule/)里两层网络的 `tiny_network` 把前向和反向一行行写死。换一个网络结构，就要重写一遍。

**自动微分**（automatic differentiation，autodiff）把这件事交给程序：用户只写前向计算，程序在计算的同时记录计算图，然后自动按正确的顺序调用每个算子的局部 VJP。这不是符号微分（不推导公式），也不是数值差分（没有截断误差），而是对链式法则的精确、机械的执行。PyTorch 的 `loss.backward()` 做的就是这件事。

本章分两步实现它。第一步是一个只处理标量的引擎（思路来自 Andrej Karpathy 的 micrograd），不到一百行，却包含了反向模式自动微分的全部核心：节点、局部反向闭包、拓扑排序、梯度累加。我们用它训练一个小 MLP。第二步把节点从标量换成 NumPy 数组，处理矩阵乘、广播和交叉熵，并与 PyTorch 逐个参数比对梯度。

## 设计：每个节点记住什么

回忆[链式法则与计算图](/math/chain-rule/)中反向传递的规则：从损失出发，按与前向相反的顺序，每个节点把“损失对自己的梯度”乘以局部导数，**累加**到它的每个输入上。要执行这个规则，每个节点需要保存四样东西：

1. **值** `data`：前向计算的结果，局部导数要在这个点上求值。
2. **梯度** `grad`：最终损失对本节点的偏导数，初始为 0，反向时累加。
3. **父节点** `_parents`：本节点由哪些节点计算而来，即计算图的边。
4. **局部反向函数** `_backward`：一个闭包，知道怎样把 `self.grad` 乘以局部导数并加到父节点的 `grad` 上。

## 标量引擎：运算与局部反向

每个运算都遵循同一个模式：算出结果，创建新节点并记下父节点，再定义一个闭包描述局部 VJP。加法的两个局部导数都是 1，乘法的局部导数是“另一个因子”：

<CodeFile path="src/llms_from_scratch/math/micrograd.py" symbol={['Value.__add__', 'Value.__mul__']} />

闭包里用的是 `+=` 而不是 `=`。原因是[多元链式法则的“路径相加”](/math/chain-rule/)：一个节点可能被多个下游节点使用，每个下游都会调用一次自己的 `_backward` 并贡献一份梯度，这些份额必须加起来。一个极端情形是 `a + a`：`self` 和 `other` 是同一个对象，两行 `+=` 一共给 `a.grad` 加了 2 次 `out.grad`，恰好是 $\frac{\mathrm d(2a)}{\mathrm da} = 2$；如果写成 `=`，第二行会覆盖第一行，得到错误的 1。

非线性函数的局部导数正好可以用前向结果表示，这让闭包可以直接复用前向值：

<CodeFile path="src/llms_from_scratch/math/micrograd.py" symbol={['Value.exp', 'Value.tanh']} />

减法、除法、取负都由已有的运算组合而成（例如 $a/b = a\cdot b^{-1}$），不需要单独写反向：只要组合中的每个原语都有正确的局部 VJP，复合运算的梯度就自动正确。这是自动微分最实用的性质——**原语少，组合多**。

## 拓扑排序与反向传递

有了局部反向，还需要决定**调用顺序**。一个节点的 `_backward` 只能在它的 `grad` 已经完整（所有下游的贡献都已累加）之后调用，否则传给父节点的是不完整的梯度。满足这个条件的顺序是计算图的**逆拓扑序**：如果 $u$ 是 $v$ 的父节点（$u$ 参与计算 $v$），那么 $v$ 必须先于 $u$ 处理。

拓扑序用深度优先搜索的后序遍历得到：先递归访问一个节点的所有父节点，再把它自己加入列表。这样每个节点都排在它的所有父节点之后。反向传递就是把这个列表倒过来逐个调用：

标量引擎的问题是效率。上面这个只有 41 个参数的网络，对一个样本做一次前向就要创建 116 个 `Value` 节点，每个都是 Python 对象，每次运算都要经过 Python 解释器。一个 $4096\times4096$ 的线性层有 1678 万个乘加，对应上千万个节点，完全不可行。解决办法是**把节点的粒度从标量提升到张量**：一个矩阵乘只是图中的一个节点，它的局部 VJP 是[上一章](/math/backprop/)推导的两次矩阵乘，由 NumPy 或 GPU 内核高效完成。

## 广播的反向：sum_to_shape

张量版本新增的一个难点是广播。线性层的 $XW + b$ 中，$b$ 的形状是 $(d,)$，$XW$ 是 $(N, d)$，加法时 $b$ 被广播到每一行。反向时 `out.grad` 的形状是 $(N, d)$，而 $b$ 的梯度必须是 $(d,)$。怎么从前者得到后者？

把广播看成一个线性映射 $\mathcal B$：它把 $b\in\mathbb R^d$ 复制成 $N$ 行，$\mathcal B(b)_{nk} = b_k$。$\mathcal B$ 是线性的，它的雅可比就是它自己，VJP 是它的**伴随**（转置）$\mathcal B^\top$。伴随由内积关系唯一确定：对任意 $b$ 和任意 $G\in\mathbb R^{N\times d}$，

$$
\langle\mathcal B(b), G\rangle = \sum_{n,k}b_kG_{nk} = \sum_k b_k\Bigl(\sum_n G_{nk}\Bigr) = \langle b, \mathcal B^\top(G)\rangle,
$$

所以 $\mathcal B^\top(G)_k = \sum_nG_{nk}$：**广播的伴随是沿被复制的维度求和**。一般地，广播可能在前面补维度（补出来的维度整个求和掉），也可能把大小为 1 的维度拉伸（沿该维求和并保留大小 1）。

## log_softmax 与交叉熵

最后实现语言模型的损失。为了数值稳定，不单独实现 softmax 和 log，而是实现 $y = \operatorname{log\_softmax}(z) = z - \operatorname{logsumexp}(z)\mathbf 1$。它的雅可比：$\partial y_i/\partial z_j = \delta_{ij} - p_j$，其中 $p = \operatorname{softmax}(z)$（因为 $\operatorname{logsumexp}$ 的梯度是 $p$）。写成矩阵 $J = I - \mathbf 1p^\top$，VJP 为

$$
\bar z = J^\top\bar y = \bar y - p\,(\mathbf 1^\top\bar y) = \bar y - p\sum_i\bar y_i .
$$

交叉熵再由两个简单原语组合：`pick` 从每行取出正确类别的对数概率（反向时把梯度放回原位置，其余位置为 0），`mean` 求批平均，最后乘以 $-1$。组合后的梯度恰好是 $(p - e_y)/N$：`pick` 和 `mean` 送回的 $\bar y$ 在每行只有正确位置为 $-1/N$，代入上式得 $\bar z = -e_y/N + p/N$。

## 小结

- 反向模式自动微分 = 前向时记录计算图 + 反向时按逆拓扑序调用每个节点的局部 VJP。
- 每个节点保存值、梯度、父节点和局部反向闭包。梯度用 `+=` 累加，以正确处理一个节点被多处使用（路径相加）；因此每步训练前要清零。
- 拓扑序由 DFS 后序得到，保证一个节点处理时它的梯度已经完整。
- 标量引擎每个运算一个 Python 对象，太慢；张量引擎把一个矩阵运算作为一个节点，VJP 由数组运算完成。
- 广播的反向是沿被复制的维度求和（`sum_to_shape`），这是广播映射的伴随。
- log_softmax 的 VJP 为 $\bar y - p\sum\bar y$；与 `pick`、`mean` 组合后自动得到交叉熵梯度 $(p - e_y)/N$。

## 练习

1. 给 `Value` 增加 `sigmoid` 方法，要求只用一个节点，并写出它的 `_backward`。

<details>
<summary>答案</summary>

```python
def sigmoid(self) -> Value:
    s = 1 / (1 + math.exp(-self.data))
    out = Value(s, (self,), "sigmoid")

    def _backward() -> None:
        self.grad += s * (1 - s) * out.grad

    out._backward = _backward
    return out
```

局部导数 $\sigma(1-\sigma)$ 用前向值 `s` 表达，不需要重算指数。也可以用已有原语组合 `1 / (1 + (-self).exp())`，结果相同但会创建 4 个节点。

</details>

2. 如果在 `Value.backward` 中忘了反转拓扑序，直接按 `order` 顺序调用 `_backward`，对 $L = (ab + a)^2$ 会得到什么？

<details>
<summary>答案</summary>

顺序变成 $a, b, c, d, L$。处理 $a$、$b$ 时它们没有父节点；处理 $c$ 时 `c.grad` 还是 0，传给 $a, b$ 的都是 0；处理 $d$ 时 `d.grad` 也是 0；最后处理 $L$ 才把 $-8$ 送给 $d$，但 $d$ 已经处理过了。结果除了 `d.grad = -8` 外，所有叶子的梯度都是 0。

</details>

3. 两个形状为 `(2, 1, 3)` 与 `(4, 1)` 的张量相加，输出形状是什么？对两个输入，`sum_to_shape` 分别在哪些轴上求和？

<details>
<summary>答案</summary>

输出为 `(2, 4, 3)`。第一个输入：第 1 轴（大小 1 被拉伸到 4）求和并保留，得 `(2, 1, 3)`。第二个输入：先把补出来的第 0 轴整体求和，得 `(4, 3)`；再对大小为 1、被拉伸到 3 的最后一轴求和并保留，得 `(4, 1)`。

</details>

4. 张量引擎中 `mean` 的 VJP 为什么是 `broadcast_to(g / n, shape)`？把它写成伴随的形式。

<details>
<summary>答案</summary>

$\operatorname{mean}(X) = \frac1n\sum_iX_i$ 是线性映射 $X\mapsto\frac1n\mathbf 1^\top\operatorname{vec}(X)$，其伴随把标量 $g$ 映为 $\frac gn\mathbf 1$，即与 $X$ 同形状、每个元素都是 $g/n$ 的数组。“求和”与“广播”互为伴随，“求平均”的伴随是“广播再除以 $n$”。

</details>

5. 估算：用标量引擎做一次 $(64, 512)\times(512, 512)$ 的矩阵乘（含加法），大约创建多少个 `Value` 节点？如果每个节点在 Python 中需要 1 微秒，前向需要多久？

<details>
<summary>答案</summary>

输出有 $64\times512 = 32768$ 个元素，每个需要 512 次乘法和约 512 次加法，共约 $3.4\times10^7$ 个节点，前向约 34 秒，反向更慢，内存也会达到数 GB。同样的计算由 NumPy 的一次 `@` 完成只需约 1 毫秒。

</details>
