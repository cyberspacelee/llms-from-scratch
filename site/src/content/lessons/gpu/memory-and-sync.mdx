用 [G1](/gpu/execution-model/) 的 thread、warp 和 block，可以给矩阵的每个元素安排负责人。转置要把 $A_{r,c}$ 写到 $B_{c,r}$。按输入行排列线程时，读取连续、写入分散；按输出行排列时则相反。

本章要让一个 warp 读取 A、写入 B 时都访问相邻的全局内存地址。先列出一条 warp 指令的地址，再用 block 内的 shared memory 交换数据，最后证明交换后的值何时可读。先修是行主序下标 $rC+c$。

全章固定 float32（每元素 4 字节）、输入 $A\in\mathbb R^{35\times67}$、输出 $B\in\mathbb R^{67\times35}$，满足 $B_{c,r}=A_{r,c}$。一个 block 处理 $32\times32$ 的数据 tile，使用 `dim3(32, 8)` 的 256 个 thread；`threadIdx.x` 从 0 到 31，刚好让同一 warp 沿一行排列。起初只看左上完整 tile，最后处理右下只有 $3\times3$ 个有效元素的 tile。下面的地址段与 bank 数量是 NVIDIA CUDA 的教学模型，不是计时结果。

## 全局内存：同样 32 个数，地址如何排列

CUDA 的 global memory 保存跨 block 可访问的输入和输出；寄存器中的局部值属于各自 thread。一个 warp 的合并访问讨论的是**某一次 load 或 store 指令中活跃 lane 的地址集合**。即使一个 thread 在循环中依次读了许多相邻元素，也不能据此判断同一条 warp 指令是否合并。

在计算能力 6.0 及以上、4 字节标量访问、对齐基址的条件下，先用 32-byte 地址段分析请求。一个段可放 8 个 float32。若 lane $\ell$ 访问从对齐基址起第 $o+s\ell$ 个元素，则它的字节地址与段号为

<KeyEq label="从 lane 到地址段">
$$
a_\ell=4(o+s\ell),\qquad
q_\ell=\left\lfloor\frac{a_\ell}{32}\right\rfloor,\qquad
N_{\mathrm{sector}}=\left|\{q_\ell:\ell\text{ 活跃}\}\right|.
$$
</KeyEq>

例如左上 tile 的第 0 行，32 个 lane 读 $A_{0,0},\ldots,A_{0,31}$，元素偏移是 0–31，落在段 0–3：请求 128 字节，段覆盖也是 128 字节。若整体向右移动一个元素，偏移 1–32，尾元素进入段 4，覆盖变成 5 段。若 32 个 lane 读取第 0 列的连续 32 行，元素偏移是 $0,67,134,\ldots$；因为相邻地址差 268 字节，每个 lane 落在不同段。相同的 32 个 float32 请求仍为 128 字节，地址段覆盖却扩大到 1024 字节。

<CoalescingLab client:visible />

实验把一条指令的元素偏移写成 $o+s\ell$。先用 $s=1,o=0$ 核对 4 段，再将 $o$ 改为 1 看第 5 段来自 lane 31；$s=8$ 时，每个 lane 占一个段。真实矩阵列步长是 67，超出实验滑块，但地址公式相同。只有活跃 lane 才计入集合；边缘 tile 的 3 个活跃 lane 不能按 32 个 lane 计数。

段覆盖不能直接当作显存实际流量：缓存可能复用段，存储路径和架构也会影响事务。它说明转置的瓶颈候选在哪里，速度须按 [G4](/gpu/measurement/) 的方法测量。

## 转置的障碍：输入行和输出行不是同一组 thread

行主序输入的元素偏移是 $r\cdot67+c$，行主序输出的元素偏移是 $c\cdot35+r$。若 lane $\ell$ 处理 $A_{r,\ell}$ 并立即写 $B_{\ell,r}$，输入 load 沿行连续，输出 store 的相邻地址却相差 35 个元素。将 lane 改为沿 $r$ 变化，会把分散访问移到输入端。

解决方法是让 block 内的 thread **换负责人**：第一组按输入行连续读取，把数据写进 `tile[r][c]`；屏障后，第二组从 shared tile 的列取值，沿输出行连续写回。数学映射 $A_{r,c}\mapsto B_{c,r}$ 没变，改变的是哪个 thread 执行最后一步。shared memory 是同一 block 内可访问、随 block 生命周期存在的程序员管理存储，适合这次交换；不同 block 不能通过它直接通信。

以 tile 内 $(r,c)=(2,5)$ 为例。装载者 `(tx,ty)=(5,2)` 把 $A_{2,5}$ 写到 `tile[2][5]`。写回者 `(tx,ty)=(2,5)` 从该槽读出，写 $B_{5,2}$。实际 block 只有 8 行 thread，代码让每个 thread 以 `j=0,8,16,24` 处理四行；因此 $(18,27)$ 的装载者是 `(27,2)`、`j=16`，写回者是 `(18,3)`、`j=24`。完整 tile 中，每条 load 和 store 指令的 warp 仍沿各自矩阵的一行走。

## Shared bank：交换后的一列为什么会排队

shared memory 分为 bank。在本章的 32 个 bank、32-bit 标量访问模型里，以 32-bit 字为单位的地址 $w$ 对应

$$
\operatorname{bank}(w)=w\bmod32.
$$

若 shared 数组声明为 `float tile[32][32]`，写回时同一 warp 的 lane $\ell$ 读取固定列 $c$、不同行的 `tile[ell][c]`。元素地址 $w_\ell=32\ell+c$ 全落在 bank $c$，却是 32 个不同地址：这是 32 路 bank 冲突模型。同一个 bank 收到多个**不同地址**会拆开服务；若所有 lane 都读同一个地址，例如 `tile[0][7]`，它是广播。

将数组声明为 `float tile[32][33]` 后，数学数据仍只有 32 列。额外一列只改变行跨度：$w_\ell=33\ell+c$，bank 号是 $(\ell+c)\bmod32$，32 个 lane 刚好分布在 32 个 bank。共享空间从 $32\cdot32\cdot4=4096$ 字节增至 $32\cdot33\cdot4=4224$ 字节，多用 128 字节。装载阶段按行访问 shared，填充不会改变输入或输出的值。

依次选择 32 列、33 列和同址广播，读每个 bank 的**不同读取地址数**。图中的最大数用于比较这类标量读取的冲突路数，不可直接换算为 kernel 周期数。若元素宽度、指令访问宽度或 bank 配置改变，需要重新分析；多线程向同一地址写不同值也不是广播，而是正确性问题。

## 屏障：何时可以交换负责人

shared 槽的写入者和读取者可能位于不同 warp。源码中先写 `tile`、后读 `tile`，只是每个 thread 自己的程序顺序，不能证明别的 thread 已经装载完成。`__syncthreads()` 在 block 范围等待参与 thread 到达，并按 CUDA 语义让屏障前的访问对屏障后的 block 内访问可见。转置只需在装载与读取之间放一道：

```cpp
for (int j = 0; j < 32; j += 8)
    tile[ty + j][tx] = valid_input ? input[input_index] : 0.0f;
__syncthreads();
for (int j = 0; j < 32; j += 8)
    if (valid_output) output[output_index] = tile[tx][ty + j];
```

这里的 `valid_input` 和 `valid_output` 分别按对应的二维矩阵行列判断；完整索引见下方 CUDA 文件。所有 256 个 thread 都到达同一道屏障，越界位置也先写 0。不要把屏障放进仅部分 thread 满足的边界分支。一次性转置在读完后就结束，不再覆盖同一个 shared tile，因此无需第二道回收屏障。

<Figure src="gpu/memory-sync.svg" alt="共享缓冲区先装载，再经过发布屏障供消费者读取；复用缓冲区时读完后还需回收屏障" minWidth="40rem">转置只走装载、发布、消费三个阶段。若循环复用同一缓冲区，沿回收箭头进入下一轮前还要等所有消费者读完。</Figure>

这道屏障只覆盖一个 block。它不等待 grid 中其他 block，也不是 host 读取设备结果的完成信号。`__syncwarp()` 只覆盖指定 warp 的参与 lane，不能替代此处可能跨 warp 的交换；原子操作保证某地址更新的原子性，也不等于整个 block 到齐。

### 回放：缺少一道屏障会读到什么

为隔离同步问题，下面用一个 shared 槽和两个消费者，初始旧值为 0，本轮应读 7，下一轮将写 9。转置只需要发布屏障；回收场景是循环复用缓冲区的扩展，对应下一章的分块矩阵乘。

<BarrierReplayLab client:visible />

正常场景里，两个消费者都读到 7，随后才覆盖为 9。缺少发布屏障时，消费者 B 可能先读到旧值 0；缺少回收屏障时，它可能在下一轮覆盖后读到 9。实验列出各一个可能的交错，足以构成反例；它没有声称所有运行都会出现同一个错误。

## 边缘 tile：没有数据的 thread 仍要协作

$35\times67$ 的输入需要 $\lceil67/32\rceil\times\lceil35/32\rceil=3\times2$ 个 tile。最右下 block 从输入 $(32,64)$ 开始，只有 3 行、3 列有效。以其中 $(r,c)=(2,2)$ 为例，它代表全局 $A_{34,66}$；转置输出是 $B_{66,34}$。两边的行主序偏移分别是 $34\cdot67+66=2344$ 和 $66\cdot35+34=2344$，碰巧相同；这一个元素的地址相同不代表整次转置可以原地执行。

越界 thread 不读取无效 global 地址。它向自己的 shared 槽写 0，然后参加屏障；写回时只对有效输出坐标执行 store。不能按“我没有有效输出”直接 `return`：该 thread 仍可能装载别人的有效输入，且 block 的屏障参与必须一致。

回到转置实验，选择“右下：3×3 有效”，将 tile 内行、列都设为 2，核对 $A_{34,66}$ 到 $B_{66,34}$ 的路径。再把列改为 3，观察该位置装载零并跳过输出。边缘只有 3 个活跃 shared 列读 lane；比较 32 列与 33 列布局，本模型的冲突分别为 3 路和 1 路。

## 迁移：归约复用同一套推理

转置交换的是元素位置；求和归约交换的是各 thread 的部分结果。对 $[1,2,3,4,5,6,7,8]$，8 个 thread 各把一个数写到 shared 并同步。第一层前 4 个 thread 把相距 4 的值相加，得到 $[6,8,10,12]$；下一层相距 2，得到 $[16,20]$；最后相距 1，得到 36。每层读写同一缓冲区，必须在下一层读取之前让上一层的写入完成。

完整例子每 block 有 256 个 thread。输入 1003 个数时需要 4 个 block，末块只有 235 个有效数，其余 21 个 thread 从私有累加器的中性值 0 开始，仍写 shared 并参加每层屏障。第一 kernel 写出 4 个部分和，第二 kernel 在同一 stream 消费它们，形成跨 block 的阶段边界。普通 block 不能用 block 屏障等待整张 grid。求最大值时中性值应改成 $-\infty$；把全负数组的无效槽填成 0 会算错。

浮点加法不严格满足结合律。树形顺序与 CPU 从左到右求和可能有末位差异；检查结果时要用合适容差，同时单独排查漏项、越界与同步错误。归约扩展了本章的方法：先列每一层的读写地址和负责人，再证明可见性，最后检查边界填充值。

## 常见误区

- **“矩阵连续”就代表访问合并。** 要看同一条 warp 指令中的活跃地址。
- **同一 bank 就是冲突。** 同址读取可以广播；不同地址的冲突才需要拆分服务。
- **shared memory 自动保证线程顺序。** 存储位置与写后读的同步保证是两回事。
- **填充一列一定更快。** 它改善这个列读映射，也多占 shared 空间；实际收益须测量。

## 练习与核对

<details>
<summary>左上 tile 的输入第 0 行改为从第 7 个元素开始，32 个 lane 覆盖多少段？只让前 8 个 lane 活跃呢？</summary>

完整 warp 读元素 7–38，段号是 0–4，共 5 段；前 8 个 lane 读元素 7–14，只涉及段 0、1。要按实际活跃 lane 求集合。
</details>

<details>
<summary>将 shared 行跨度改为 34，固定列读的 32 个 lane 分布到多少个 bank？</summary>

$w_\ell=34\ell+c$，bank 号为 $(2\ell+c)\bmod32$。它只遍历 16 个 bank，每个 bank 收到两个不同地址，所以是 2 路冲突模型。额外填充两列不如填充一列适合这个访问。
</details>

<details>
<summary>若转置 kernel 在循环里重复使用同一 shared tile，为什么仅有装载后的屏障还不够？</summary>

快 thread 可能已开始下一轮装载并覆盖 tile，慢 thread 还在读上一轮。需在本轮消费结束和下一轮覆盖之间再放一道所有参与 thread 都到达的回收屏障；一次性转置没有下一轮覆盖。
</details>

<details>
<summary>把归约改为求最大值，末块无效槽该填什么？所有输入为负时填 0 会怎样？</summary>

填 $-\infty$，使它不改变任何有限输入的最大值。填 0 会让全负数组错误地得到 0。同步只能保证读到填充值，不能修正填充值的数学含义。
</details>
