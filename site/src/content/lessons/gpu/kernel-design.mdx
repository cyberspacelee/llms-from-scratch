设 $A\in\mathbb R^{5\times7}$、$B\in\mathbb R^{7\times6}$，我们要计算 $C=AB$。数学式只要求每个 $C_{ij}$ 累加七项；GPU kernel 还必须决定哪个线程写它、怎样协作读取 A 和 B，以及边缘不足一块时如何避免越界。本章从 [G1 线程与 block](/gpu/execution-model/) 和 [G2 内存与同步](/gpu/memory-and-sync/) 出发，把这个小矩阵乘完整地映射到 GPU。文末再用同行计算的 softmax 说明融合适用的另一种依赖结构。

先约定接口：本章 CUDA 示例接受连续行主序的 float32 A、B，另分配 C；不允许输入输出共享存储。元素地址分别为 `A + i*7 + q`、`B + q*6 + j`、`C + i*6 + j`，C 的形状是 $5\times6$。如果 A 是隔列切片，即使形状仍是 $5\times7$，它的实际 stride 也已改变，这个入口就不适用。dtype、形状、stride 和别名约定共同构成 kernel 的正确性前提。

## 一个输出归谁：从公式到线程坐标

矩阵乘的定义是

<KeyEq label="矩阵乘的单个输出">
$$
C_{ij}=\sum_{q=0}^{K-1}A_{iq}B_{qj},
\qquad A\in\mathbb R^{M\times K},\quad B\in\mathbb R^{K\times N}.
$$
</KeyEq>

本例 $M=5,K=7,N=6$。取方便手算的 $A_{iq}=i+q+1$、$B_{qj}=q-j$，则 $C_{00}=1\cdot0+2\cdot1+\cdots+7\cdot6=112$。让一个线程负责一个输出，线程把累计值保存在自己的寄存器，七项全部求完后写 C 一次。这样 $C_{00}$ 不需要原子加法；若将七项分给不同 block，唯一写入的证明就不再成立。

设一个二维 block 对应边长 $t=4$ 的输出 tile。CUDA 示例用 `row=blockIdx.y*t+threadIdx.y`、`col=blockIdx.x*t+threadIdx.x`：grid 的 x 轴有 $\lceil6/4\rceil=2$ 块，y 轴有 $\lceil5/4\rceil=2$ 块。每个有效 $(i,j)$ 恰好由一组 block/thread 坐标表示。右下块虽然有 16 个逻辑线程，只有行 4、列 4 和 5 对应两个有效输出；最终 store 必须检查 `row<M && col<N`。

每个输出线程若自行循环读取七对 A、B，会重复读取相邻输出需要的数：同一 $A_{iq}$ 被相邻列使用，同一 $B_{qj}$ 被相邻行使用。接下来的问题是怎样让一块输出共享这些输入，而不改变任何 $C_{ij}$ 的定义。

## 一个 tile 怎样累计：沿 K 分段复用输入

第一块输出覆盖 C 的行 0–3、列 0–3。先装载 $A_{0:4,0:4}$ 和 $B_{0:4,0:4}$，形成第一段贡献；再装载 K 索引 4–6 的输入，形成第二段贡献，最后才写输出。对上面的 $C_{00}$，两段分别是 $20$ 和 $92$，合起来仍是 $112$。$0:4$ 表示索引 0、1、2、3，K 的第二段只有三个真实位置。

<TileReuseLab client:visible />

图中 A 的高亮列和 B 的高亮行是同一段 K；蓝色 C tile 在所有 K 段里保持不变。调整 tile 边长可以观察装载范围及重复读取数，但图中的“读取”是按算法逐元素计数，不是硬件 DRAM 事务。

一个完整的 $t\times t$ 输出 tile 在一段长度为 $t$ 的 K 上，装载 A、B 各 $t^2$ 个元素，计算 $t^2$ 个输出的 $t$ 次乘加。一次融合乘加（FMA）按 2 FLOP 计，因此运算量为 $2t^3$ FLOP，输入读取为 $2t^2$ 个元素。同一 A 元素在 tile 内被 $t$ 列使用，同一 B 元素被 $t$ 行使用；这正是分块能减少重复输入读取的原因。

对整个 $5\times7$ 乘 $7\times6$ 算例，朴素逐输出逻辑读取是 $2MKN=420$ 个输入元素。分块后，每个 A 元素按输出列 tile 数被装载，每个 B 元素按输出行 tile 数被装载：

$$
R_{\mathrm{tile}}
=MK\left\lceil\frac Nt\right\rceil
+KN\left\lceil\frac Mt\right\rceil.
$$

$t=4$ 时是 $35\cdot2+42\cdot2=154$ 个有效输入元素。减少 266 次逻辑读取不意味着 DRAM 恰好少读 266 个元素：缓存、事务粒度和其他 block 对同一数据的复用会改变实际流量。边缘 padding 仍执行额外乘加，输出有效元素始终只有 30 个。

### 非整除边缘为什么先补零

沿 K 的第二段逻辑索引为 4–7，但 $K=7$，索引 7 越界。装载 A、B 时分别检查它们自己的行列范围，越界槽写零；零不会改变加法中的有效乘积。右下输出块第一段中，虽然只有两个线程最后写 C，其余线程仍可能负责装载有效输入。因而不能按“我不写输出”在 kernel 开头提前退出。

可把每个线程的职责拆成三个判断：A load 看 $i<M$ 且 $q<K$；B load 看 $q<K$ 且 $j<N$；C store 看 $i<M$ 且 $j<N$。三个条件并不相同。例如输出列越界的线程仍可能负责装载 A 的有效元素。仅在 C 的地址上加一个 mask，不能保证 A、B 的访问安全。

## 共享缓冲区：何时能读，何时能覆盖

CUDA 教学实现给一个 block 分配两个 $t\times t$ 的 shared 数组。各线程协作把 A、B 的当前 tile 装入 shared，再用其中的值更新自己的寄存器累计量。shared memory 的作用是让一个 block 内的输出重用刚装载的数据；它不改变不同 block 之间的读写规则。

### 逐步读图：数据在哪里，什么时候可以覆盖

<KernelLifecycleLab client:visible />

按图追踪 $C_{00}$：装载第一段，经过第一道 `__syncthreads()`，所有线程才读取完整的当前 tile；累计到 20 后，经过第二道屏障，下一段才能覆盖相同 shared 数组；第二段累计到 112 后才写 C。右下边缘块也由全部线程参加两道屏障，最终只让两个有效线程写回。

<Figure src="gpu/kernel-pipeline.svg" alt="装载输入、发布屏障、读取并累计、回收屏障、重复或写回的顺序" minWidth="42rem">同一个 shared 缓冲区反复使用。第一道屏障保证当前轮已装载完，第二道保证上一轮已读完；箭头表示依赖顺序，不是耗时比例。</Figure>

若删去第二道屏障，一个较快的 warp 可能在另一个 warp 仍读取旧 tile 时，已经把新 tile 写到同一数组。下一轮装载后的第一道屏障无法修复已经发生的覆盖。两道屏障都在所有线程共同执行的 K 循环中；不能让边缘线程提前返回后只让部分线程到达屏障。

对于 float32，两个 shared 数组每块占 $2t^2\cdot4=8t^2$ byte；$t=4$ 时是 128 byte，$t=16$ 时是 2048 byte。每个输出还需一个累计标量，所以此教学映射有 $t^2$ 个累计槽；它们通常在各线程寄存器中，但不等于编译器报告的全部寄存器用量。增大 tile 会增加复用，也增加线程、shared 和寄存器压力。[G4 驻留资源](/gpu/measurement/#驻留资源先算一个-sm-装得下多少-block) 会把这些量放入同一张资源账。

## 屋顶线：强度决定上限贴着哪条线

对内部完整 tile，只算 A、B 的 float32 输入读取，暂不算 C 的写回，算术强度是

$$
I_{\mathrm{input}}=
\frac{2t^3\ \mathrm{FLOP}}{2t^2\cdot4\ \mathrm{byte}}
=\frac t4\ \mathrm{FLOP/byte}.
$$

$t=16$ 时是 4 FLOP/byte。这个值是该 tile 的局部模型，不是整个 kernel 的 HBM 实测强度；边缘、输出写回、缓存和其他指令都未计入。若输入元素改为 2 byte、运算量仍按相同的 FMA 次数计，局部强度变成 $t/2$ FLOP/byte，但数值精度和可用指令也可能变化。

设假想设备的计算峰值为 $\pi=100$ TFLOP/s、带宽峰值为 $\beta=2$ TB/s。若一个 kernel 每处理 1 byte 最多完成 $I$ FLOP，它由带宽供给的运算速率上限为 $\beta I$；另有计算峰值 $\pi$。两者取小值，就是 [屋顶线模型](https://dl.acm.org/doi/10.1145/1498765.1498785) 的上界：

<KeyEq label="屋顶线上界与脊点">
$$
P\le\min(\pi,\beta I),\qquad
I_{\mathrm{ridge}}=\frac{\pi}{\beta}.
$$
</KeyEq>

本例脊点为 50 FLOP/byte，$t=16$ 的局部输入强度代入，得到 $P\le2\times4=8$ TFLOP/s。这个 8 只是按所选局部字节模型计算的理想上限，不能当作该 CUDA kernel 的速度预测。屋顶线不计发射、同步、驻留不足与实际指令效率；较大的 tile 也可能因资源压力更慢。真实比较在 [G4 测量](/gpu/measurement/) 中进行。

## 融合：等到完整累计值再写

仍用相同 C，假设下一步要计算 $D_{ij}=\max(C_{ij}+b_j,0)$。每个输出线程在七项都累计完成后，手里已有 $C_{ij}$，可以加偏置、做 ReLU，然后直接写 D。这种写回末段常称为 epilogue。它省掉单独写 C、读 C 的中间往返，也可能省 kernel launch。

融合的位置受数学依赖限制。若两段 K 贡献分别是 2 和 $-3$，对总和做 ReLU 得 0；对两段各做 ReLU 再相加却得 2。因而偏置和非线性必须等完整 K 累计结束。若基线是 GEMM、偏置、ReLU 三个独立 kernel，忽略偏置、缓存与输入，C/D 的逻辑读写共 $4MN+8MN+8MN=20MN$ byte；合并写回只有 $4MN$ byte。这个差值只对所述基线成立，融合也可能增加寄存器占用，最终仍需计时。

上面的 CUDA 示例使用普通 float32 标量乘加。Tensor Core 是另一种矩阵乘累加硬件路径；将 `TILE` 改为 16 并不会自动使用它。要核对输入类型、tile 布局、对齐和架构支持，先以 cuBLAS 或框架矩阵乘作为数值与性能基线。[Triton 矩阵乘教程](https://triton-lang.org/main/getting-started/tutorials/03-matrix-multiplication.html) 用一个 program 负责一个输出 tile，并展示地址计算和分块；它的 `BLOCK_SIZE_M/N/K` 是数据块尺寸，不能直接当作 CUDA threads per block。

### 延伸：softmax 的一行为什么适合融合

矩阵乘的输出彼此独立，但同行 softmax 的各个输出共同依赖这一行的最大值与指数和。给定一行有限 logits $x_j$，有效位置集合 $\mathcal V$ 非空时，先取 $a=\max_{j\in\mathcal V}x_j$，再计算

$$
y_j=
\begin{cases}
\exp(x_j-a)\big/\sum_{r\in\mathcal V}\exp(x_r-a),&j\in\mathcal V,\\
0,&j\notin\mathcal V.
\end{cases}
$$

例如 $(1000,1001,1002)$ 减去最大值 1002，得到指数约 $(0.135335,0.367879,1)$，概率约 $(0.090031,0.244728,0.665241)$。减去同一个最大值不改变比值，却避免直接计算 $e^{1002}$ 的溢出。这里的语义 mask 指定哪些输入参与分母；地址边界 mask 则防止宽度不足数据块时越界读取，两者作用不同。

若 $\mathcal V$ 为空，普通概率分布没有定义。本章示例明确约定整行输出零：这不是概率和为 1 的分布。Triton 示例由一个 program 处理一行，在片上连续完成 max、exp、sum 和输出，避免把每个中间结果写回全局内存；它支持最多 4096 列的教学范围以及正 stride 的输入视图。更宽的行需要分段归约；注意力进一步融合值向量时，还需跨块维护最大值和分母，见 [S3 FlashAttention](/systems/flash-attention/)。

## 常见误区

- 边缘线程不写 C，仍可能要装载 A/B 并参加屏障。
- 逻辑读取从 420 降到 154，不代表 HBM 字节或运行时间按同一比例下降。
- 单个 tile 的 FLOP/byte 和全 kernel 的实测 FLOP/byte 是不同对象。
- 稳定 softmax 解决大数指数溢出，不会自动给全屏蔽行定义概率分布。

## 练习与核对

<details>
<summary>把输出 tile 改为 2×2。这个矩阵乘需要多少输出块、多少段 K？有效输入逻辑读取是多少？</summary>

grid 是 $\lceil6/2\rceil\times\lceil5/2\rceil=3\times3$，K 有 $\lceil7/2\rceil=4$ 段。按上面的计数式，读取为 $35\cdot3+42\cdot3=231$ 个输入元素；比边长 4 的 154 多，因为每份 A、B 被更多输出块分别装载。末段 K 只有索引 6 有效，索引 7 仍要补零。
</details>

<details>
<summary>右下输出块的线程发现自己的输出列越界，可以直接跳过 A 的 load 和屏障吗？</summary>

不可以。A 的 load 只取决于输出行和当前 K 列，这个线程可能负责一个有效 A 元素，供块内其他输出列复用。全部 block 线程还须共同经过屏障；最后的 C store 才按输出行列判断。
</details>

<details>
<summary>两段 K 的贡献为 2 与 -3，偏置为 1。应该何时计算 ReLU，结果是多少？</summary>

先累计全部 K，再加偏置，得到 $2-3+1=0$，ReLU 输出 0。若对每段分别应用 ReLU，得到的和一般不同，因此不能把非线性移动进 K 循环。
</details>
