这条路线回答一个问题：一次文本生成，时间和显存到底花在哪里，以及多加一张卡时这笔账怎么变。[模型原理](/principles/) 已经说明注意力在算什么、缓存为什么正确；这里接着问这些张量放在哪、搬多少次、由谁调度。

## 五章各增加一个变量

<ChapterList track="systems" />

读法是顺着走。每章只用前面已经算过的量：S1 给出权重与 KV 的字节、prefill 与 decode 的算术强度；S2 把这些强度放到一张加速器的带宽和算力上，得到能达到的上限，并说明 kernel 怎样靠近它、怎样测量离它多远；S3 和 S4 沿 nano-vLLM 约 1,200 行源码看一个推理引擎怎样把这些账变成调度、页表、张量并行和 CUDA Graph；S5 把同样的账扩展到多张卡和多台机器。

已经熟悉某一层的读者可以从对应一章进入，但 S2 的脊点要用 S1 的字节和强度，S3 的调度器要用 S1 对 prefill 与 decode 的区分。

## 每章读完要能手算的事

| 章 | 新出现的量 | 读完要能手算的事 |
| --- | --- | --- |
| S1 | 权重字节、KV 字节、KV 头数、算术强度、优化器状态 | 换一个上下文长度或 KV 头数，重算缓存字节 |
| S2 | 带宽、算力峰值、脊点、tile 复用 | 判断一个 kernel 该贴着斜线还是平台 |
| S3 | 迭代级调度、块表、前缀哈希 | 给定 block table，逐 token 算出物理槽位 |
| S4 | 批形状、通信落点、graph 捕获、接受率 | 说明一次 decode 在哪些地方同步多张卡 |
| S5 | 切分维度、集合通信、状态放置 | 说出一种并行每一步多出来的通信 |

## 材料各自负责什么

正文里的手算、图和例子是为这条讲义写的。外部材料只在两处出现：定义和数字指向一手来源，阅读顺序参考两条已经整理好的路线。

- [AI Infra Book](https://bojieli.github.io/ai-infra-book/index.html) 把系统从一次执行的资源账写到端边云。本路线借用它的问题分层，每章注明对应的章节，不复述书里的表述和例题。
- [GPU Performance Engineering Resources](https://github.com/wafer-ai/gpu-perf-engineering-resources) 是一份按「一次请求 → 一张 GPU → kernel → 引擎 → 分布式」排好的原始资料索引。本路线用它决定进一步阅读的顺序，不把链接列表当成正文。

一手材料包括论文、NVIDIA 的 CUDA 与 Nsight 文档、产品规格表、Meta 公开的 Llama 3 模型代码，以及 nano-vLLM 的固定源码快照。产品页上的峰值会改版，S2 写明了读取日期；把某个数字写进自己的报告之前，要回到那一页再核对一次。

## 和前两条路线的接缝

[KV cache 的正确性](/principles/kv-cache/) 用 CPU 上的小张量证明：有缓存的逐步解码和整段注意力可以算出同一个结果。那一章故意把存储写成 `torch.cat`，好让等式看得清。从 S1 起，同一块缓存要按字节计价，并在后面的章节里变成页表、带宽和跨机传输。
