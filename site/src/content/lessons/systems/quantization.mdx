一块 GPU 能否装下模型，[S1](/systems/ledger/) 的第一项是权重个数乘每元素字节数。把 bf16 的 2 字节改成 4 bit，看起来容量直接减少四倍；但真实文件还要存 scale，执行器还要解包与反量化，输出分布也可能变化。量化讨论必须同时回答三个问题：表示省了多少、近似改变了多少、目标硬件怎样执行。

本章以一个权重矩阵为入口，需要 [M3 向量与矩阵](/math/linear-algebra/) 和 [S2 单卡上限](/systems/accelerator/)。质量比较沿用 [T4 评估](/training/evaluation/) 的固定数据与协议。我们会手算一种对称整数表示，解释生产方法在这个基础上解决什么问题；不把 CPU 浮点模拟叫作 INT4 kernel 加速。

## 浮点与整数：存储格式并不是同一个数轴

fp32、fp16、bf16 都是浮点数，用符号、指数和有效位表示数值。bf16 与 fp32 有相近指数范围，但有效位更少；fp16 的指数范围更小。范围与精度是两件事，不能把“16 bit”理解为所有格式有同样溢出边界与误差。

整数 INT8 的编码范围通常是 $[-128,127]$，但量化方案可以只使用对称子集 $[-127,127]$。一个整数码 $q$ 必须搭配 scale $s>0$ 与零点 $z$ 才能表示近似实数：

$$
\widehat x=s(q-z).
$$

这里 $s,z$ 是存储元数据，不是神经网络权重的梯度，也不是采样温度。没有它们，整数 12 没有确定的实数意义。量化可针对加载后的权重离线进行，也可在训练时模拟表示误差；本章先分析训练后量化的表示。

## 对称量化：逐步选择范围、scale 与舍入

取有符号 $b$ bit，对称码上限 $Q_b=2^{b-1}-1$，使用 $[-Q_b,Q_b]$，零点设为 0。给定一组待量化数，取 $a=\max|x|$。若 $a>0$，令 $s=a/Q_b$；若全部为零，可以令 $s=1$，所有码取 0。

<KeyEq label="对称量化与反量化">

$$
q=\operatorname{clip}\!\left(\operatorname{round}(x/s),-Q_b,Q_b\right),
\qquad \widehat x=sq.
$$

</KeyEq>

舍入将连续数轴映射到离散网格，截断处理超过表示范围的值。本文脚本采用 NumPy 的 ties-to-even：0.5 舍到 0，1.5 舍到 2，2.5 舍到 2。不同 kernel 若采用别的半整数规则，边界码可能不同，复现时必须记录。无截断且按最近值舍入时，每个元素绝对误差不超过 $s/2$；发生截断时误差可以更大。

```mermaid
flowchart LR
  X[原始实数 x] --> D[除以 scale]
  D --> R[舍入为整数]
  R --> C[截断到码范围]
  C --> Q[压缩存储 q 与元数据]
  Q --> F[执行时反量化或整数 kernel]
```

箭头最后一步不能省略。存储时少读字节，执行时却可能增加转换。是否获益要在实际 kernel 上测量。

## 五个权重：bit 减少怎样改变网格

令 $x=(-1,-0.5,0,0.5,1)$。INT8 对称量化 $Q_8=127$，$s=1/127$，整数码为 $(-127,-64,0,64,127)$，反量化为 $(-1,-64/127,0,64/127,1)$。中间两个误差约为 0.003937，而端点与零精确。

为了看清网格，使用教学 3 bit 对称范围 $[-3,3]$，这并不是某个生产格式的默认规范。此时 $s=1/3$，舍入后码为 $(-3,-2,0,2,3)$，反量化为 $(-1,-2/3,0,2/3,1)$，0.5 的误差上升到 1/6。对这五个数平均平方误差为 $2(1/6)^2/5=1/90$。

位数变少时网格更疏，但误差对模型的影响还取决于输入。沿数学路线的列向量布局，$y=Wx$，量化后 $\widehat y=\widehat Wx$，令 $E=\widehat W-W$，则

$$
\widehat y-y=Ex,\qquad
\|Ex\|_2\le\|E\|_F\|x\|_2.
$$

这是一个上界，既不证明所有输入都达到它，也不证明相同权重均方误差会产生相同任务误差。输入在哪些方向取大值、误差落在哪些通道，会影响输出。所以只报权重误差不足以宣称模型质量保持。

## 非对称量化：零点让网格适应不居中的范围

若待表示数据主要在 $[0,6]$，有符号对称范围会浪费负半轴。用无符号码 $[0,255]$ 时，先让选择的范围包含 0，即下界取原最小值与 0 中较小者、上界取原最大值与 0 中较大者；可令 $s=(x_{\max}-x_{\min})/255$，零点 $z=\operatorname{clip}(\operatorname{round}(-x_{\min}/s),0,255)$，再用 $q=\operatorname{clip}(\operatorname{round}(x/s)+z,0,255)$。全零数组使用 $s=1,z=0$。

当 $x_{\min}=0,x_{\max}=6$，$s=6/255,z=0$，零可精确表示。对于范围 $[-2,6]$，$s=8/255$，理想零点为 63.75，舍入后取 64。零点本身是整数，端点可能因舍入不能同时精确落在网格；“仿射量化”不是毫无误差地线性变换原数组。

矩阵乘中两个 zero point 会引入偏移校正项。若整数算子使用 $\sum_j(q_{w,j}-z_w)(q_{x,j}-z_x)$，展开后除了整数点积，还包含两种整数和与常数项。硬件及 kernel 是否融合这些项，会影响开销。不要只看到整数乘法更便宜就忽略完整执行路径。

## 粒度与异常值：谁共享一个 scale

逐张量（per-tensor）让所有元素共享 scale，元数据最少；逐通道（per-channel）为某个轴的切片分别存 scale；逐组（per-group）把通道中的连续元素再划为固定小组。报告必须说明具体轴，尤其 PyTorch 线性权重按输出行保存，不能仅写“按行”而不说明布局。

取矩阵的两行 $(-1,-0.5,0,0.5,1)$ 和 $(-20,-1,0,1,20)$。共同用 3 bit scale $20/3$，第一行所有非端点小数都可能舍为 0，连 ±1 也会消失。分别按行量化，第一行用 $1/3$，保留明显更多信息；第二行仍受大值 20 支配。进一步分组可能把异常值所在位置与小值隔离，但每组多存一份元数据。

异常值不一定是应该删除的坏数据。它可能承载模型的重要特征，直接裁剪会改变函数。校准（calibration）使用代表性输入估计激活范围和敏感通道；校准数据与线上请求差别大时，误差评估会乐观。量化配置属于模型发布契约，需要跟着 checkpoint 保存。

## 字节账：把元数据与打包算进去

若 $N$ 个权重用 4 bit、每组 $G=128$，每组存一个 fp16 scale，无 zero point，则完整组的字节为

$$
128\cdot4/8+2=66.
$$

平均每权重 66/128=0.515625 字节，相比 bf16 的 2 字节压缩约 3.879 倍，已经小于 4 倍。若再存 1 字节零点，就是 67/128 字节；尾组、对齐填充、打包索引与加载时临时工作区还会进一步改变实际峰值。

本章 NumPy 示例把码存在 `int8` 容器中，即使只使用 3 bit 范围，也仍占每元素 1 字节。它验证整数值与误差，不实现 bit packing。因此其 `nbytes` 不能当 3 bit 文件的存储大小，理论字节必须单独计算。生产格式常采用不同布局来适配 kernel，不能只将一个 Python 数组类型改名就得到压缩模型。

## 权重、激活与 KV：三个对象三种生命周期

权重量化可以在部署前处理，并对很多请求复用；激活取决于当前输入，可能需要动态 scale 或事先校准范围；KV 状态随每条请求追加，量化后会被未来很多查询反复读取。它们不是同一笔误差。

权重-only 路径通常将压缩权重在 kernel 内恢复为浮点参与计算，较大的预填充矩阵乘未必更快；权重与激活共同量化可能使用整数矩阵乘，但还要支付激活统计与转换。KV 量化既减少常驻容量也减少历史读取带宽，不过需要每次写入维护 scale、读取反量化，并评价长上下文下累积影响。不能用一次短输入的 perplexity 核对覆盖所有缓存长度。

SmoothQuant 通过等价缩放把某些激活大值带来的量化难度迁移到权重：对可逆对角缩放矩阵 $D$，$XW=(XD^{-1})(DW)$。这个等式在未量化时精确，选 scale 的目的在于让量化后的两侧更易表示。AWQ 则利用激活信息识别对输出影响大的权重通道，并采用保护性缩放。它们都需要先定义量化对象与误差，不能把方法名当成质量保证。QLoRA 的低精度冻结基座与可训练 adapter 另见 [T6 LoRA](/training/lora/)。

## 常见误区

- 位数减半就把所有显存减半。缓存、激活、元数据和工作区可能不变。
- 更小文件就必然更快。反量化、打包布局和 kernel 支持决定执行成本。
- 校准集损失没变就表示所有任务没变。分布与长上下文都需要单独检查。
- 浮点格式与整数 bit 数可直接比较。指数范围、网格与 scale 机制不同。

<details>
<summary>对称 INT8 的 scale 为 0.02，数值 0.031 与 3.0 如何表示？</summary>

0.031/0.02=1.55，舍为 2，恢复 0.04，误差 0.009。3/0.02=150，截断到 127，恢复 2.54，误差 0.46；后一项不能套无截断时 $s/2=0.01$ 的误差界。

</details>

<details>
<summary>某量化模型 TTFT 更慢，但可承载更多请求，总吞吐更高，结论冲突吗？</summary>

不冲突。单请求预填充可能因转换变慢，容量增长却允许更高并发、更充分的权重复用。应分别报告相同负载下的延迟与给定 SLO 下的最大有效吞吐。

</details>
