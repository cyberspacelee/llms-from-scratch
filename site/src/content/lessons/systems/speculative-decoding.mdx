[P9 生成](/principles/generation/) 每选一个 token，就要用新的历史再问目标模型一次；[P10 KV cache](/principles/kv-cache/) 避免重算旧历史，却没有消除逐次等待。设一个便宜的草稿模型先提出两个候选。目标模型可以用一次因果前向同时检查它们，但草稿的概率与目标不同，直接提交候选会改变输出分布。本章从一个位置的三类别例子解决这个偏差，再把规则用于两步验证。需要 [M1 概率](/math/probability/) 中的条件概率；性能账接 [S1](/systems/ledger/) 和 [S2](/systems/accelerator/)。

这里的目标是**分布相同**：对每段已提交历史，下一个 token 仍服从目标模型指定的采样分布。使用相同 seed 不保证与普通生成得到逐项相同的随机输出，因为两种算法消耗随机数的顺序不同。

## 一个位置：草稿多给了第一类多少概率

固定历史 $h$，令目标的实际采样分布为 $p=(0.5,0.3,0.2)$，草稿分布为 $q=(0.6,0.1,0.3)$。三项依次对应 token ID `0,1,2`。$p$ 与 $q$ 必须是**同一历史、同一词表上的归一化分布**。若生成协议包括温度或 top-p，就分别在目标和草稿完成这些变换后再比较实际用于抽样的概率。

草稿从 $q$ 抽出候选 $x$。目标只接受其中与 $p$ 重合的概率质量：对提出的 $x$，以

<KeyEq label="候选接受概率">
$$
\alpha(x)=\min\!\left(1,\frac{p(x)}{q(x)}\right)
$$
</KeyEq>

的概率接受。比值只在 $q(x)>0$ 的候选上求值，因为草稿不可能提出 $q(x)=0$ 的类别。本例若提出 ID 0，接受概率是 $0.5/0.6=5/6$；提出 ID 1，目标概率反而更大，所以必定接受；ID 2 以 $0.2/0.3=2/3$ 接受。把提出概率乘回去，三项被接受并输出的质量分别为 $0.5,0.1,0.2$。它们还缺 ID 1 的 $0.2$。

拒绝事件出现时，必须从**尚缺的目标质量**中抽一个替代 token。记缺口 $d(x)=\max(p(x)-q(x),0)$，总缺口 $D=\sum_xd(x)$，则拒绝后的条件分布为 $r(x)=d(x)/D$。本例 $d=(0,0.2,0)$，$D=0.2$，所以拒绝后必定输出 ID 1。若直接从 $p$ 重抽，会把已经接受过的质量再次分配。

| 候选 ID | 草稿提出 $q(x)$ | 接受率 $\alpha(x)$ | 接受并输出 $q(x)\alpha(x)$ | 拒绝后补入 $D r(x)$ | 最终输出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 0.6 | $5/6$ | 0.5 | 0 | 0.5 |
| 1 | 0.1 | 1 | 0.1 | 0.2 | 0.3 |
| 2 | 0.3 | $2/3$ | 0.2 | 0 | 0.2 |

表的末列回到了目标 $p$。若误从 $p$ 重抽，拒绝概率 0.2 会贡献 $0.2p=(0.1,0.06,0.04)$，末列变成 $(0.6,0.16,0.24)$。问题并不在于草稿有没有猜中最大概率类别，而在于每一类的概率质量如何流动。

## 为什么这条规则对任意有限分布成立

对任意类别 $x$，草稿提出并被接受的概率正好是 $\min(p(x),q(x))$。记总接受率 $A=\sum_x\min(p(x),q(x))$。由于 $p$、$q$ 各自求和为 1，所有正部缺口的和等于拒绝概率 $D=1-A$。因此

$$
\begin{aligned}
P(\text{最终输出 }x)
&=\underbrace{\min(p(x),q(x))}_{\text{接受草稿}}
 +\underbrace{D\frac{(p(x)-q(x))_+}{D}}_{\text{拒绝后补偿}}\\
&=p(x).
\end{aligned}
$$

这也解释了两个边界。若 $q(x)=0$ 而 $p(x)>0$，该类不会从草稿接受分支出现，却仍能从残差分支出现；不需要把 $p/q$ 定义在这个点。若 $p=q$，则 $D=0$、拒绝不可能发生，也不应该除以零去构造残差。一个位置的平均接受率还可写成 $A=1-\tfrac12\sum_x|p(x)-q(x)|$。草稿分布越接近目标，平均接受率越高；这不等同于两者的 argmax 相同。

这个证明要求：候选确实按保存的 $q$ 抽取；目标与草稿各位置使用其**实际条件历史**；接受、补偿和最终输出使用一致的采样协议。有限精度和实现细节可能造成微小误差，不能把数学等式当作任意服务配置下的逐位恒等保证。

## 两步草稿：一次验证怎样给出三个分布

现在令历史是已缓存的 `[1,2]`。草稿先在这个历史下抽 $x_1=0$，再在 `[1,2,0]` 下抽 $x_2=2$，同时保存两次分布 $q_1(\cdot\mid[1,2])$ 和 $q_2(\cdot\mid[1,2,0])$。目标在处理历史末项 2 后保存的 logits 给出 $p_1(\cdot\mid[1,2])$；将已知草稿 `[0,2]` 送进一次因果块前向，它的两行 logits 分别给出 $p_2(\cdot\mid[1,2,0])$ 和全接受时额外抽样所需的 $p_3(\cdot\mid[1,2,0,2])$。若没有保存 $p_1$，就需连历史末项一起计算。批验证减少串行目标调用，因果条件没有消失。

为单独看清控制流，假设本轮的 $p_1,q_1$ 正是上面的三候选例子，而第二位置也恰好有同样的数值。**数值重复不代表两个位置共享历史**：第二位置必须重新在 `[1,2,0]` 下求分布。若目标模型在那里给出不同概率，以下步骤只需换用新的 $p_2,q_2$。

| 检查结果 | 已接受的草稿 | 本轮新增输出 | 可继续验证后面的草稿吗 |
| --- | --- | --- | --- |
| 第一位置拒绝 | 无 | 从第一位置残差抽一个 | 不可，第二候选依赖被拒绝的 0 |
| 第一位置接受、第二位置拒绝 | `0` | `0` 加第二位置的残差 token | 不可，后续历史已改变 |
| 两位置都接受 | `0,2` | `0,2` 加从 $p_3$ 抽的额外 token | 已无候选 |

逐位置按顺序检查，遇到**首次拒绝**就停止。假设第一位置接受、第二位置提出 2 却拒绝；本例的残差只含 ID 1，新增输出就是 `[0,1]`。已经计算的第二候选 2 不能保留，因为模型下一次应该以 `[1,2,0,1]` 为历史。若两项全接受，还要从 $p_3$ 抽一个额外 token；这使一次验证最多返回 $k+1$ 个，而不是只有 $k$ 个。

为什么整个序列也正确？在每个真正提交的位置，上一节的枚举保证其输出服从目标在**已提交历史**下的条件分布。首次拒绝后不再沿错误历史继续；全接受时额外 token 直接从目标分布抽。逐位置应用概率链式法则，就得到目标原本的序列分布。贪心变体可以按候选是否等于目标 argmax 处理，但那是另一个确定性协议，不能用它的规则声称保持这里的随机采样分布。

## KV cache：输出 ID 与已计算状态相差一步

[P10](/principles/kv-cache/) 的关键约定是：某个 token 被**选中**时，它的 KV 不一定已经计算；下轮输入这个 token 后才得到它的 KV。目标验证草稿时写入的 KV 也有可能属于后来被拒绝的路径。沿上例，从已缓存 `[1,2]` 开始，验证暂时计算了草稿 0、2 的目标 KV。

| 结果 | 已提交的完整 ID | 可保留的目标 KV 历史 | 下轮尚需输入 |
| --- | --- | --- | --- |
| 第二位置拒绝，补到 1 | `[1,2,0,1]` | `[1,2,0]` | 1 |
| 两位置全接受，$p_3$ 抽到 2 | `[1,2,0,2,2]` | `[1,2,0,2]` | 2 |

第一行必须截掉验证阶段为 2 写入的 KV。草稿模型自身的缓存也要与提交后的历史对齐；替代 token 或额外 token 在其下一次提案前需被处理。分页缓存还要同步有效长度、块引用和尾块回收，不能只缩短 Python 的 ID 列表。EOS 只有在被接受或作为残差/额外 token 真正抽中后才结束；输出预算可能使本轮少提交 token，批中每条请求也有不同的首次拒绝位置。

## 是否加速：把节省的目标调用与新增工作相抵

为得到可手算的数量，**暂时假设**每个候选独立地以同一概率 $a$ 被接受，草稿长度为 $k$。一轮总会提交至少一个 token；要提交第 $i+1$ 个，前 $i$ 个候选都必须被接受，所以

$$
\mathbb E[N]=\sum_{i=0}^{k}a^i.
$$

本章三类别例子的单位置接受率是 $a=0.8$。若示意性地延长为 $k=4$ 且各位置维持独立的 0.8，期望提交数为 $1+0.8+0.64+0.512+0.4096=3.3616$；$a=1$ 时是 $k+1$，$a=0$ 时仍为 1。实际语言模型的接受事件随历史和位置变化，不能把这个独立假设当作普遍预测。

设普通目标逐 token 延迟为 $c_t$，草稿每步为 $c_d$，目标批验证 $k$ 个候选所用时间为 $c_v(k)$，其他采样、同步及缓存管理时间为 $c_o$。同样输出 $\mathbb E[N]$ 个 token 的近似延迟比是

$$
\mathrm{speedup}\approx
\frac{c_t\mathbb E[N]}{k c_d+c_v(k)+c_o}.
$$

例如在上述 $k=4$ 假设下，若教学用成本为 $c_t=10$ ms、$c_d=1$ ms、$c_v(4)=12$ ms、$c_o=1$ ms，比例约为 $33.616/17=1.98$。草稿若变为每步 5 ms，分母升到 33 ms，优势几乎消失。这些数是算例，不是设备实测。验证虽并行，仍要计算注意力、激活与 KV；高并发时普通 decode 已能复用权重，额外验证也会争抢预算。选择 $k$ 应在固定目标、采样协议、请求长度分布和 SLO 下测端到端延迟及吞吐，指标边界见 [S10](/systems/serving-evaluation/)。

## 练习与核对

<details>
<summary>把例子改为 $p=(0.2,0.8)$、$q=(0.7,0.3)$。拒绝后抽什么？</summary>

接受质量为 $(0.2,0.3)$，总接受率为 0.5。目标缺口是 $(0,0.5)$，所以拒绝后只抽第二类；其最终质量为 $0.3+0.5=0.8$。

</details>

<details>
<summary>三个候选在第二个首次拒绝，本轮输出多少 token，保留哪些候选 KV？</summary>

输出第一个已接受候选和第二位置的残差，共两个 token。目标缓存只保留第一个候选的 KV；第二、第三候选处于错误历史，不能提交。残差 token 的 KV 下一轮再计算。

</details>

<details>
<summary>若草稿与目标支持集完全不相交，分布还正确吗？会加速吗？</summary>

所有候选都在第一位置被拒绝，残差就是目标分布，因此仍输出正确的目标 token；每轮只提交一个，额外草稿与验证工作一般使它更慢。

</details>
