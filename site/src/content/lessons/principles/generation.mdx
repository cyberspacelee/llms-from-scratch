## 从一次预测到一段输出

[P2](/principles/language-modeling/) 用真实文档 `[BOS,A,B,EOS]` 训练下一 token 预测；[P4](/principles/decoder/) 给出完成这项预测的 Decoder。现在只有提示 `[BOS,A]`，真实后文未知。怎样让模型自己接着写，又知道何时停止？本章先用一个四类模型走完循环，再研究选择下一项的规则。这里只需要 [M2](/math/distributions/) 的 softmax；KV cache 留给下一章。

词表 ID 固定为 `BOS=0,A=1,B=2,EOS=3`。模型读取 `[BOS,A]` 后，在最后位置给出四个 logits

$$
z=(\ln0.1,\ln0.4,\ln0.3,\ln0.2),\qquad
p_\theta(\cdot\mid BOS,A)=\operatorname{softmax}(z)=(0.1,0.4,0.3,0.2).
$$

这是一组用于手算的假设分数，不宣称 P2 中的模型训练后恰好输出它们。$p_\theta$ 是模型在给定历史下的条件分布，四项对应 BOS、A、B、EOS。选择规则可能把它改成另一个分布 $q$；**模型权重不会因修改温度或 top-p 而改变**。

## 自回归：为什么每选一项就要再问一次模型

对于长度 $T$ 的单条非空 prompt，Decoder 返回形状 $(1,T,4)$ 的 logits；只取最后一个有效位置的四类分数。假定这一步从上面的分布选中 B，则 B 成为历史的一部分。模型下一次要回答的是 $p_\theta(\cdot\mid BOS,A,B)$，不是再使用旧的 $p_\theta(\cdot\mid BOS,A)$。例如新分布若为 $(0.1,0.1,0.2,0.6)$，下一步可以选中 EOS：

| 次数 | 输入历史 | 取哪一行 logits | 选中 | 更新后的历史 |
| --- | --- | --- | --- | --- |
| 1 | `[BOS,A]` | A 所在的最后位置 | B | `[BOS,A,B]` |
| 2 | `[BOS,A,B]` | B 所在的最后位置 | EOS | `[BOS,A,B,EOS]`，停止 |

这就是自回归生成。第一步选 B 只是该分布下的一种可能，并非贪心结果。一般地，在第 $t$ 步先取 $p_\theta(u_t\mid u_{<t})$，再按选定协议抽样或选最大项，接到历史；下一步的输入依赖这次选择。用已知真实后文一次算出各位置损失的 teacher forcing，与这个逐步生成过程不同。

本章的单条示例没有 padding，因此 `logits[0,-1]` 就是最后有效位置。批生成若在右侧补 PAD，这个索引可能读到 PAD 的位置；需要按每条请求的有效长度取相应行。示例代码每步重算整段历史，虽然重复计算，但下一章可以直接用它核对缓存版输出。

## 先选最大值，还是从概率中抽样

贪心（greedy）选 $\arg\max_c z_c$，本例必选 A，得到 `[BOS,A,A]`。softmax 不改变分数排序，因此贪心无须先算概率；精确并列时必须约定如何打破并列。随机采样则按四项概率抽一个 ID，本例抽到 B 的概率为 0.3，抽到 EOS 的概率为 0.2。EOS 若在第一步出现，输出就是 `[BOS,A,EOS]`，循环立刻结束。

贪心只最大化**当前一步**概率。进一步假设选 A 后的新分布为 $(0.2,0.2,0.2,0.4)$，而选 B 后仍是上表的 $(0.1,0.1,0.2,0.6)$。贪心先选 A，再选该历史下概率最大的 EOS，完整输出 `A,EOS` 的概率为 $0.4\times0.4=0.16$；另一条 `B,EOS` 的概率为 $0.3\times0.6=0.18$。这已构成贪心输出不是最高概率完整序列的反例。束搜索可保留多条候选历史，但评分还需处理长度与结束；本章先把单路径生成算清。

## 温度：怎样改变 A 与 B 的相对机会

对原始 logits 除以正温度 $\tau$ 再做 softmax，得到采样分布

$$
q_c^{(\tau)}=\frac{\exp(z_c/\tau)}{\sum_a\exp(z_a/\tau)},\qquad
\frac{q_A^{(\tau)}}{q_B^{(\tau)}}=\exp\!\left(\frac{z_A-z_B}{\tau}\right).
$$

本例 $z_A-z_B=\ln(4/3)$。$\tau=1$ 时 A:B 为 4:3；降到 $\tau=0.5$ 后比值变成 16:9，概率与原概率平方成正比：

$$
q^{(0.5)}=\frac{(0.01,0.16,0.09,0.04)}{0.30}
=(0.0333,0.5333,0.3000,0.1333).
$$

升温则让各分数差的作用变小。只改变正温度时，排序不变，纯贪心仍选 A；低温也不保证输出正确。某些 API 将 `temperature=0` 作为切换到贪心的特殊设置，不能把 0 代入上式。

## Top-k 与 top-p：候选集合怎样确定

温度仍给每类正概率。有时希望排除低概率候选，再对留下的概率归一化。top-k 保留概率最大的固定 $k$ 项。本例 $k=2$ 只留下 A、B，它们原来合计 $0.4+0.3=0.7$，最终分布按 BOS、A、B、EOS 的 ID 顺序写成 $(0,4/7,3/7,0)$。它的候选数固定，无法随分布的尖锐程度调整。

核采样 top-p（nucleus sampling）则按概率降序，保留累计概率**首次达到** $p$ 的最短前缀。本例 $p=0.6$：A 单独只有 0.4，再加入 B 达到 0.7，因此也得到 $(0,4/7,3/7,0)$。如果 $p=0.2$，A 一项已足够，得到只选 A 的分布。跨过阈值的 B 必须留下；若按“累计和大于 $p$ 就删掉当前项”写代码，甚至可能把唯一候选也删掉。

top-k 与 top-p 在这组数上碰巧相同，规则并不相同。将第一步分布变为 $(0.1,0.7,0.1,0.1)$，$k=2$ 仍保留两项，$p=0.6$ 只保留 A。严格的 top-k 遇到并列分数时需要确定的排序规则；示例实现用稳定排序，让较小的原 ID 先出现。

## 生成什么时候结束

若抽到 EOS，就把它接到输出并停止。另一种停止是调用方的 `max_new_tokens` 预算：例如从 `[BOS,A]` 开始只允许 1 个新 token，即使这一步选中 B，也会停止在 `[BOS,A,B]`；这是**预算截断**，不是模型选择了结束。预算为 0 时原样返回 prompt，不应多采一次。

还要检查上下文容量。示例 Decoder 的学习式位置表若只容纳 4 个输入位置，本章保守接口要求 `prompt 长度 + 最大新 token 数 <= 4`。只有两项位置可用时，不能要求三个新输出后还继续前向。RoPE 虽可计算更远位置，也不意味着模型在那里可靠；长上下文边界见 [A4](/advanced/long-context/)。

EOS 是一个 token ID；“遇到字符串就停止”是另外的文本级协议。停止字符串可能跨多个 token，流式输出还需处理未完成的解码字节。批处理也不能因为一条请求生成 EOS 就停止全部请求，每条请求有自己的结束状态和输出预算。

## 选读：min-p 与重复惩罚如何修改同一分布

min-p 相对于当前最大概率设门槛：保留 $q_c\ge p_{\min}\max_a q_a$ 的项。它与 top-p 的累计质量门槛不同。对本例原始分布取 $p_{\min}=0.6$，门槛是 $0.6\times0.4=0.24$，只留下 A、B，仍得 $(0,4/7,3/7,0)$。若先降温到 0.5，最大概率是 0.5333，门槛变为 0.32，仅 A 留下。最大项总能通过门槛，所以它不会产生空集合。

本例 A 已出现在 prompt 中，而模型又给 A 最大概率 0.4。采用 CTRL 形式、系数 $\theta\ge1$ 的重复惩罚时，只对历史中已出现的 ID 修改**原始 logits**：正分数除以 $\theta$，零或负分数乘以 $\theta$；同一 ID 重复出现也只处理一次。我们的 $z_A=\ln0.4<0$，取 $\theta=2$ 后变为 $\ln0.16$。BOS 也在历史中且 $z_{BOS}=\ln0.1<0$，因此同时变成 $\ln0.01$；归一化后的四项为 $(0.01,0.16,0.30,0.20)/0.67$。B 的排序升到第一。惩罚不会识别语义上合理的重复，例如代码里再次出现的变量名。

按 logits 正负分段的规则不保持 softmax 的平移不变性：原始 $z$ 全部加上相同常数时，未经惩罚的 softmax 不变，但某些历史项会从“乘”切换到“除”，惩罚后的分布便改变。实际调用需要记录具体惩罚公式和应用顺序。本文参考实现依次做重复惩罚、除以温度、top-k、top-p、min-p，最后归一化；例如先做 top-k 再惩罚，已删掉的候选就无法因为惩罚 A 而回到集合。

阈值恰好等于浮点累计和时，top-p 的候选集合可能受舍入影响。数学定义要先说清“保留跨过阈值项”，工程实现还应记录精度和并列规则。脚本用不在这类边界上的 $p=0.6$ 核对主算例。

## 对话输入：为什么同样的采样设置也可能答非所问

上述 `[BOS,A]` 是基础模型的续写提示。聊天模型通常还需要把 system、user、assistant 等角色消息按**该模型的 chat template** 排列，再由 tokenizer 编码成 token ID。比如用户消息的内容仍为 A，一个假设模板可能送入 `[BOS,USER,A,END_TURN,ASSISTANT]`，然后从 ASSISTANT 后面开始生成；这里的 `USER` 等符号仅表示该模板自己的控制项，并非前面四类教学词表中的 ID。角色边界、每轮结束项与 assistant 起始项依模型而异。这些控制项仍是输入序列的一部分，并没有增加神经网络层。不能把另一个模型的模板拿来套用，也不能手工多加一次 BOS。

指令微调让模型学习如何依据角色和任务回答；裸文本续写权重不一定具备同样行为。[T5](/training/instruction-tuning/) 再讨论训练数据与 loss mask。模板不匹配改变模型实际看到的历史 $u_{<t}$，调整温度只改变给定历史下的选择分布，修复不了输入契约。某模型的思考段落、停止标记和输出展示规则也应按它自己的模板与训练协议处理。

## 常见误区

- 贪心只选每一步最大项，不能保证完整序列的概率最大。
- 温度、top-k 与 top-p 修改选择协议，不会更新模型权重。
- top-p 必须保留跨阈值项；top-k 遇到并列项还需指定规则。
- EOS、输出预算和上下文容量分别属于模型选择、调用约束和可计算范围。
- chat template 改变模型读到的历史，采样参数无法代替它。

## 练习与核对

<details>
<summary>只把第一步的 top-p 从 0.6 改为 0.45；再改为 0.8。各保留什么？</summary>

概率降序为 A 0.4、B 0.3、EOS 0.2、BOS 0.1。$p=0.45$ 时 A 不足，加入 B 后到 0.7，保留 A、B；$p=0.8$ 时还要加入 EOS，达到 0.9，保留 A、B、EOS。两种情况都要重新归一化，后者按 ID 顺序为 $(0,4/9,3/9,2/9)$。

</details>

<details>
<summary>在固定四个 logits、不开其他过滤和惩罚时，升高温度会让 min-p=0.6 留下的候选减少吗？</summary>

不会。对任一非最大项 $c$，它与最大项 A 的概率比是 $\exp((z_c-z_A)/\tau)$；因为 $z_c-z_A\le0$，升高正温度只会让该比值向 1 增加。因此已达到相对门槛的项不会退出。若先改变 logits 或用别的过滤改变候选集合，不能直接套用这个结论。

</details>

<details>
<summary>把 prompt 改成 `[BOS,A,B]`、预算改为 0；应该返回什么？若预算为 1 且选到 EOS 呢？</summary>

预算为 0 时原样返回 `[BOS,A,B]`，不调用模型。预算为 1 且选到 EOS 时，返回包含结束 ID 的 `[BOS,A,B,EOS]`；展示给读者时可按 tokenizer 的约定隐藏这个特殊项。两种停止原因不同。

</details>
