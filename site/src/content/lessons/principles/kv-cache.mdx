在 [P9](/principles/generation/) 中，生成一个新 token 后，朴素做法是把增长后的整段历史再次送进 Decoder。这样当然能得到下一步 logits，却把早已算过的历史位置重复计算了一遍。本章使用同一段 `[BOS,A,B,C,D]`：先读 `[BOS,A,B]`，再加入 C、D，说明怎样只算新增位置，同时保留整段重算的结果。先假设模型权重固定、处于 eval 模式、没有 padding 或窗口，且每步采用同一套 RoPE 频率。

**KV cache** 是每层保存历史键 K 和值 V 的状态；**prefill** 是一次处理已有提示并建立缓存；**decode** 是随后用新 token 继续前向。采样出 C 的那一刻，缓存仍只包含 `[BOS,A,B]`。下一次以前向输入 C，才会写入它的 K/V 并得到预测 D 所用的 logits。采样出的最后一个 token 若不再进入前向，就不在缓存里。

## 整段重算：新增 token 会改变哪些行？

先看一个注意力头。设位置 $i=0,\ldots,4$ 分别是 BOS、A、B、C、D。每个位置的查询、键、值由该层输入投影得到；[P7](/principles/rope/) 的 RoPE 把位置 $i$ 的查询和键旋转，记为 $\widetilde q_i=R(i)q_i$、$\widetilde k_i=R(i)k_i$。每对二维坐标有自己的频率；下面的数值例只有一对，其频率为 1 弧度/位置。注意力分数是

$$
s_{ij}=\frac{\widetilde q_i^\top\widetilde k_j}{\sqrt{d_h}}+M_{ij},\qquad
M_{ij}=\begin{cases}0,&j\le i,\\-\infty,&j>i.\end{cases}
$$

这里的 **causal mask** 只屏蔽未来键；它不是训练损失中排除目标位置的 mask。softmax 使未来键的权重为零，所以第 $i$ 行输出仅依赖位置 $0,\ldots,i$：

$$
y_i=\frac{\sum_{j=0}^{i}\exp(\widetilde q_i^\top\widetilde k_j/\sqrt{d_h})v_j}
{\sum_{\ell=0}^{i}\exp(\widetilde q_i^\top\widetilde k_\ell/\sqrt{d_h})}.
$$

如果在三项提示后追加 C，原来 BOS、A、B 三行的可见集合都不变。注意力不会回头改写它们；逐位置的归一化、FFN 和残差也不会让未来 token 流入旧行。这是缓存成立的因果条件。若使用双向注意力或跨位置统计，不能直接套用这个结论。

为了看到具体的数，在本头令 $d_h=2$，所有未旋转的 $q_i=k_i=(1,0)^\top$，而 $v_i=(i,0)^\top$。于是 C 位于 $i=3$，它对四个可见键的缩放分数依次为

$$
(s_{30},s_{31},s_{32},s_{33})
=\frac{1}{\sqrt2}(\cos3,\cos2,\cos1,1)
\approx(-0.7000,-0.2943,0.3821,0.7071).
$$

对这四项做 softmax 后再加权 $v_0,\ldots,v_3$，C 行输出的首坐标约为 **2.061223**。D 是未来位置，不能进入 C 行的分母。这个数稍后由整段、逐 token 和分块三种调用独立得到。

## Prefill 后为什么只保存 K/V？

对 `[BOS,A,B]` 做 prefill，得到三个位置的输出，同时保存 $\widetilde k_0,\widetilde k_1,\widetilde k_2$ 和 $v_0,v_1,v_2$。采样出 C 后，下一次前向只给 C：先计算它的新 Q/K/V，并对 Q/K 用绝对位置 3 旋转。C 的查询需要与键 0、1、2、3 配对，然后混合对应 V；旧查询只参与过旧行的输出，不会被 C 使用。

$$
\underbrace{\widetilde q_3^\top}_{1\times2}
\underbrace{[\widetilde k_0,\widetilde k_1,\widetilde k_2,\widetilde k_3]}_{2\times4}
\longrightarrow\underbrace{(s_{30},s_{31},s_{32},s_{33})}_{1\times4}
\xrightarrow{\text{softmax、加权 V}} y_3^\top.
$$

| 调用 | 输入位置 | 计算的查询行 | 返回后缓存覆盖的位置 |
| --- | --- | --- | --- |
| Prefill `[BOS,A,B]` | 0, 1, 2 | 0, 1, 2 | 0, 1, 2 |
| Decode C | 3 | 3，读取键 0–3 | 0–3 |
| Decode D | 4 | 4，读取键 0–4 | 0–4 |

每一行只在**输入该 token 时**进入缓存。若 prefill 的末行 logits 先采样出 C，采样完成与下一次输入 C 之间，返回文本已有 C，而缓存仍只到 B。

本章缓存**已旋转的 K**和未旋转的 V。旧注意力权重也不能复用：新 Q 改变了整行分数。缓存未旋转 K 也可行，但读取时必须用每个键原有的位置旋转；两种缓存契约不可混用。上面的短式省略了 $1/\sqrt{d_h}$ 缩放，实际计算始终保留它。

| 阶段 | Q 的形状 | 可用 K/V 的形状 | 分数形状 |
|---|---|---|---|
| Prefill，提示长 3 | $(B,n_q,3,d_h)$ | $(B,n_{\mathrm{kv}},3,d_h)$ | $(B,n_q,3,3)$ |
| Decode C，已有 3 个位置 | $(B,n_q,1,d_h)$ | $(B,n_{\mathrm{kv}},4,d_h)$ | $(B,n_q,1,4)$ |

轴顺序是 batch、头、位置、特征。本页数值例只有一个头，令值宽也为 $d_h$。一般模型若使用 [P8](/principles/modern-decoder/) 的 GQA，$n_{\mathrm{kv}}<n_q$，多个 Q 头共享一组 K/V；这减少缓存量，却不改变每个头的可见位置。每层缓存形状为两份 $(B,n_{\mathrm{kv}},T_{\mathrm{past}},d_h)$，未量化总元素数为 $2Bn_{\mathrm{layers}}T_{\mathrm{past}}n_{\mathrm{kv}}d_h$。缓存不包括 Q，也不包括已算出的完整注意力矩阵。

滑到 $t=3$ 可以检查 C 读取的四个键；$t=4$ 对应下一次输入 D。实验显示的是位置差 $j-t$，不是存储槽号。

## 位置编号：C 的查询为何必须在位置 3？

prefill 已缓存位置 0、1、2 的旋转后 K。C 的 Q/K 必须在位置 3 旋转，才能与整段路径一致。对本例任何旧键 $j\le2$，RoPE 的点积关系给出

$$
\widetilde q_3^\top\widetilde k_j=q_3^\top R(j-3)k_j.
$$

若每次 decode 都把新查询当作位置 0，右边就成了 $q_3^\top R(j)k_j$。例如旧键 A 在 $j=1$：正确未缩放点积是 $\cos(1-3)=\cos2\approx-0.4161$；错误重置得到 $\cos1\approx0.5403$。softmax 仍会给出和为 1 的权重，但它们对应另一个模型计算。

RoPE 的共同平移不变性要求 Q 和所有 K 一起换坐标；只重置新 Q 不满足这个条件。学习式绝对位置的 [P4 Decoder](/principles/decoder/) 同样要给 C 查位置 3 的 embedding，而不是重新查位置 0。

### 已旋转的旧键不能再次旋转

键在位置 $j$ 入缓存时已经是 $R(j)k_j$。若每次读取又乘 $R(j)$，得到 $R(2j)k_j$。例如 A 的旧键原本转 1 弧度，再转一次就成了 2 弧度，C 对 A 的分数也随之改变。

$$
R(j)\underbrace{R(j)k_j}_{\text{已缓存的键}}
=R(2j)k_j\ne R(j)k_j.
$$

数据顺序是：C 投影得到新 Q/K/V，用位置 3 旋转新 Q/K，把新 K/V 接到旧缓存后，再让新 Q 读取四个可见键。D 重复这个过程，位置为 4。旧缓存原样保留；同一请求中途更换 RoPE 频率，也会破坏新 Q 与旧 K 的共同位置规则。

## 分块追加：两行查询怎样读五个键？

除了分别输入 C、D，还可以在同一次调用中把 `[C,D]` 作为长度 2 的块接到长度 3 的缓存。新查询局部行号 $r=0,1$，绝对位置是 $3+r$；键轴同时包含旧位置 0、1、2 和新位置 3、4。每个查询的可见条件是

$$
\operatorname{visible}(r,j)\iff j\le T_{\mathrm{past}}+r,
\qquad T_{\mathrm{past}}=3.
$$

因此两行 mask 为

$$
\begin{array}{c|ccccc}
 &j=0&j=1&j=2&j=3&j=4\\\hline
i=3&1&1&1&1&0\\
i=4&1&1&1&1&1
\end{array}
$$

第一行就是先输入 C 时算过的四项；第二行是输入 D 时的五项。直接对 $2\times5$ 全 1 矩阵做左上对齐的 `tril()`，第一行只会看键 0，第二行只看键 0、1，结果会错。某些注意力 API 接受 `is_causal` 标记，但矩形矩阵的对齐规则需按该 API 具体版本核对；示例显式比较绝对位置。

单 token decode 时，新查询恰在缓存末端；在没有 padding 和预分配空槽的本例，键轴里没有未来键，因而可直接读全部键。若把未来的存储槽也传给算子，仍须明确屏蔽它们。

## 为什么三种切分得到相同结果？

### 一个注意力头：逐项比较 softmax 的输入

以 C 为例：整段、`[3,1,1]` 和 `[3,2]` 三条路径使用相同的 $q_3$、相同的 $k_0,\ldots,k_3$ 与 $v_0,\ldots,v_3$、相同的位置旋转和可见集合。因此每项分数、softmax 分母、权重与输出都相同。D 的五项同理。一般位置 $t$ 可写成

$$
\forall j\le t:\ s^{\mathrm{full}}_{tj}=s^{\mathrm{cache}}_{tj}
\quad\Longrightarrow\quad
\alpha^{\mathrm{full}}_{tj}=\alpha^{\mathrm{cache}}_{tj}
\quad\Longrightarrow\quad y^{\mathrm{full}}_t=y^{\mathrm{cache}}_t.
$$

### 完整 Decoder：沿位置和层数归纳

输入层同一 token 的 embedding 和位置处理相同。因果性先保证前面位置的隐藏状态不受新 token 影响；若第 $\ell$ 层各位置输入与整段计算相同，则该层的新 Q/K/V 相同。按单头结论，所有头的注意力输出相同；确定性的逐 token 归一化、FFN 和残差也相同，于是下一层输入相同。逐层重复，最终每个位置的 **logits** 也相同。这一证明同时要求没有训练态 dropout、参数更新、跨位置归一化或错误的 padding mask。

因此**每层各有自己的 KV cache**，且每层必须覆盖同一个历史前缀。第 1 层与第 2 层的 K/V 由不同隐藏状态和投影权重产生，不能互换。若只缓存第一层，却让第二层遗漏旧前缀，归纳链会在第二层断开。

固定层宽时，朴素重算每次对长度 $t$ 的所有查询和键做约 $t^2$ 次配对；缓存后新 token 只与 $t$ 个键配对。连续生成许多 token 时，这消除了重复处理旧行的工作，但新查询仍必须读取可见 K/V，不能把整段生成的注意力成本说成常数。实际延迟还取决于读写带宽、kernel 和缓存管理。

预分配、分页和请求间共享在 [S5](/systems/paged-cache/) 研究。本章只检查逻辑缓存内容及逐层长度。

## 扩展边界：padding、窗口与物理槽位

### 左侧 padding

缓存存储槽位、序列内逻辑位置和可见性是三个变量。若 `[BOS,A,B]` 左侧补两个 PAD，物理输入槽位是 0–4，但真实 token 的逻辑位置仍是 0–2，C 应处于逻辑位置 3。一种常见逻辑位置构造是

$$
\operatorname{position\_ids}=\operatorname{cumsum}(\operatorname{attention\_mask},-1)-1.
$$

对 `attention_mask=[0,0,1,1,1]`，累计减一得到 `[-1,-1,0,1,2]`。PAD 的负位置要按模型接口填成安全值，它们对应的 K 仍须被注意力 mask 排除。另一个样本可能没有 padding，因此一批请求的有效长度、位置和 mask 要逐样本维护。本章的 `apply_rope` 只支持统一的 `[T]` 位置，不能直接处理这种 `[B,T]` 情况。

### 滑动窗口

设窗口大小为 3，**包含当前 token**。处理完 D（位置 4）后，每层物理缓存可只保留 B、C、D（位置 2、3、4）的 K/V。下一次输入 E 时仍使用逻辑位置 5；先产生 E 的 K/V，再让 E 的查询直接读取 C、D、E（位置 3、4、5），B 已过期。物理槽位及缓存长度都不能充当 RoPE 位置。窗口层的直接注意力候选少于全历史层，因此两种模型的计算规则不同。

“直接读不到 A”不等于“结果中没有 A 的信息”。用两层标量注意力核对：两层的 Q/K 分数都为 0、V 等于该层输入，每个位置输出最近三个位置的均值；不加残差和 FFN。令 `[BOS,A,B,C,D,E]` 的输入为 $[0,9,0,0,0,0]$。第一层在 C（位置 3）读 A、B、C，得到 $h^{(1)}_3=(9+0+0)/3=3$；在 D、E 得到 $h^{(1)}_4=h^{(1)}_5=0$。第二层 E 的查询**直接**只读 C、D、E 的第一层状态，却得到

$$
h^{(2)}_5=(h^{(1)}_3+h^{(1)}_4+h^{(1)}_5)/3=(3+0+0)/3=1.
$$

所以 A 仍沿“A → C 的第一层状态 → E 的第二层输出”间接影响 E。即使旧原始 token 和第一层 K/V 已被驱逐，高层缓存中保留的 C 等状态也可能带着更早的信息。正确的缓存等价性参照是：**从完整前缀按相同位置规则、每层相同滑动窗口 mask 整段重算**。只拿 `[C,D,E]` 三个原始 token 从头计算会让 C 的第一层看不到 A，上例得到 0，不能作为缓存路径的参照。

若实现刻意将共同坐标原点移动 $c$，在固定频率条件下，保留的旧旋转键还必须同步变换：

$$
\widetilde k'_j=R(-c\omega)\widetilde k_j
=R((j-c)\omega)k_j.
$$

这只保持保留下来的 Q/K 配对分数；它不能恢复被丢弃的直接候选。上例的间接历史信息来自驱逐前已经计算的高层输入，不能保证任意久远的信息一直保留。实际模型还可能混用滑动窗口层与全局层，缓存策略需逐层核对。

### 改变 RoPE 频率属于新计算规则

若只把 C 的频率改了，旧 K 仍按原频率旋转，点积不再由同一组相对位置规则给出。要改变频率，需重新计算或按可证明等价的方式转换旧缓存。即使公式能代入更大位置，也不保证模型在那里有可靠预测；位置插值和频率缩放留给 [A4 长上下文](/advanced/long-context/)。

## 常见误区

- “缓存后每步是常数时间”：每个新查询仍读取随历史增长的 K/V；缓存主要避免旧查询和旧层状态的重复计算。
- “输出文本长度必须等于缓存长度”：刚采样出的 token 还没有前向，缓存可以短一项。
- “softmax 权重和为 1 就说明 mask 正确”：错误可见集合仍能归一化；要比较具体 logits 或注意力候选。
- “RoPE 自动处理窗口或 padding”：RoPE 只变换 Q/K；有效位置和可见键由调用方单独定义。

<summary>1. 提示现在只含 `[BOS,A]`，随后一次输入 `[B,C,D]`。写出三个新增查询的逻辑位置和 3×5 causal mask。</summary>

历史长 2，三个查询位于 2、3、4。五个键依次位于 0–4；按 $j\le2+r$，三行是 `[1,1,1,0,0]`、`[1,1,1,1,0]`、`[1,1,1,1,1]`。与正文的 2×5 mask 比，第一行可见键数少一，最后一行相同。

<details>
<summary>2. 一条样本左侧有 2 个 padding，attention_mask 为 [0, 0, 1, 1, 1]。按 cumsum − 1 构造的 position_ids 是什么？</summary>

累加和为 $[0,0,1,2,3]$，减 1 得 $[-1,-1,0,1,2]$。三个真实 token 的位置是 0、1、2，与没有 padding 时一致；两个 padding 位置得到 $-1$，需要按模型接口替换成安全值，并由 mask 屏蔽。下一步解码的新 token 位置应为 3，而不是 5。

</details>

<details>
<summary>3. 窗口大小为 3，处理完 D 后缓存 B、C、D。输入 E 时的位置和直接可见键是什么？只对 `[C,D,E]` 从头重算能否检验缓存等价？</summary>

E 的逻辑位置为 5，不是物理槽位数 3。写入 E 后，窗口层的 E 查询直接看 C、D、E（位置 3、4、5），不再直接看 B。全历史层还能直接看 BOS、A、B，计算规则不同；但两层窗口模型的 C 状态可能已经带入 A 的信息。只从 `[C,D,E]` 重算会丢失 C 当时读取 A 的过程；应使用完整前缀，并在**每层**应用相同窗口 mask，再与逐步缓存的 E 输出比较。

</details>
