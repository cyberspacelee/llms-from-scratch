在 [M7](/math/training/) 中，输入已经是一行实数。语言模型收到的却是字符串，例如“猫 sat”。我们必须先回答三个不同的问题：怎样切成离散单位，怎样给单位编号，怎样把编号变成模型可以求导的实数向量。本章完成这条输入链；下一章才讨论这些向量要预测什么。

先修是 [M3 的矩阵与索引](/math/linear-algebra/) 和 [M7 的参数更新](/math/training/)。分词器可以先于模型训练确定；嵌入矩阵则在模型训练中更新。两者不能混成一个“文本转向量”黑箱。

## 离散单位：字符、字节与子词分别是什么

字符级方案可以把“猫”“ ”“s”“a”“t”分别作为单位，容易理解，但训练时没见过的字符怎么办？词级方案可以把英文单词作为单位，但新词、大小写、标点和中文词边界会迅速扩大词表。子词方案折中：常见片段合并成长单位，罕见片段继续拆小。

token 是分词器实际输出的离散单位；它可能是词、词片段、标点、空白，甚至是不完整的字符字节。不能把一个 token 固定翻译成“一个字”或“一个词”。同一句话在不同分词器下，token 数可以不同，后续序列长度、缓存容量和每 token 损失也随之不同。

Unicode 码点与 UTF-8 字节也不同。“猫”的码点是 U+732B，而 UTF-8 编码是三个字节 `E7 8C AB`。字符串里的一个视觉字符还可能由多个码点组成，比如字母与组合重音；字符级究竟按码点还是按字素簇切分，需要另行定义。本章教学分词器直接从 UTF-8 字节开始，每个初始 token 表示一个 0–255 的字节值。

因此，只要输入是可正常编码为 UTF-8 的字符串，它总能退回到初始字节，不需要额外的未知 token。这个性质来自覆盖全部 256 个字节，不能推广为所有分词器都没有未知项。

沿箭头读时，每一步都有自己的规则。前三步通常不参与神经网络反向传播；最后一步的矩阵是可训练参数。

## 词表与 ID：编号不携带大小关系

令词表大小为 $n_{\mathrm{vocab}}$。词表规定每个 token 对应唯一 ID，通常在 $0$ 到 $n_{\mathrm{vocab}}-1$ 之间。分词器的 `encode` 输出 ID 列表，`decode` 根据同一词表还原字节或字符串。

ID 17 不意味着某个词比 ID 8 更大，也不表示语义距离是 9。ID 只是地址。若同时重排词表和嵌入矩阵行，模型收到的向量可以完全不变；若只换分词器却保留权重行，含义就错位了。

实际模型的输入契约因此包含分词器文件、合并规则、特殊 token、词表大小、模型嵌入与输出层。下载权重时，仅知道网络层数与隐藏维度还不足以正确处理文本。词表索引超出嵌入矩阵行数是显式错误；索引落在范围内但语义错位更难发现。

## BPE：从计数到确定的合并规则

字节对编码（byte-pair encoding，BPE）的训练反复选择相邻的高频 token 对，将它加入词表，并在训练序列中替换该对。这里的“对”不是原始字符对：第一次合并后，新 token 也可以参加下一次合并。

采用小语料：`aba` 出现 4 次，`abb` 出现 2 次，`bab` 出现 1 次。每条文档独立计数，不跨文档边界合并。初始字节 ID 为 `a=97,b=98`。相邻对计数如下：

| 相邻对 | 来自 aba | 来自 abb | 来自 bab | 总次数 |
| --- | --- | --- | --- | --- |
| a,b | 4 | 2 | 1 | 7 |
| b,a | 4 | 0 | 1 | 5 |
| b,b | 0 | 2 | 0 | 2 |

先合并 `a,b`，新 ID 256 表示字节串 `ab`。各序列变成 `[ab,a]`、`[ab,b]`、`[b,ab]`。重新计数后，`[ab,a]` 出现 4 次，成为下一次合并，新 ID 257 表示 `aba`。训练两次后，词表大小是 258，不能用语料里“只有 a 和 b”推断词表只有 4 项：所有基础字节仍保留。

交互图中的步骤改变的是离散切分，token 的覆盖字节串不变。恢复训练前的切分并不会删除原文本；合并规则是在改变表示粒度。

### 重叠与并列计数需要明确规则

`aaa` 的相邻 `aa` 有两个重叠出现，但一次替换不能同时消耗中间的 a。教学代码从左向右做非重叠替换，因此结果是 `[aa,a]`。计数与替换不是同一个操作。频次相同的对也必须有固定排序，否则两次训练可能产生不同词表。代码按 ID 对的字典序打破并列。

这套实现用每轮重新计数，便于核对逻辑；其运行成本随语料长度与合并次数增长，不承担生产分词器的高吞吐训练任务。完整工程分词器可采用维护受影响相邻对的索引等优化，这不改变这里的合并定义。

### 编码为什么不能随便选最长片段

分词器训练完成后，面对新文本，先转成基础字节，再按照**训练得到的合并优先级**应用规则。即使词表里存在某个长片段，也不能擅自改用另一套最长匹配算法。编码算法与合并规则共同决定结果。

在本例中，`aba` 编码为 `[257]`，`abb` 为 `[256,98]`，`bab` 为 `[98,256]`。这些结果都来自先合并 `ab`、再合并 `aba` 的顺序。分词规则确定后，模型训练不会每一步重新统计并改变这个规则。

## 解码边界：先连接字节，再解释字符

一个 token 的字节串未必单独构成完整 UTF-8 字符。例如初始 ID 231 表示 `E7`，它可能是“猫”的第一个字节，却不能单独按严格 UTF-8 解码。本章 `decode` 先连接全部 token 的字节，再一次性解码。因此对完整有效文本有 `decode(encode(text)) == text`，不保证每个单独 token 都能展示为正常字符。

生产分词器还常包含文本规范化、预分词与特殊标记识别。规范化可能将两种写法映射为同一种，因此往返结果不一定逐字节等于原文。预分词可能禁止跨某些边界合并。本章实现不做这两步，不能将其切分结果冒充某个实际模型的 tokenizer。

特殊 token 用于开始、结束、填充或角色边界，其 ID 必须与普通词表项明确区分。`BOS` 和 `EOS` 分别常表示开始与结束，但是否自动添加、对话模板是否使用它们，都取决于模型契约。用户文本中的字面字符串 `<EOS>` 也不应未经规则说明就被当作控制标记；安全的编码接口通常显式控制特殊项处理。

### 特殊标记与保存：控制 token 必须显式启用

配套类可声明 `PreSplitBPE(["<bos>", "<eos>"])`。拟合时不让合并跨这些已声明边界；普通 `encode(text)` 仍把字面标记当作文本，只有 `encode(text, allowed_special=True)` 才将它们识别为控制 ID。例如正文中用户写 `<eos>`，默认不会结束序列。这种 opt-in 规则与训练程序直接添加 BOS/EOS ID 的做法一致。

普通词表含 256 个字节与按顺序新增的合并项，特殊 ID 从普通词表末尾开始，因此只能在拟合完成后冻结并建立模型。改变合并次数可能改变特殊 ID；同一个 checkpoint 必须使用保存的完整状态，不能只重新计算一个“看起来一样”的词表大小。

`save(path)` 写 JSON，记录格式版本、算法类别、特殊项和合并顺序；`ByteBPE.load(path)` 重建普通片段并检查合并只能引用此前已有 ID。重复合并和越界引用被拒绝。状态不包含 Python 对象序列化，训练、恢复与生成可以使用同一份映射；[T3](/training/pretraining/) 同时把它保存进 checkpoint 并另写 JSON 文件。

## 生产分词器：预分词与两类训练算法

本章的字节 BPE 直接在整段 UTF-8 上合并。常见的生产分词器在它前后各加了几步，读模型的 tokenizer 文件时需要认出它们。

**预分词**先用规则把文本切成块，合并只在块内进行。GPT-2 及其后继（包括 tiktoken 实现的编码）用正则表达式把字母串、数字串、标点和空白分开，并让单词带上前导空格。为什么需要这一步？因为 BPE 只看频次：语料里“a b”出现得多，不加限制就会合成一个跨越单词边界的 token，相同的单词随上下文被切成不同的片段。脚本用五条“a b”核对：不预分词时第二次合并得到字节串 `a b`；按简化正则预分词后，块是 `a` 与 ` b`，合并结果中空格只可能出现在 token 开头。

**SentencePiece** 不预先按空格切词，而是把空格替换成可见符号 ▁（U+2581）后当作普通字符处理，这让它对不以空格分词的语言更一致。它支持 BPE，也支持 Unigram 语言模型：Unigram 从一个大词表出发，按删除后似然下降最少的原则逐步删减；编码时不按合并顺序，而是用动态规划选择总概率最大的切分。同一段文本在 BPE 与 Unigram 下可能得到不同的 token 序列，训练和推理必须使用同一个模型文件。SentencePiece 的字节回退（byte fallback）选项让未登录字符退回 UTF-8 字节 token，效果上与本章从字节出发的覆盖性质相同。

公开模型在这些选择上各不相同：Llama 2 使用 32000 项的 SentencePiece BPE，Llama 3 改用基于 tiktoken 的 128256 项词表。词表更大，同一段文本的 token 通常更少，但嵌入与 LM head 的参数随之增加；[S1](/systems/ledger/) 的账本里，Llama 3 8B 的两块词表矩阵约有 10.5 亿参数。换分词器意味着换掉整个输入输出契约，不是一个可以单独升级的预处理步骤。

## 嵌入矩阵：整数索引怎样变成向量

设嵌入矩阵 $E\in\mathbb R^{n_{\mathrm{vocab}}\times d}$，每一行是某个 token 的可训练向量。单个 ID 为 $u$ 时，输出列向量 $x=E_{u,:}^\top\in\mathbb R^d$。批输入 ID 张量的形状是 $(B,T)$，选行后变成 $(B,T,d)$。

为手算方便，以下改用一个独立的小词表，$n_{\mathrm{vocab}}=8,d=4$；它不是前面 258 项的字节词表。若第 1 行是 $(0.2,-0.1,0.5,0.3)$，输入 ID 1 就取出这一整行。输入 ID 1、2、1 时，第 1 行会出现两次，但两处引用的是同一参数。

令独热列向量 $e_u\in\mathbb R^{n_{\mathrm{vocab}}}$ 的第 $u$ 个元素为 1，其余为 0，则：

$$
x=E^\top e_u.
$$

按行堆叠独热输入 $O\in\mathbb R^{BT\times n_{\mathrm{vocab}}}$，得到 $X=OE$。这个等式帮助理解查表与矩阵运算的关系；实际实现通常直接索引，不构造占用 $BTn_{\mathrm{vocab}}$ 个元素的独热矩阵。

查表也有反向传播。若第 $i$ 个位置对嵌入输出的梯度为 $g_i\in\mathbb R^d$，则所有使用同一 ID 的位置贡献相加：

$$
\frac{\partial L}{\partial E_{u,:}}=\sum_{i:\,\mathrm{id}_i=u}g_i^\top.
$$

这正是 [M6 共享节点梯度相加](/math/backprop/) 的实例。ID 是离散索引，不对 ID 求导；被选中的参数行才接收梯度。没出现的行在这个查表操作上没有梯度贡献，但其他共享用途仍可能贡献，例如后文的输出权重绑定。

代码取 ID `[[1,2,1],[3,1,0]]`，对所有嵌入元素求和。每次出现都贡献四个 1，因此第 1 行梯度为四个 3；第 0、2、3 行分别为四个 1，其他行为零。

## 从输入契约到模型成本

仅嵌入矩阵就有 $n_{\mathrm{vocab}}d$ 个参数。较长 token 往往减少序列长度，却可能扩大词表；较小词表可能拉长序列。后续注意力、缓存与词表输出成本受不同因素控制，不能只凭“token 更少”断言所有计算都更便宜。

输入查表不等于每个位置完整计算 $OE$ 的密集矩阵乘法。实际读出若干行，而输出 LM head 通常对全部词表计算分数。这个区别会在 [S1](/systems/ledger/) 的计算账本中变得重要。

目前得到的是向量序列，而不是语义正确的模型。随机初始化嵌入没有天然词义；它需要在预测目标下学习。下一章将使用同一 ID 体系，把每个位置连接到其后一个 token 的类别标签。

## 常见误区

- 把 token 数当字符数。英文、中文、空白和不同分词规则都可能使这个比例改变。
- 对 ID 直接乘学习矩阵，把编号大小当连续特征。应先选取嵌入行。
- 一边训练网络一边随意改词表。既有参数行和输出类别都因此改义。
- 对单个字节 token 强制解码并据此判断分词器损坏。需要检查完整字节序列。
- 把教学字节 BPE 当成生产 tokenizer 的全部处理流程。规范化、预分词和特殊标记都属于契约。

## 练习与核对

<details>
<summary>语料只包含 a 和 b，为什么教学词表仍从 256 项开始？</summary>

基础项覆盖所有字节。语料频次决定增加哪些合并项，不删除基础覆盖。两次合并后是 258 项；若采用字符级 BPE，基础词表定义才会不同。

</details>

<details>
<summary>输入 ID 是 [2,2,5]，每个输出向量梯度都是 (1,3)，嵌入梯度是多少？</summary>

第 2 行累加两次，得到 $(2,6)$；第 5 行得到 $(1,3)$。其他行在此操作上为零。这里对同一参数相加，不对重复位置求平均；损失的平均因子应已包含在上游梯度里。

</details>

<details>
<summary>同时交换词表 ID 2 与 5，要怎样保持模型输出对应的文本含义？</summary>

不仅要交换输入嵌入对应行，也要交换输出词表分数对应行及偏置，并更新特殊 ID 与相关配置。只换输入行不足以保持输出类别契约。

</details>
