[P11 完整 Decoder](/principles/complete-transformer/) 已能把一段 token 变成下一 token 的分数，也能对一个教学样本更新参数。但拿到一批原始文档时，仍不能直接宣布“模型学会了”：重复文档可能同时进入训练和验证；padding 可能混入损失分母；中断恢复可能丢掉优化器的历史。训练路线围绕一件事展开：**从可追溯的文档出发，得到定义清楚、能够恢复和独立评估的模型更新。**

## 阅读路线：先完成一次可信的更新

<ChapterList track="training" />

[T1 数据与样本构造](/training/data/) 先确定文档身份、训练与验证的边界，再把文本编码成移位的 input/target。它同时区分注意力 mask、损失 mask 与 padding：哪些位置可以读取，哪些目标计入损失，是两件不同的事。[T2 优化与训练稳定性](/training/optimization/) 接着以**有效目标数**为分母，把不同长度的微批合成一次更新，逐步算清梯度、AdamW 状态和 checkpoint 需要保存的历史。[T3 从零训练](/training/pretraining/) 将两者接入真实循环：训练、验证、写盘、中断、恢复，并比较恢复与连续运行的轨迹。

更新能复现，还不能说明模型有用。[T4 模型评估与受控实验](/training/evaluation/) 固定 tokenizer、文档来源、上下文窗口和评分协议，再比较有效 token 的 NLL、任务结果及其不确定性。它回答“观察到的改善支持什么结论”，也为后续实验提供共同的测量边界。有现成 checkpoint 的读者可从 T4 开始，不必先完成 T3 的训练。

[T5 指令微调](/training/instruction-tuning/) 保留下一 token 目标，但通过 chat template 和回复位置的 loss mask 规定模型学习哪段对话；章末再把同一批位置用于蒸馏。[T6 LoRA](/training/lora/) 保留这套监督目标，冻结基座，只训练低秩 adapter。读完 T4 后，按需求进入适配分支即可。

## 放大条件：预算、原料与多个进程

[T7 缩放规律与计算预算](/training/scaling-laws/) 问固定训练计算量该分给参数还是有效目标；先在同一评估协议下拟合经验关系，再说明其外推边界。[T8 预训练数据工程](/training/data-engineering/) 从原始网页追踪提取、过滤、近重复分组与来源混合，把 T1 的“文档身份”落实到原料处理。[T9 分布式训练与状态分片](/training/distributed-training/) 则检查两个进程处理不同数量的有效目标时，怎样仍执行同一次全局更新，以及训练状态如何占用和释放内存。这三章都从 T1–T4 的闭环出发，可以按问题选读；T9 不以 LoRA 为先修。

阅读顺序与执行顺序有所不同：课程先用少量干净文档在 T1–T4 建立可核对的闭环，才拆开讲大规模数据处理。实际启动预训练项目时，必须先完成 T8 所讨论的来源审查、清理和重复组划分，**再**定训练/验证边界、拟合 tokenizer、构造样本和更新模型；不能在看过验证结果后才回头清理数据并沿用原分数。扩大模型或改成多进程时，也要沿用同一有效目标定义和评估协议，才能判断变化来自哪里。

## 从哪里开始

已学过 [P1 token 与 tokenizer](/principles/tokenization/)、[P2 下一 token 预测](/principles/language-modeling/) 和 [P4 Decoder](/principles/decoder/) 的读者，可从 T1 顺序读到 T4；T3 的现代文本实验还会用到 P11。T2 的推导依赖 [M6 反向传播](/math/backprop/) 和 [M7 神经网络训练](/math/training/)；PyTorch 的梯度和训练状态接口可回读 [F4](/frameworks/autograd/) 与 [F6](/frameworks/data-and-training/)。

每章都先固定自己的数据、目标和比较边界，再给出手算与可运行核对；数值结果只在该章声明的条件下成立。准备训练真实文本时，先沿 T8 处理原料，再用 T1–T4 的协议记录数据版本、更新状态和评估结果。
