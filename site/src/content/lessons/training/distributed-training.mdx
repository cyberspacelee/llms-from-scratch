[T2](/training/optimization/) 已经说明：把有效目标拆成微批时，每个目标仍应在一次更新中占相同权重。现在把同一批目标交给两个进程。rank 0 处理 5 个，rank 1 处理 9 个；如果两个进程各算平均损失，再平均它们的梯度，5 个目标和 9 个目标就各占一半。参数可以保持同步，训练目标却已经改变。

本章沿用一组十四个目标，从单进程参考更新出发，逐步得到 DDP 同步与累积规则，再看复制和分片各占多少状态。只需知道 [M9 反向传播](/math/backprop/) 的梯度相加和 [T2](/training/optimization/) 的有效目标分母；[S9 集合通信](/systems/cluster/) 可在理解公式后回读。

## 单进程参考：十四个目标定义哪一次更新

用一个参数 $\theta$ 隔离模型结构。每个目标值 $y$ 的损失为 $\ell(\theta;y)=\frac12(\theta-y)^2$，在 $\theta_0=0$ 开始，以学习率 $\eta=0.1$ 做一次 SGD。这里的平方损失代替语言模型的逐 token NLL；**分片、计数和归约规则相同**，但损失的数值不是某个语言模型的 NLL。

| 进程 | 微批 1 | 微批 2 | 每个目标的 $y$ | $\theta_0$ 处每目标损失 / 梯度 |
| --- | ---: | ---: | ---: | ---: |
| rank 0 | 3 个 | 2 个 | 1 | $0.5$ / $-1$ |
| rank 1 | 5 个 | 4 个 | 3 | $4.5$ / $-3$ |

一个 rank 是参与训练的一个进程身份，world size $R=2$ 是本次协作的进程数。表中每个微批都是一组**有效目标**；如果有 padding 或被 loss mask 取消的位置，它们不在计数里。总有效目标数 $N=3+2+5+4=14$，这一步的全局目标只有一个：

<KeyEq label="一次更新的全局目标">
$$
L(\theta)=\frac1N\sum_{r=0}^{R-1}\sum_m\sum_{i\in(r,m)}\ell_i(\theta),
\qquad
g=\nabla_\theta L(\theta_0)=\frac1N\sum_{r,m,i}\nabla_\theta\ell_i(\theta_0).
$$
</KeyEq>

本例 rank 0 的损失和为 $5(0.5)=2.5$，梯度和为 $5(-1)=-5$；rank 1 分别为 $9(4.5)=40.5$、$9(-3)=-27$。所以 $L(\theta_0)=43/14\approx3.0714$，$g=-32/14\approx-2.2857$，更新后 $\theta_1=0-0.1g=3.2/14\approx0.2286$。这些是后面多进程结果必须匹配的三个数。

### 错误的分母怎样改变参数

两个 rank 各自的平均损失是 $0.5$ 和 $4.5$。直接平均会报告 $2.5$；各自平均梯度 $-1$ 和 $-3$ 再平均得到 $-2$，更新为 $\theta_1=0.2$。这相当于 rank 0 每个目标占 $1/10$，rank 1 每个目标占 $1/18$，而参考目标中每个目标都占 $1/14$。只修正报告用的损失、仍让错误损失参与 <code>backward()</code>，参数照样会走向 $0.2$。

## DDP：从局部梯度恢复全局梯度

DDP（DistributedDataParallel）在每个 rank 保留一份模型，分别做前向和反向，再同步对应参数的梯度。普通 DDP 的同步结果是各 rank 梯度的**平均**。每个 rank 并不天然知道全局分母：先统计自己本次更新的有效目标数 $n_r$，用计数 <code>all_reduce(SUM)</code> 得到 $N=\sum_rn_r$，再计算带梯度的损失。

令 $S_{r,m}$ 是 rank $r$、微批 $m$ 的逐目标损失**和**。因为 DDP 最后除以进程数 $R$，每次本地反向应使用 $\widetilde L_{r,m}=R S_{r,m}/N$。同一参数在所有微批反向并同步后，其梯度为

$$
\frac1R\sum_r\sum_m\nabla_\theta\widetilde L_{r,m}
=\frac1R\sum_r\sum_m\frac{R}{N}\sum_{i\in(r,m)}\nabla_\theta\ell_i
=\frac1N\sum_{r,m,i}\nabla_\theta\ell_i=g.
$$

如果 loss API 已经给出微批均值 $\bar L_{r,m}=S_{r,m}/n_{r,m}$，就反向 $\bar L_{r,m}\,R n_{r,m}/N$。若 API 给的是 sum，则只乘 $R/N$。不要在这一步再除以微批数，也不要补偿两次 $R$。

<Figure src="training/weighted-ddp.svg" alt="两个 rank 的四个微批先按目标数得到损失和与梯度和，DDP 平均缩放后的梯度，结果等于十四个目标的单进程平均">按箭头读取每个微批的梯度和：$-3,-2,-15,-12$。先各乘 $2/14$，再由 DDP 除以 2，恰好得到 $-32/14$；损失报告则直接用 $43/14$。</Figure>

图中只有一个参数，因此“梯度”是一个数。实际模型对每个参数张量逐元素遵循同一线性归约。这个等价性要求每个目标的前向损失在单进程与分布式组织下相同；使用跨样本 BatchNorm 或不同随机 dropout 轨迹时，改分母仍不能保证逐位相同。自定义通信 hook 若改变默认平均语义，也必须重新推系数。

## 梯度累积：四个微批只更新一次

本例每个 rank 有两个微批。两个进程都先清梯度一次：rank 0 依次反向 3 个和 2 个目标，rank 1 依次反向 5 个和 4 个目标；最后各执行一次 <code>optimizer.step()</code>。第一微批可放在 <code>model.no_sync()</code> 中，暂不做梯度通信；第二微批正常反向，DDP 同步此前累积的梯度。<code>no_sync()</code> 要同时包住对应的前向和反向，因为 DDP 会在前向设置同步状态。

对应脚本将每个微批的损失先 <code>sum()</code>，乘 $2/14$ 后反向。rank 0 本地贡献为 $(-3-2)\times2/14=-10/14$，rank 1 为 $(-15-12)\times2/14=-54/14$；同步平均为 $(-10/14-54/14)/2=-32/14$。这一步说明了为什么**一次更新的分母**要覆盖全部 rank 和微批。若后续微批的有效数尚未知，可以先累积未平均的损失梯度，等 $N$ 已知后统一缩放，并按所用 DDP 同步时机重新设计通信；不能把当前均值直接除以“预计的微批个数”。

梯度裁剪也要等所有贡献同步完成后再做。比如两侧局部平均梯度是 $-1$ 和 $-3$，先分别按绝对值上限 2 裁剪，再等权平均得到 $-1.5$；正确做法是先合成全局梯度 $-32/14$，再裁剪到 $-2$。[T2](/training/optimization/) 的 AMP unscale 和非有限检查同样应在一致的更新边界进行。

## 两个进程怎样按相同时序运行

两个 Python 进程各自构造一个初值为零的参数；DDP 负责使初始参数和之后的梯度保持一致，它们不是同一个内存对象。CPU 示例使用 Gloo 进程组和临时文件 rendezvous，不要求 GPU。一张 GPU 对应一个 rank 是常见部署方式，并不是 rank 的数学定义。

进程组调用有共同顺序：每个 rank 先参加计数归约，再走各自的第一个 <code>no_sync()</code> 微批和第二个同步微批，最后更新参数。少一个 rank 参加 collective，其他进程可能等待或超时。脚本对进程组设超时，并在退出时销毁进程组；两个 rank 更新后还互相核对参数。

### 分片数据时，还需核对哪些事件

数据并行要求不同 rank 处理不同数据片。本例十四个事件的编号互不重复，只是 rank 0 的五个目标值都为 1、rank 1 的九个目标值都为 3。真实文本数据应按文档 ID、epoch 和 shuffle seed 建立明确的采样计划，再记录每个 rank 的游标。[T1](/training/data/) 的文档边界和 loss mask 决定哪些 token 算有效目标，不能用输入长度代替 $n_r$。

为了让 rank 的迭代次数相同，sampler 可能重复尾部样本；若训练目标包含这些重复事件，它们要按实际次数计数。评估去重则是另一问题。一个 rank 提前耗尽数据时，本章这种两个微批同速的代码不再适用；应让所有 rank 进入共同更新计划，或使用明确支持不均匀输入的 join 协议。有效目标数为零的一次全局更新不能做除法，应跳过更新并让所有 rank 作同一决定。

## 状态分片：同一次更新需要存什么

DDP 让每个 rank 都有完整参数、梯度和优化器状态；增加 rank 会分摊样本计算，却不会自动降低单卡上这三项的常驻内存。状态分片改变的是**每个进程持有哪些字节**，不是前面定义的全局目标。以 $N_p$ 个参数、$R$ 个 rank 和一种明确的混合精度布局为例：低精度参数 2 字节、梯度 2 字节、float32 主参数及 Adam 的一阶矩和二阶原始矩共 12 字节，每参数合计 16 字节。

| 布局 | 每 rank 常驻状态的示意字节数 | 更新时的主要额外动作 |
| --- | --- | --- |
| DDP：全复制 | $16N_p$ | 归约梯度，各 rank 更新完整参数 |
| ZeRO-1：分片优化器状态 | $4N_p+12N_p/R$ | 各 rank 更新负责的参数段，再同步参数 |
| ZeRO-2：再分片梯度 | $2N_p+14N_p/R$ | 梯度 reduce-scatter 到负责的 rank |
| ZeRO-3 / 全分片 FSDP：再分片参数 | $16N_p/R$ | 计算层前 gather 所需参数，反向后分散梯度 |

这些式子是给定精度布局的**常驻模型状态账**。例如十亿参数、四个 rank 时，依次约为 16、7、5.5、4 GB，按十进制 GB 计算；都没有算激活、通信缓冲或临时完整参数。实际框架可能使用不同梯度精度、无 fp32 主参数、参数扁平化或 CPU offload，应按实现重新列账。

为什么分片还可以执行同一次更新？单进程参考有一个完整的 $g$；DDP 让每个 rank 都拿到 $g$。若把参数按坐标切成 $R$ 段，reduce-scatter 可以让每段的拥有者只拿到该段的全局梯度，并更新该段优化器状态，随后按需要 all-gather 参数。每个坐标仍由其正确的 $g$ 更新一次。这里的坐标分片与前面的**样本分片**是两个不同维度；[S9](/systems/cluster/) 进一步推导 collective 及通信量。

状态布局实验固定十亿参数和上表每参数 16 字节的假设。先设为四个 rank，核对 DDP、ZeRO-1、ZeRO-2、ZeRO-3 的每 rank 常驻账依次为 `16、7、5.5、4 GB`。

柱形只计常驻模型状态。激活与临时 gather 不在柱中，不能用这里的每 rank 读数直接判断显存峰值。

### 常驻四分之一，峰值为何未必四分之一

全分片在某层计算前需要临时 all-gather 该层的完整参数；反向可能再次 gather。激活、预取层、通信 bucket 和算子工作区也可能同时存在。若一层有一亿个低精度参数，完整计算视图约 0.2 GB，四卡均分常驻切片约 0.05 GB；是否额外同时占用 0.2 GB，取决于缓冲复用和预取时序。仅凭上表的 4 GB，不能断定一张 4 GB 卡能训练十亿参数模型。

激活 checkpoint 通过反向时重算来少保存前向中间值，状态分片通过通信减少常驻模型状态；两者作用于不同内存项，可以组合。显存容量判断要在目标硬件上记录实际峰值、模型状态、激活与临时分配；CPU DDP 脚本不提供 FSDP 显存证据。张量并行把一层矩阵切开，流水线并行把层分开，还会改变通信和微批排程，[S9](/systems/cluster/) 另行讨论。

## checkpoint：恢复的也是同一次全局更新吗

单进程的 [T5 checkpoint](/training/checkpoint/) 已经保存模型、优化器、RNG 和数据游标。多进程还需要知道各 rank 的数据顺序与游标、随机状态、world size、分片配置及已完成的全局更新数。只有 rank 0 的模型参数相同，不保证其他 rank 恢复后取到同样的目标。保存点若落在两个微批之间，还需保存未完成梯度与累计有效目标数；选择完整 <code>optimizer.step()</code> 后作为保存边界更容易核对。

FSDP 保存时需声明是完整 state dict 还是分片 state dict，以及加载时怎样重分片。临时聚合完整权重可能提高保存峰值；分片格式需要匹配对应 API。这里的脚本只验证一步 DDP，并未演示故障恢复或 FSDP checkpoint，所以实际训练应对一次中断后的**下一步损失和参数**再做独立核对。

## 常见误区

- rank、微批或输入 token 数不是默认分母；本章分母是全部有效目标数 14。
- 参数在各 rank 一致，只说明通信与更新一致，不证明平均损失的权重正确。
- 对损失求和后又除本地目标数，再乘 $R/N$，会把目标多除一次。
- 只在 <code>backward()</code> 外层使用 <code>no_sync()</code>，或在两个微批间清梯度，都会改变同步或累积结果。
- 用状态分片的常驻字节数推断显存峰值，会漏掉完整层、激活和通信缓冲。

## 练习与核对

<details>
<summary>仍用两个 rank 的目标值 1 和 3，但微批数变成 rank 0 的 1+2、rank 1 的 2+3。全局损失、梯度和学习率 0.1 的一步结果是什么？</summary>

总目标数 $N=8$。在 $\theta_0=0$，损失和为 $3(0.5)+5(4.5)=24$，所以 $L=3$；梯度和为 $3(-1)+5(-3)=-18$，所以 $g=-18/8=-2.25$，更新到 $\theta_1=0.225$。局部 sum 仍乘 $R/N=2/8$ 后反向，由 DDP 再平均。

</details>

<details>
<summary>若误把原例四个微批的均值等权平均，能否通过检查两个 rank 更新后参数相同发现错误？</summary>

不能。两个进程仍可能同步到相同的错误梯度并作相同更新。应与按十四个有效目标直接求平均的单进程参考比较；尤其要比梯度与更新后参数，而不只是日志损失。

</details>

<details>
<summary>四卡全分片后某模型常驻状态从 16 GB 降到约 4 GB，可否放进 4 GB 显存？</summary>

不能据此判定。4 GB 只计了假设布局的常驻模型状态；计算时还会出现完整层参数、激活、通信缓冲和临时工作区。要测实际峰值，并给框架和硬件留出余量。

</details>
