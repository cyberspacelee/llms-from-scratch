## 数据：先确定八篇文档的身份

训练集包含六篇自编短文，围绕cat、dog、bird、rain、child、sun。验证集另有两篇重新组合的句子。例如训练文档包含 `the cat sits by the window. the cat watches the rain.`，验证文档包含 `the cat rests by the door. the cat watches the garden.`。

它们足够小，便于在CPU上检查数据流；词汇高度重叠，不适合证明自然语言能力。运行时拒绝完全相同的文档跨集合出现。真实数据还需先按 [数据工程](/training/data-engineering/) 处理来源和近重复组，精确字符串不相等并不证明没有泄漏。

## Tokenizer：拟合完成后冻结规则

沿 [token与embedding](/principles/tokenization/) 的byte-BPE实现，先在训练集拟合16次merge，再把BOS、EOS加入特殊项。原始字节始终能编码；验证集不参与merge选择，不会改变词表的行身份。

每篇文档变为 `[BOS,...文本ID,EOS]`。假设一篇得到51项，取上下文24，窗口分别从0、24、48开始，长度最多25；每窗前24项作输入、后一项移位作目标。相邻窗共享一个边界token，目标下标1到50各计一次，没有跨文档预测。

这些窗口独立前向，因此第二窗不会看到第一窗全部历史。计分目标虽各一次，条件历史已改变；与更长上下文比较时必须重新声明评分协议，不能沿用原NLL。

## 模型：使用原理路线的同一实现

统一包中的 `Transformer` 接收 `ModelConfig`。本实验选两层、残差宽D=24、FFN宽48、四个Q头、两个KV头、每头宽8、最大长度64；使用Pre-RMSNorm、RoPE、GQA、SwiGLU与绑定词表权重。Q总宽为32，输出投影映回24，不要求D等于Q头总宽。

`model(input_ids)` 返回 `ModelOutput`，其中 `.logits` 的shape为 `(B,T,V)`。这里固定CPU、float64；模型配置和tokenizer工件随后一起保存，生成不会重新建立另一个Decoder。

## 更新：数据状态决定下一次读哪个窗口

每轮从保存的排列和游标取一个窗口，随机去掉至多两个前缀项作为后缀增广。Torch RNG负责排列，Python RNG负责增广。这样随机状态确实影响训练，而不是只为了演示checkpoint才存在。

输入 `document[:,:-1]`，目标 `document[:,1:]`，每个目标均有效。对统一包的有效目标损失求导，将合成梯度范数裁到1，再执行一次AdamW更新。更新后步数加一，日志记录loss与裁剪前范数。

只有loss.backward负责梯度，optimizer.step负责更新。若扩展成padding或assistant-only数据，应先得到loss_sum与valid_count；局部零目标贡献不授权整步更新。T2中的全局目标协议必须仍成立。

## 验证：固定文档与分母

验证阶段使用eval和no_grad，不做随机增广，也不更新参数。每个窗口直接产生loss_sum与valid_count，分别求和，再除以总有效目标数。这样短尾窗不会获得与完整窗相同的权重。

## 运行：训练、继续与生成

在仓库根运行：

```sh
uv run python -m examples.training.text_pretraining --checkpoint runs/prose.pt --steps 80
uv run python -m examples.training.text_pretraining --checkpoint runs/prose.pt --resume --steps 20
uv run python -m examples.training.text_pretraining --checkpoint runs/prose.pt --generate-only --prompt "the cat" --max-new-tokens 16
```

steps表示本次额外更新次数，两次训练后全局步数为100。新运行要求checkpoint路径尚不存在；继续时使用文件内冻结的文本、tokenizer和配置。它不会悄悄用新的词表解释旧权重。恢复状态和原子写盘的检查在 [精确恢复](/training/checkpoint/) 中完成。

可用 `--train-text train.txt --validation-text valid.txt` 开始新实验；两份UTF-8文件每个非空行是一篇文档。先声明数据版本和分组，再运行，不在看过验证结果之后换数据并沿用旧分数。

生成前给prompt加BOS，一次prefill后逐token使用同一模型的cache；遇EOS或新token预算停止。未训练充分的字节模型可能生成非法UTF-8，显示用替换字符；这不放宽tokenizer对原始文本的严格往返契约。

## 自检与变式

不带参数运行 `uv run python -m examples.training.text_pretraining`。程序使用临时文件，核对tokenizer工件、验证分母、载入前向和恢复后的八次更新；这些是运行链路的验收，不是语言质量基准。

<details>
<summary>验证尾窗只有2个目标，完整窗有24个，直接平均两个窗口NLL会改变什么？</summary>

直接平均给尾窗每个目标12倍权重。token等权的均值是 `(24L_full+2L_tail)/26`，不是 `(L_full+L_tail)/2`。

</details>

<details>
<summary>把验证文本也用于BPE拟合，模型参数未看过其标签，是否仍算完全独立验证？</summary>

不算。验证文本改变了预处理工件与词表分配，已参与实验设计。应只用训练文本拟合，或把这一额外数据来源作为新协议声明并用新独立集合评估。

</details>
