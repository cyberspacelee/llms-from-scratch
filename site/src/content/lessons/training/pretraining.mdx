下一 token 损失和 Decoder 接上训练循环后，还要检查验证阶段是否记录梯度、checkpoint 是否包含 AdamW 的矩状态、恢复后是否读取同一批数据、生成时是否使用原词表。这些状态决定中断前后的实验能否对齐。

先修是 [T1 数据](/training/data/)、[T2 优化](/training/optimization/) 与 [P4 Decoder](/principles/decoder/)。生成和缓存分别参见 [P9](/principles/generation/)、[P10](/principles/kv-cache/)。本章使用同一个 `Decoder` 和 `sequence_loss`，完整脚本在 CPU 上训练、评估、生成并验证恢复轨迹，不下载 checkpoint。我们先把一个可审计的小实验做完整，再讨论怎样扩大规模。

本章有两个互补实验。下面的四 ID 实验用于手算与精确 FLOP 计数；后面的文本实验使用 [P11 完整现代 Transformer](/principles/complete-transformer/) 与真实 UTF-8/BPE 输入，支持磁盘 checkpoint 和命令行恢复。它们使用不同配置，各自保存自己的 tokenizer，不互相加载权重。

## 固定实验：配置、语料和结论边界

词表只有四个 ID：`a=0,b=1,c=2,EOS=3`。训练文档是三个从不同字母开始的循环片段，每篇有十一个字符和一个 EOS。验证文档长度不同，没有与训练文档完全相同，但共享刻意设计的 `abc` 规律。它检验模型能否在同一合成规则下预测新长度，不代表自然语言的开放领域泛化。

| 项目 | 固定值 | 为什么需要记录 |
| --- | --- | --- |
| 隐藏维度 $d$ | 16 | 决定表示宽度与参数量 |
| 查询头数 $n_q$ | 2 | 头维度 $d_h=8$ |
| 前馈维度 $d_{\mathrm{ff}}$ | 32 | 规定 GELU 前馈网络容量 |
| 层数 $n_{\mathrm{layers}}$ | 2 | 必须训练全部两层 |
| 最大输入长度 | 12 | 学习式位置表的有效范围 |
| 优化器 | AdamW，学习率 0.01，衰减 0.01 | 记录完整配置与矩状态 |
| 梯度裁剪阈值 | 1 | 在一次更新前裁剪全部参数 |
| 计算类型 | CPU float64 | 用于精确核对，不是生产精度建议 |
| 随机种子 | Python 与 PyTorch 均为 29 | 数据和初始化都可复现 |

Decoder 使用学习式位置嵌入、pre-LayerNorm、多头注意力和 GELU 前馈块；它是教学结构，不冒充 Llama 或 Qwen 的配置。替换为 [P8](/principles/modern-decoder/) 的 RMSNorm、SwiGLU、GQA 或 RoPE 时，一次只改变一个因素，并保留相同数据与目标计数的对照。

字符 tokenizer 固定来自这套预先声明的合成字母表。自然语料应按 [T1](/training/data/) 在训练文档拟合或使用固定外部 tokenizer。换成 BPE 后，token 数和目标空间都改变，不能直接拿两种 token PPL 排名；需要按 [T4](/training/evaluation/) 的比较边界重新报告。

## Batch 与前向：独立文档不需要伪装成 packing

脚本每次选择一篇文档，并随机从前两个边界或开头截取一个后缀。输入是后缀除最后一个 token，标签是后缀除第一个 token。这仍然是同文档内的下一 token 目标：我们没有在不支持分块掩码的模型上直接拼装无关文档。

对 `[a,b,c,a,EOS]`，输入 `[a,b,c,a]` 的形状为 $(1,4)$，输出 logits 的形状为 $(1,4,4)$，目标 `[b,c,a,EOS]` 的形状为 $(1,4)$。`sequence_loss` 沿词表轴计算交叉熵，对全部有效目标平均。需要 padding 时，传入布尔有效目标 mask；批大小与输入元素数不应该成为另一个分母。

截取后缀后，位置从零开始。这表示我们训练的是“给定这个后缀作为独立可见上下文”的预测，而不是保留原文所有历史。没有 BOS 的约定不监督后缀的首 token。训练数据构造应明确这些条件，不能把被截断历史当成模型仍然可见的内容。

准备数据时可以先输出一个样本的解码文本、输入 ID、目标 ID 和有效计数。检查相邻关系是最便宜的正确性验证。若把输入本身当标签，模型可能通过当前 token 表示学到复制而损失下降，却没有训练真正的下一 token 预测。

## 一个更新：五个阶段怎样对应数学式

一次训练先调用 `model.train()`，再按顺序清空梯度、前向传播、计算有效目标损失、反向传播、裁剪并更新。`train()` 只设置模块模式，不会自动计算损失或调用优化器；`backward()` 只生成梯度，不会修改参数。

```python
optimizer.zero_grad(set_to_none=True)
logits = model(inputs)
loss = sequence_loss(logits, targets, valid)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
optimizer.step()
```

如果要按 [T2](/training/optimization/) 累积微批，清空与 `step()` 的频率应围绕完整更新调整，而损失按完整有效目标数缩放。不要在每个微批执行上面全部六行后仍称为梯度累积。

训练中可记录数据损失、学习率、梯度范数、有效目标累计数和验证损失。每个日志点对应的是更新前还是更新后状态也应固定。耗时要区分首次导入、初始化和训练；本章验证脚本不作 GPU 性能测量。

对极小数据的第一项检查是能否过拟合一个固定批。固定输入、固定目标和无 dropout 配置下，若几十到几百步连训练损失都无法显著下降，就应先查标签移位、mask、梯度路径和更新状态。过拟合成功证明这条优化链至少可以拟合该批次，不证明泛化，也不能保证较大数据一定更好。

完整脚本最后运行一个独立固定批探针：固定种子 31、同一模型配置，只训练第一篇文档 60 次。实际训练 NLL 从约 1.387822 降到 0.002195，并断言低于 0.03。探针不参与前面验证对照或 checkpoint 选择，目的只是确认可以拟合这一批目标。

## 验证：把模式和梯度开关分开

验证函数使用 `model.eval()` 并包在 `torch.no_grad()` 中。前者控制 dropout 等模块的行为，后者关闭梯度记录；两者不是同一个开关。本章 Decoder 没有 dropout，但仍保留这两个动作，以便同一流程能明确扩展。

验证集使用两条等长文档，因而可以直接组成一个批。自然数据长度不同则需要有效目标 mask，并先对损失求和与目标数累计，再统一相除。平均每个验证批的均值可能因末批大小和长度不同而改变结果，见 [T4](/training/evaluation/)。

检查验证函数没有调用 `backward()` 或 `step()`；最好确认参数和优化器状态没有变化。之后继续训练时重新设置 `train()`。用验证损失选择 checkpoint 可以合理，但最后报告应说明选择规则，例如“验证 NLL 最低的一次”与“固定预算最后一步”并不一样。

本脚本先计算初始化验证损失，再训练 30 步并计算最终验证损失。它只断言最终值小于初始值，不预设必须胜过基线的阈值。先跑实验得到事实，再决定怎样解释；不要为适配预想结论而挑选种子。

## Bigram 对照：相同 token 与相同目标怎样比较

[P2](/principles/language-modeling/) 的 bigram 模型只根据当前 token 预测后一个 token。我们用训练文档统计四乘四的转移计数，并给每个格子加 1 平滑，形成

$$
P(t_{i+1}=v\mid t_i=u)=\frac{C_{uv}+1}{\sum_{v'}C_{uv'}+n_{\mathrm{vocab}}}.
$$

加 1 是声明的基线估计方式，避免未见转移概率为零；它不是训练神经网络的标签平滑。基线只读取训练文档，验证时用与 Decoder 完全相同的移位目标，包括 EOS，比较每个有效目标的平均负对数概率。

本次 CPU float64 运行得到：初始化 Decoder 验证 NLL 约 1.354763，30 步后约 0.221303，平滑 bigram 约 0.499571。这里的差异发生在这套合成循环数据、固定配置和单个种子上。尤其 EOS 的长度模式可能被位置表示利用，不能由此推出“两层 Transformer 总是优于 bigram”。脚本打印实际结果，库版本改变时重新运行记录。

一个有意义的扩展是保持 tokenizer、数据、有效预算与评估不变，分别关闭位置嵌入、减少为一层或替换前馈激活。若同时扩大模型、增加训练步数并更换 tokenizer，观察到更低损失就无法归因于某一个改动。

## Checkpoint：保存的是下一步需要的全部历史

模型参数只描述当前函数。AdamW 的一阶矩、二阶原始矩和步计数描述优化历史；随机状态决定下一次窗口和文档顺序；数据游标决定下一条样本。恢复参数却丢失其中任一项，都可能得到不同训练轨迹。

<Figure src="training/checkpoint.svg" alt="更新结束时保存参数、优化器、随机状态和游标，恢复后核对下一步">四类状态在同一个更新边界保存，恢复时共同决定下一次训练事件。参数相同只是其中一项条件。</Figure>

脚本保存模型配置、tokenizer 映射、模型与优化器 `state_dict`、已完成步数、当前顺序与游标、PyTorch RNG 状态、Python RNG 状态。若实际使用 NumPy 随机数、CUDA、数据加载工作进程或独立 `Generator`，也需要保存相关状态。本脚本没有使用它们，所以不创建不存在的状态。

快照选择在完整 `optimizer.step()` 后、下一批抽样前。这样不需要额外保存未完成的梯度累积。如果允许在某个微批之间中断，就还要保存当前梯度、累积目标数和微批进度，复杂度明显增加。先选择清楚的更新边界，可以让恢复协议更简单。

`state_dict()` 中张量可能仍共享当前存储。若在内存保存字典后继续训练，旧快照可能一起改变，因此脚本用深拷贝。文件持久化则应先写临时文件，完成后再原子替换目标路径，避免中途失败留下半个 checkpoint；同一目录中的原子替换通常更容易保证。大规模分片 checkpoint 还要定义多文件完整性标记。

序列化格式也有信任边界。脚本用内存字节流写入本进程生成的可信 payload，再读取完整 Python 状态；不要对未知来源的 pickle 关闭安全限制。对外分享权重时可以采用受限的纯张量格式，并把配置与训练元数据另行保存。

## 恢复检验：连续和中断怎样形成同一个实验

先训练 18 步并保存快照，继续训练 12 步，记录每一步损失与最终参数。再创建新模型和新优化器，加载快照，并在模型初始化消耗随机数之后恢复 RNG。随后从保存顺序和游标继续执行 12 步，逐项比较损失、游标、顺序和所有参数。

恢复顺序很重要：如果先恢复 RNG，再随机初始化新模型，初始化就消耗了本应属于后续抽样的随机数。模型模式不包含在普通权重字典中，恢复后也要明确设置训练或评估模式。学习率日程若存在，则在对应 optimizer 状态之后恢复，并核对下一步学习率。

本章脚本设置 CPU 单线程、无 dropout、float64，检查恢复后损失和参数完全相等。这个严格相等只证明指定环境下的恢复协议。GPU 内核、分布式规约、版本变化或非确定算子可能带来浮点差异；生产恢复应同时定义随机/数据协议和数值容差，而不是把位级相等作为所有平台的承诺。

只比较加载后立刻的模型输出还不够，因为丢失 AdamW 状态时，加载后的前向仍能相同。至少比较一次后续更新；本章比较十二步，包含重新打乱文档顺序的时刻，确保随机和游标都真正参与核对。

## 生成：训练目标如何进入自由运行

脚本以 `[a,b]` 为提示，取最后一行 logits 的最大项作为下一 token，追加回输入，再重复最多六次；出现 EOS 就停止。一次实际运行生成 ID `[0,1,2,0,1,2,0,1]`，即 `abcabcab`，没有在这个短预算内遇到 EOS。

这使用贪心选择，不表示训练损失只要求预测最大项；交叉熵监督完整正确类别概率。自由生成会把自己的选择作为后续上下文，而验证通常使用真实历史的教师强制（teacher forcing）。二者条件不同，因此低验证 NLL 不能保证任何提示都生成正确序列。

生成示例每次重算整个短提示，让生成链条与前向结构一一对应。脚本还对已经训练并恢复的同一模型执行 [P10](/principles/kv-cache/) 的缓存核对：验证输入长九个 token，分别整体运行、逐 token 运行和按 `[3,2,4]` 分块运行，拼回全部 logits，与普通前向在 $10^{-10}$ 容差下比较，并检查每层缓存长度。这样缓存检验使用的是当前训练权重，没有另起一份不相关的随机模型。

缓存不改变训练目标，也不是保存 checkpoint 的另一种方式。缓存核对以 eval 模式和相同绝对位置进行，主要比较 logits；浮点近似相同的分布仍可能在采样边界产生不同文本。

学习式位置表有长度上限。超过 12 不能通过任意取模位置就声称继续使用同一模型；可以明确截断上下文作为新的评估策略，或换用经过设计与评估的位置方案。长上下文扩展将在进阶路线讨论，本实验只生成在位置表范围内的文本。

## 规模：参数、token 与计算预算怎样一起选

本章的模型只有几千个参数，结论只覆盖这组合成数据。放大到真实预训练时，第一个要回答的问题是：固定一笔计算预算，参数量 N 与训练 token 数 D 怎样分配。

### 为什么训练一次约是 6ND

先数矩阵乘法。每个 token 经过一个权重时做一次乘加，按 2 FLOP 计，所以前向约 $2N$ FLOP。反向传播对每个权重要算两件事：传给上一层的激活梯度，以及权重自身的梯度，各是一次同样规模的乘加，约 $4N$。合计每个训练 token 约 $6N$：

<KeyEq label="训练计算量">

$$
C\approx6ND+12\,n_{\mathrm{layers}}\,T\,d\,D.
$$

</KeyEq>

第二项来自注意力的 $QK^\top$ 与加权 V：每层前向每个 token 约 $4Td$，训练再乘 3。这里的 N 只计参与矩阵乘法的权重，嵌入查表不是乘法，LM head 是。第二项与第一项之比约为 $T/(6d)$，本章 $T=11,d=16$ 时约占 15%；上下文远长于隐藏维度时，它不能省略。跳过遮罩块的注意力实现只算下三角，第二项约减半。

脚本用 PyTorch 的 `FlopCounterMode` 统计本章模型一次前向加反向的矩阵乘法 FLOP。4160 个线性权重、33 个目标 token 时，计数恰为 $6\times4160\times33+12\times2\times11\times16\times33=963072$。这个等式核对的是乘法次数，不是运行时间；[S1](/systems/ledger/) 与 [S2](/systems/accelerator/) 讨论 FLOP 怎样变成秒。

### 固定预算下的分配

Kaplan 等人发现，在足够宽的范围内，测试损失随 N、D 与 C 近似按幂律下降。Hoffmann 等人（Chinchilla）在固定 C 下系统比较不同的 N、D 组合，拟合得到计算最优的 N 与 D 大致按相同速度增长，各约与 $\sqrt C$ 成正比；他们的 70B 参数模型用了 1.4T token，约每个参数 20 个 token，用同样预算胜过了 280B 参数、300B token 的 Gopher。

把“每参数 20 token”当作经验比例代入 $C=6ND$：预算 $10^{21}$ FLOP 时 $120N^2=10^{21}$，得 $N\approx2.9\times10^9$、$D\approx5.8\times10^{10}$。这个比例是在特定数据、tokenizer 与架构上拟合出的，换条件就要重新测量。

计算最优只针对训练预算。部署时每次推理的成本随 N 增长，所以常见做法是让较小的模型读远多于 20 倍的 token：Llama 3 8B 用了超过 15T token，约每参数 1900 个。这是用更多训练计算换更低的推理成本，不违背缩放规律，只是优化目标不同。缩放曲线预测的是同分布验证损失；它不直接预测某项下游任务的得分，后者由 [T4](/training/evaluation/) 的评估协议另行测量。

## 文本实验：同一个现代模型接入可分发语料

`text_pretraining.py` 中六篇训练短文与两篇验证短文均为自编文本。先固定文档划分，再只用训练文档拟合预切分字节 BPE，最多十六次合并。特殊词表项为 `<bos>`、`<eos>`；它们的 ID 位于所有普通字节与合并项之后，模型词表数据此建立。训练程序直接添加控制 ID，不把普通文本中的相同字面串自动升级成控制 token。

模型用两层、隐藏宽 24、前馈宽 48、四个 Q 头、两个 KV 头、独立头宽 8、最大上下文 64，绑定输入输出权重。查询总宽 32 不等于隐藏宽 24，正好让真实训练也覆盖这个边界。PyTorch AdamW 学习率 0.006、衰减 0.01，CPU float64 用于恢复核对；这不是推荐的大模型训练配方。

每篇文档形成 `[BOS,普通文本ID,EOS]`，按 24 个输入目标划成窗口。窗口之间重复一个边界输入以预测后续 token，目标没有重复；每个窗口独立可见历史，位置重新从零开始。尾窗可以更短，程序逐窗更新而不填充，因此没有悄悄要求模型支持 padding。训练还随机截掉窗口前零到两项，作为明确的后缀上下文增强，实际目标数随之变化。

验证不使用随机裁剪，对所有窗口 NLL 求和后按真实目标数平均。输出保留每个窗口的索引、目标数与平均 NLL；短尾窗与完整窗不会获得同样总权重。当前验证共 63 个目标，初始 NLL 约 5.623874，训练 28 次后约 3.638732。这些文本共享题材，数量很小，只用于验证计算与保存流程，不能据此声称开放领域语言能力。

## 磁盘状态：恢复要跨过真正的文件边界

checkpoint 保存模型 config、权重、AdamW 状态、分词器状态、全局步数、窗口顺序、顺序游标、Python/Torch RNG，以及冻结的训练和验证文档。文档与 tokenizer 的 SHA-256 指纹在加载时重算，避免内容或 ID 映射改变后继续使用旧数据游标。词表数、顺序排列和游标范围也要检查。

先在目标目录写临时文件，再用同文件系统的原子替换更新 checkpoint；写入失败不会先删除旧 checkpoint。该流程保护进程级写入中断，不承诺突然断电时的持久化；需要耐断电时应进一步调用文件与目录同步并制定备份策略。加载使用 `weights_only=True` 与 CPU 映射，不启用任意 pickle 对象恢复。

载入模型和优化器后，最后恢复 RNG，因为实例构造本身会消耗初始化随机数。教学程序固定 CPU dtype，所有随机源只有 Python 与 Torch；若接入 NumPy、CUDA、多 worker 或 dropout，必须一并保存相应状态和数据加载器契约。[T9](/training/distributed-training/) 还解释各 rank 随机状态不一定相同。

默认运行 `python code/training/text_pretraining.py`，先更新二十次并保存磁盘文件，连续运行八次，再从该文件恢复八次。断言加载时 logits 逐位相同，之后八个损失、所有参数、游标和顺序均相同。它检验真正的文件序列化，不只是复制一个内存字典。

## 命令行：训练、恢复与生成分别运行

```sh
python code/training/text_pretraining.py --checkpoint runs/prose.pt --steps 80
python code/training/text_pretraining.py --checkpoint runs/prose.pt --resume --steps 20
python code/training/text_pretraining.py --checkpoint runs/prose.pt --generate-only --prompt "the cat" --max-new-tokens 16
```

`--steps` 是本次额外执行的更新数，所以前两次之后全局步数为 100。恢复使用 checkpoint 自带冻结文本与 tokenizer；不会重新拟合 BPE，也不从命令行替换旧语料。新训练要求 checkpoint 路径尚不存在，避免意外覆盖旧模型，并写对应的 `.tokenizer.json` 供单独查看。

可用 `--train-text train.txt --validation-text valid.txt` 启动新的训练，两份文件都采用 UTF-8、每个非空行一篇文档；程序拒绝完全重叠的文档与空集合。来源分组、近重复和评估污染仍需在进入程序前处理，见 [T8](/training/data-engineering/)，精确集合不重叠不能证明不存在所有泄漏。

生成给 prompt 前添加 BOS，prefill 后逐 token 使用缓存，采样遇 EOS 或达到预算停止。词表包含所有字节，随机生成可能不是合法 UTF-8，展示采用替换字符；P1 的严格往返检查不因此放宽。模型尚小、训练尚短，生成内容不保证可读，训练、评估与恢复才是本实验的验收对象。

## 常见误区

保存参数不是保存训练；设置 eval 不是关闭梯度；损失下降不是泛化证明。窗口随机种子相同也不保证恢复一致，因为初始化、抽样和多次验证可能改变随机数消耗顺序。扩展规模前先确保输入移位、有效目标分母、参数更新和恢复协议均可核对。

## 练习与核对

<details>
<summary>只加载模型权重，重新创建 AdamW，加载后验证输出相同。为什么下一步仍会不同？</summary>

前向仅依赖权重与输入，而 AdamW 更新还依赖历史矩状态和步计数。新优化器把它们设为零，偏差校正也从第一步开始，所以同一梯度产生不同更新。需要恢复优化器状态，并核对后续一步。

</details>

<details>
<summary>为什么在内存保存 state_dict 后要深拷贝？</summary>

普通字典中的张量可能引用模型当前存储，继续训练会修改它们。深拷贝或立即序列化才能固定保存时刻。文件写入失败则是另一类风险，需要持久化协议解决。

</details>

<details>
<summary>怎样设计“RoPE 是否改善结果”的第一轮实验？</summary>

保持数据划分、tokenizer、有效 token 预算、模型宽度和训练评估协议固定，只替换位置方案，记录参数量差异与多个种子。比较验证 NLL和规定长度任务；若同时换成更大模型或增加训练预算，就不能把差异归因于 RoPE。

</details>
