[P11 完整 Transformer](/principles/complete-transformer/) 已经能从一行输入算出下一 token 的分数。但把原始文本交给模型之前，我们还要回答：哪篇文档属于训练集？词表从哪里学来？拼接短文后，第二篇能不能读取第一篇？一次损失究竟平均了几个目标？

本章用四条记录一直算到训练输入。读完后，你应能给出同一批样本的文档来源、input/target ID、允许关注的位置和有效目标数，并解释哪一步做错会污染验证结果。[P1 tokenizer](/principles/tokenization/) 和 [P2 下一 token 目标](/principles/language-modeling/) 是先修；优化器在 [T2](/training/optimization/) 再讨论。

## 文档身份：先知道要评估什么

假设四条已获准使用的记录如下。这里的“来源组”代表独立的原始文档；重复采集的副本仍属于原组。

| 记录 ID | 来源组 | 文本 | 预定用途 |
| --- | --- | --- | --- |
| A | s1 | `ab` | 训练 |
| A-copy | s1 | `ab` | 训练 |
| B | s2 | `cd` | 训练 |
| C | s3 | `az` | 验证 |

我们希望验证损失反映**未见来源组**的预测能力。因此独立单位是来源组，训练组为 s1、s2，验证组为 s3。A-copy 与 A 的 UTF-8 字节完全相同，精确去重后只有三篇唯一文档：训练 A、B，验证 C。若先把 A 和 A-copy 各自切成窗口，再随机分配窗口，模型可能在训练和验证中看到同一段内容。此时低验证损失不能支持“能泛化到新文档”的结论。

真实语料至少要保留稳定记录 ID、来源、版本和使用许可。内容 SHA-256 指纹能发现本例的逐字副本，却不能证明两个不同标题、相同正文的文章独立；同一作者、同一代码仓库的近重复也可能跨集合。先确认评估的独立单位，再按来源和重复关系分组，最后划分。若任务要预测未来文章，还要按时间约束划分。固定的外部测试集应保留到开发决策结束后，不靠反复查看测试分数来选择规则。

“公开可读”不等于可用于训练或再分发。生产流程要逐来源核对许可与个人信息、密钥等敏感内容，并记录过滤规则和删去比例。本例只用自造文本；这一页的哈希检查不是完整的数据治理流程。

## Tokenizer：验证文本可以编码，不能参与拟合

使用字符级 tokenizer 演示 [P1](/principles/tokenization/) 的同一原则：只从训练文本 `ab`、`cd` 收集字符。约定 `UNK=0` 表示未收录字符，随后按字母序给 `a,b,c,d` 分别分配 ID `1,2,3,4`，保留 `EOS=5` 表示文档结束。于是

| 文档 | 编码结果，含 EOS | 所属集合 |
| --- | --- | --- |
| A | `[1,2,5]` | 训练 |
| B | `[3,4,5]` | 训练 |
| C | `[1,0,5]` | 验证 |

验证文档 C 的 `z` 只能成为预先规定的 UNK。若看见 C 后才把 `z` 加入词表，分词器已经利用验证信息，哪怕模型权重还没更新。真实 BPE tokenizer 还会从训练文本统计合并规则；冻结前同样不能读取验证内容。字节覆盖的 tokenizer 可以避免这个字符级 UNK，但也应记录其版本和训练来源。

ID 映射本身是模型契约。把 `a` 从 ID 1 改成 ID 2，已有 embedding 表不会自动交换两行；恢复 checkpoint 时必须复用相同的规范化、词表、合并规则与特殊 ID。反复用验证集比较 tokenizer 和清洗阈值，也是在用验证结果做选择；最终结论需要留出未参与选择的测试集，或者明确只报告验证观察。

## 移位与窗口：一篇文档产生哪些预测

对 A 的 `[1,2,5]`，不加 BOS 时把序列错开一位，得到输入 `[1,2]`、目标 `[2,5]`。第一行学习在 `a` 后预测 `b`，第二行学习在 `ab` 后预测 EOS。EOS 是真实结束事件，应该计入目标；本约定没有学习“文档开始前预测首 token”。若需要首 token 的概率，可以另加 BOS，并在训练、评估和生成中保持同一约定。

一般地，文档 token 为 `[t_0,...,t_{m-1},EOS]`，则输入与目标是

$$
x=(t_0,\ldots,t_{m-1}),\qquad
y=(t_1,\ldots,t_{m-1},\mathrm{EOS}).
$$

这里每篇非空文档有 $m$ 个有效目标。B 同理得到输入 `[3,4]`、目标 `[4,5]`；若独立处理 A、B，本批共有四个有效目标。验证 C 的输入为 `[1,0]`、目标为 `[0,5]`。UNK 仍是目标，因而字符级玩具实验会丢失 `z` 的细节；不能把验证损失解释为对原字符的精确预测。

模型上下文上限若为 $T$ 个**输入** token，窗口必须读到 $T+1$ 个连续 token 才有 $T$ 个移位目标。例如较长文档的流为 `[t0,t1,t2,t3,t4,t5,EOS]`，取 $T=2$、步幅 2，第一窗用 `[t0,t1]` 预测 `[t1,t2]`，第二窗用 `[t2,t3]` 预测 `[t3,t4]`。下一窗才会覆盖末尾。步幅变成 1 会重复监督某些目标；**先划分文档，再在各集合内取窗口**，否则相邻窗口可能分落训练和验证。窗口断点以外的历史不可见，因此截断后的损失对应有限上下文，而非完整文档条件概率。

## Packing：省下 padding 会改变可见历史吗

A 与 B 都很短。把它们连同 EOS 拼成流 `[1,2,5,3,4,5]`，整体移位后有五行：

| 行 $i$ | 输入 $x_i$ | 目标 $y_i$ | 输入所属文档 | 目标所属文档 |
| --- | --- | --- | --- | --- |
| 0 | 1 | 2 | A | A |
| 1 | 2 | 5 | A | A |
| 2 | 5 | 3 | A | B |
| 3 | 3 | 4 | B | B |
| 4 | 4 | 5 | B | B |

行 2 是关键：它要求模型在 A 的 EOS 后预测 B 的首 token。**连续语料**策略保留这一行，并让 B 读取 A 的历史；于是五个目标都有效。它适合把两段视作相接文本的目标，但拼接顺序会影响所学条件分布。

若 A、B 是独立文档，**文档隔离**策略只让查询读取同文档内不晚于自身的键，并取消行 2 的直接损失。B 的位置编号从 0 重启。五行输入仍在同一数组里，却只有四个有效目标，和分别处理 A、B 的目标数相同。EOS 只是一个 ID，不会自动阻断跨文档注意力。

<Figure src="training/packing.svg" alt="连续语料是完整下三角注意力，文档隔离是两个分块下三角；隔离还取消跨文档损失并重置 B 的位置编号">列是可读取的输入位置，行是当前查询。对比 B 的第 3 行：左图可读 A 的三列，右图只能读自己的列；下方的损失与位置行显示另外两处必须同步改变的元数据。</Figure>

这两种目标都可以训练因果模型，不能把其中一种默认为“正确”。无关会话拼在一起时通常需要隔离；连续书籍段落可以选择保留跨段上下文。选择必须与训练及评估所声称的条件分布一致。

实验保留 A、B 的同一编码。构造阶段依次显示拼接、移位、位置与监督元数据；注意力矩阵始终区分查询行和键列。选择行 3，再切换文档隔离，可读键从 `0–3` 缩为 `3`，位置从 3 变为 0，有效分母从 5 变为 4；选择行 2 则能核对跨界预测为什么被取消。三项变化缺一项，就不是前面定义的隔离目标。

## 三种 mask：注意力、损失与 padding 各管一件事

令 $o_i$ 是输入行 $i$ 的文档编号。隔离时注意力的**允许**矩阵为

$$
A_{ij}=\mathbf1[j\le i]\,\mathbf1[o_i=o_j].
$$

$A_{ij}=1$ 表示第 $i$ 行可以读取第 $j$ 行；它不是 softmax 后的权重。因果项挡住未来，文档项挡住别的文档。图中行 3 因而只读列 3。不同框架的布尔 attention mask 有时以 `True` 表示“禁止”，调用 API 前须核对约定。

损失 mask 则为 $v_i=\mathbf1[o_i=o_{i+1}]$，在本例是 `[1,1,0,1,1]`。它取消跨界的行 2，但不会改变别的行可以读哪些键。行 2 的隐藏状态仍可能被计算；仅令它的损失为零不能阻止 B 读取 A。

若 batch 为对齐长度而补 padding，padding 位置又需要单独处理：它不能成为真实目标，也不应作为有效键被读取。仅把 padding 查询的损失置零，不一定能防止该查询在全键屏蔽的 softmax 中产生 NaN；实现应定义无效查询的计算与输出。教学例没有 padding，且每个有效查询至少可读自身。位置编号不是 mask，却同样依赖边界：隔离 B 使用 `[0,1]`，连续策略在拼接流中使用 `[3,4]`。

## 损失分母：五行输入为什么只除以四

设每行目标的负对数似然为 $\ell_i$。隔离策略的平均损失定义为

$$
L=\frac{\sum_i v_i\ell_i}{N_{\mathrm{valid}}},
\qquad N_{\mathrm{valid}}=\sum_i v_i=4.
$$

例如五行损失为 `[1,2,9,3,4]`，行 2 无效，则 $L=(1+2+3+4)/4=2.5$。若将无效行乘零后仍除以五，得到 2.0，所有参数梯度也被统一缩为原来的 $4/5$。分母不是输入长度，也不是文档数；没有任何有效目标的 batch 应跳过或报错，不能除以零。T2 将用同一个计数合并长度不同的微批。

采样策略也会影响“见过多少数据”。在本例，每篇文档各抽一次并独立移位，各贡献两个目标。若一篇长文被切成重叠窗口，它的同一目标可能在多个训练事件中出现。一个 epoch 只有在“遍历一遍已定义样本集合”时才有明确含义；无限流和重采样更应记录实际累计有效目标数。按**文档数**一半一半混合代码与短文本，也未必等于按**有效 token 数**一半一半：长文通常贡献更多位置。配置抽样概率后应统计实际来源占比和目标数。

## 常见误区

- 精确去重只发现逐字相同的文本；近重复、同源改写和已有评测题污染需要分别审计。
- EOS 仍应被预测；padding 通常既非真实目标，也非真实历史。二者不能互换。
- 损失 mask 只决定直接监督位置，不会改变注意力读取范围。
- 即使模型梯度没读验证集，重新拟合 tokenizer 或反复挑选最优清洗规则也会用到验证信息。
