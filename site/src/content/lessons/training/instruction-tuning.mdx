对一个只训练文本续写的模型输入“请回答问题”，它可能续写出另一位作者的讨论、重复问题，或者给出答案。这并不矛盾：预训练目标是预测下一 token，没有额外约定“当前应该扮演助手”。指令微调通过带角色和回复的数据，让同一个下一 token 目标集中监督期望的助手行为。

先修是 [T3 训练闭环](/training/pretraining/)、[T4 评估](/training/evaluation/) 和 [P9 生成](/principles/generation/)。本章先定义序列化与目标选择，再核对多轮对话的移位位置，最后用小型格式任务比较更新前后的结果。它验证监督式微调（supervised fine-tuning，SFT）的计算链，不将几十步合成实验称为通用指令跟随能力。

## Base 与 Instruct：权重训练目标和推理模板共同决定行为

Base 模型通常指主要完成预训练的基座；Instruct 模型通常经过指令或对话数据及其他后训练。它们仍可以使用相同的因果 Decoder 和词表输出，区别来自训练数据、目标选择、后训练方法及生成约定，不是一个新增“聊天层”就让架构发生根本改变。

一个 Instruct checkpoint 可能还经过偏好优化、拒绝策略或推理专项训练；SFT 是其中一个阶段，不包含所有后训练方法。后续进阶路线讨论 DPO 与推理强化学习。此处只使用监督对话：给定输入历史，让正确回复的 token 概率提高。

对话模板属于模型输入协议。角色名字出现在 API 请求里，最终仍要被序列化成模型能读取的 token；模型不会直接看见外部 Python 字典的 `role` 字段。不同 checkpoint 可能使用不同边界标记，不能因为都叫 `user` 与 `assistant` 就交换模板。

同一基座使用错误模板也可能产生看似合理文本，但这不证明协议无关。正确比较应固定训练和生成模板，检查末尾是否真的提示模型开始助手回复，并确认停止 token 与训练结束标记一致。

## 对话序列化：角色怎样成为一条 token 流

一段会话可以包含 system 规则、user 请求与 assistant 回复。序列化时插入角色头、消息结束标记和内容，例如教学协议：`SYS 规则 USER 问题 ASSISTANT 回答 END`。这些字符串仅用于解释；脚本使用独立 ID，不假定真实 tokenizer 会将它们各自编码为一个 token。

角色头有时由多个 token 组成，消息结束符也可能与整个会话 EOS 不同。使用真实模型时，先读取 checkpoint 的 tokenizer 配置与 chat template，再调用对应模板接口。若先生成含特殊标记的字符串，再用会自动添加特殊 token 的编码接口处理，可能重复 BOS 或 EOS。

规范化会话也要检查角色序列。连续两条 assistant、缺少 user、没有回复、空回复或工具调用，需要有明确处理规则。不能将多种格式直接拼入同一个模板后期待模型自动补齐。截断尤其要避免保留了 assistant 头却删除全部回复，造成没有有效目标的样本。

在多轮训练中，把所有消息串成同一条因果序列，后面的回复可以读取前面的用户请求和助手回答。这正是对话上下文；不同用户会话之间是否隔离则回到 [T1](/training/data/) 的 packing 策略，角色头不自动阻断注意力。

## Generation prompt：末尾助手头为什么不是一条已完成回复

训练数据通常含完整 assistant 内容；生成时只提供到助手回复开始处。例如提示末尾是 `ASSISTANT`，之后让模型生成回复文本和结束标记。这段未完成的助手头称 generation prompt，它告诉模型下一个 token 属于哪种消息。

“追加助手头”与“继续最后一条助手消息”是不同操作。前者启动新回复，后者续写已经给出的部分回答。模板 API 通常提供不同开关；调用时要匹配训练协议，不能一边把已有回复留在提示中，一边再追加一个新助手头却仍认为是同一个任务。

训练完成后，生成也必须使用同一角色标记、空白和边界。EOS 与消息结束 ID 不同的模型，应该按规定停止条件处理，而不是仅靠遇到某个可见字符串停止。工具消息和多模态内容更复杂，本章先限定纯文本、无工具的教学协议。

## Assistant 目标：掩码针对被预测 token 的身份

SFT 可以对整个序列计算损失，也可以只监督 assistant 回复。两者都是可定义的目标，但本章使用回复内容及助手结束标记参与损失，system、user 和角色头不参与直接监督。首先标记完整 token 流中每个 token 的归属，再做移位。

设完整流为 $t_0,\ldots,t_{N-1}$，输入 $x_i=t_i$，标签 $y_i=t_{i+1}$。若 $r_j$ 表示 token $j$ 的归属，回复有效标志是

$$
v_i=\mathbf 1[r_{i+1}=\mathrm{assistant}]\,
\mathbf 1[t_{i+1}\text{ 不是 padding}].
$$

关键是 $i+1$：第 $i$ 行 logits 预测下一 token，应根据目标身份决定是否监督，不能根据当前输入身份。预测第一个回复 token 的输入常是 assistant 头，因此“只有输入已经是回复内容才计入损失”会漏掉第一个回复 token。

有些生产模板也监督 assistant 角色头，或者把回复结束标记归到特殊类中；这都可以，但需要具体定义。跨模型迁移时不要只搬运布尔数组而不检查模板和边界，尤其回复第一项与结束项最容易错一行。

## 多轮算例：两段回复怎样各自获得监督

| 完整下标 $j$ | ID | 含义 | 目标归属 |
| --- | --- | --- | --- |
| 0 | 0 | S | system |
| 1 | 1 | 规则 | system |
| 2 | 2 | U | user |
| 3 | 3 | 问题一 | user |
| 4 | 4 | A | assistant 头，不监督 |
| 5 | 5 | 回答一 | assistant |
| 6 | 6 | E | assistant |
| 7 | 7 | U | user |
| 8 | 8 | 问题二 | user |
| 9 | 9 | A | assistant 头，不监督 |
| 10 | 10 | 回答二 | assistant |
| 11 | 11 | E | assistant |

这张表使用不同 ID 区分两次相同角色符号，目的是方便逐行核查，不是推荐真实词表为每一轮建立新的角色 ID。真实模型应复用相同角色标记的编码，仍可在预处理元数据中记录每个目标归属。

如果只监督最后一轮回复，则 mask 仅保留 $i=9,10$；如果希望多轮所有助手消息提供监督，则保留四行。两个目标不同，数据集和训练报告要明确选择。不应让一个通用 collator 在不同任务中悄悄改变策略。

## 屏蔽提示损失：为什么提示表示仍然收到梯度

对于被屏蔽的 logits 行，直接损失梯度为零。但有效回复的隐藏状态通过因果注意力读取提示表示，所以梯度可以沿注意力路径回到 prompt 嵌入。这不与“只监督回复”矛盾：mask 选择监督项，没有删除前向依赖。

用一个最简单的因果平均注意力说明。令隐藏输入为 $h_j$，第 $i$ 行输出为 $u_i=\sum_{j\leq i}h_j/(i+1)$，再经输出矩阵给出 logits。若行 $i$ 的回复损失有效，则对任意 $j\leq i$，有 $\partial u_i/\partial h_j=I/(i+1)$，提示行同样存在反向路径。

脚本使用这个透明参考注意力，保留每行 logits 的梯度，断言无效行直接梯度全零、有效行非零；同时检查首个 system token 的隐藏表示与嵌入获得非零梯度。真正的多头注意力还有 Q/K/V 依赖，路径更复杂，但这里已经反驳“屏蔽 prompt loss 就冻结了 prompt embedding”的错误推断。

若基座参数冻结，只训练 [T6](/training/lora/) 的 adapter，提示依赖仍然参与计算，但梯度只积累到允许训练的参数。是否监督某位置与是否冻结某参数，是两个独立选择。

## 更新与长度：回复较长为什么可能贡献更多梯度

回复监督的目标是

$$
L_{\mathrm{SFT}}=-\frac{\sum_i v_i\ln P(t_{i+1}\mid t_{\leq i})}{\sum_i v_i}.
$$

这里仍然是交叉熵，没有新增“指令损失函数”。变化在于序列化和有效目标。按 token 平均时，长回复比短回复贡献更多监督项；按每条回复平均再按样本平均，则是另一种加权策略，不能混用分母。

长提示、短回复会导致总输入 token 多而有效监督少。应分别记录计算 token 和有效目标 token；它们分别影响运算预算和损失尺度。梯度累积使用有效目标总数，不能因为输入长度大就把回复梯度再额外压小。

截断时需要至少保留规定的有效回复，或者明确跳过该样本。简单截断到最大长度可能删除整个回答，只留下提示；对这样的空 mask，损失接口应报错，数据管道可按预先定义策略处理，而非生成 NaN 后继续更新。

训练前检查一批解码序列与有效 token 高亮，比仅看张量形状更可靠。对于真实聊天模板，角色头可能跨多个 token，文本中的特殊标记也可能被当作普通内容，所以不能用粗糙字符串搜索猜测 assistant span。

## 小型格式实验：更新前后怎样作有限对照

脚本第二部分复用 [P4](/principles/decoder/) 的两层 Decoder。训练两种请求，均要求回复两个固定 ID `[5,7]`，分别代表 `OK` 与结束标记。提示为 `[system,user,请求,assistant头]`，仅监督随后两个目标；另一个未用于训练的请求 ID 用于验证。

这是一项非常窄的格式任务：所有正确回复相同，因此模型可能仅学会忽略请求内容并输出固定格式。它适合检查模板、mask、更新和停止 token，不适合证明模型理解了新指令。真实泛化评估需要新内容、不同正确答案、未见组合与更丰富模板，按 [T4](/training/evaluation/) 固定协议。

本次固定种子 CPU 运行，未见请求的回复 NLL 从约 3.066293 降至 0.004345；自由生成的两个回复 ID 从 `[1,5]` 变为 `[5,7]`。训练 40 步，使用相同 checkpoint 架构与同一生成规则比较前后。报告这项有限的改善，不称其为一个可用聊天模型。

注意回复 NLL使用真实前缀的教师强制，生成结果使用自己的首个选择作为后续输入。代码同时输出两个观察，避免仅用低 NLL 推断实际格式成功。没有同时调整温度、提示模板或重复次数，因此这项前后比较的主要变化来自参数更新。

## 蒸馏：用教师分布代替单个目标 token

SFT 在每个回复位置只给出一个正确 token，交叉熵的目标是独热分布。若已有一个更大的教师模型，它在同一位置给出的是整个词表上的分布：除了最可能的 token，还说明哪些替代写法也合理、哪些明显错误。知识蒸馏（knowledge distillation）让学生去拟合这个分布。

设教师与学生在同一位置的 logits 为 $z^{\mathrm t},z^{\mathrm s}$，温度 $\tau$ 下的分布记作 $p^{\mathrm t}_\tau=\operatorname{softmax}(z^{\mathrm t}/\tau)$，学生同理。逐位置损失为：

$$
\ell_{\mathrm{KD}}=\tau^2\,\mathrm{KL}\big(p^{\mathrm t}_\tau\,\|\,p^{\mathrm s}_\tau\big)
=\tau^2\sum_c p^{\mathrm t}_{\tau,c}\big(\ln p^{\mathrm t}_{\tau,c}-\ln p^{\mathrm s}_{\tau,c}\big).
$$

对学生 logits 求导，沿用 [M2](/math/distributions/) 的 softmax 交叉熵结果，得到 $\partial\ell_{\mathrm{KD}}/\partial z^{\mathrm s}_c=\tau\,(p^{\mathrm s}_{\tau,c}-p^{\mathrm t}_{\tau,c})$。$\tau=1$ 时就是“学生概率减教师概率”；教师分布若是独热，KL 退化为普通交叉熵，SFT 是蒸馏的特例。升温使两个分布都变平，让低概率项的差别也进入梯度；除以 $\tau$ 缩小了 logits，前面的 $\tau^2$ 把梯度幅度补回同一量级，便于与普通交叉熵项混合。

实际有两种做法。逐 token 蒸馏需要教师与学生共用同一个 tokenizer 和词表，训练时对每个位置运行教师前向，损失遮罩与 SFT 相同，只在回复位置计算。序列级蒸馏更简单：让教师为一批提示生成回复，再把这些回复当作普通 SFT 数据训练学生，只用到教师的采样结果，不需要词表一致。[A5](/advanced/reasoning-rl/) 中用推理模型生成的轨迹训练较小模型，就是序列级蒸馏。

蒸馏只能把学生推向教师的分布，教师的错误也会一起学到；它同样需要本章的模板契约、去重与独立评估。脚本核对三件事：$\tau=1$ 时梯度等于概率差，独热教师下损失等于交叉熵，以及 $\tau=4$ 时梯度为 $\tau$ 倍的软概率差。

## 数据质量与遗忘：为什么 SFT 不能只增加样本数

错误答案、互相矛盾的角色规则、模板不一致和低质量自动生成回复，都会进入监督目标。去重和文档划分仍按 [T1](/training/data/) 执行，尤其同一会话的改写版本不能散入训练和验证。来源、回复生成方法与审核规则应记录，以便解释数据偏好。

任务适配可能降低基座在其他任务上的表现，称为遗忘或能力迁移代价。只评估新任务无法发现它。保留一个明确的旧能力评估集，在相同模板和协议下检查；若基座原本没有同一对话模板，比较时要说明如何构造相容输入。

可以研究更小学习率、更短预算、混入原分布数据或限制更新参数等策略，但它们都需要受控实验。LoRA 减少可训练参数并不自动保证没有遗忘。小型格式任务的成功也不能替代通用能力保留评估。

SFT 也不是可靠性或安全性的保证。学习到训练回复的风格不意味着模型能识别所有错误前提、未知事实和对抗提示。涉及这类目标时，应有明确的数据与独立评估，而不是从一次格式核对扩展结论。

## 常见误区

assistant-only loss 不代表 prompt 不影响训练；assistant 头不是回复正文；消息结束符不一定是整段 EOS。不要在训练和生成使用两份不一致的模板，也不要把被截断后无有效回复的样本送进平均损失。SFT 是训练阶段，不是新架构，也不包含所有偏好与强化学习方法。

<details>
<summary>为什么屏蔽 user token 的损失不能防止后面回复读取它？</summary>

损失 mask 删除的是直接监督项，注意力允许矩阵仍让后面行读取历史 user 表示。这正是条件回复需要的路径。若想阻断读取，必须改变注意力约束，但那会改变任务本身。

</details>

<details>
<summary>模型在固定 OK 格式任务成功，能否说明它能回答未见问题？</summary>

不能。任务所有答案相同，可以通过忽略问题完成。它只验证这个窄格式规则的适配。需要不同答案、未见内容与受控评估来支持更广的指令跟随结论。

</details>
