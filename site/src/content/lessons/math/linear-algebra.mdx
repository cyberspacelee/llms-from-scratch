假设每条记录有两个数值特征，模型要为它算出两个新特征。三条记录如何共用同一组权重，同时又不让一条记录读到另一条的特征？本章从一条记录的两次乘加开始，把它写成向量、矩阵和 batch 计算。这里只需要实数运算；下一章 [M7 微积分与梯度](/math/calculus/) 才讨论权重改变后结果怎样变化。

## 坐标与轴：每个数字属于哪条记录

先把三条记录排成数表：

$$
X=\begin{bmatrix}1&2\\3&4\\-1&0\end{bmatrix}
\in\mathbb R^{3\times2}.
$$

行表示记录，列表示特征。第二条记录是 $x_2=(3,4)^\top\in\mathbb R^2$；上标 $\top$ 表示转置，这里把一行数字明确写为列向量。一般地，单条记录 $x\in\mathbb R^d$ 有 $d$ 个特征；$B$ 条记录组成 $X\in\mathbb R^{B\times d}$，其中 $B$ 是 batch size（批次中的记录数）。本例 $B=3,d=2$。形状告诉我们每个轴有多长，轴名告诉我们它表示什么；只看数字 3 和 2 无法得知数据含义。

<Definition term="向量与矩阵" source="https://zh.wikipedia.org/wiki/矩阵">
  选定坐标方向后，向量由一组有序坐标表示；矩阵是按行、列排列的数，可用来组织线性映射的权重。本文的列向量写作 $x\in\mathbb R^d$，矩阵写作 $X\in\mathbb R^{B\times d}$。
</Definition>

<Figure src="math/01-vectors.svg" alt="向量 (3,4) 由水平 3 单位与竖直 4 单位合成">二维向量 $(3,4)^\top$ 可从原点沿两个坐标方向分别走 3 和 4 个单位得到。图中的坐标方向是读数的约定，不是向量自身的两个独立标签。</Figure>

图中第二条记录的两个数是相对于所选坐标方向的分量。换一组坐标方向，同一个向量会有另一组坐标；在真实模型里，两个特征也不一定分别对应可以命名的人类概念。后面计算需要的是它们的顺序与权重一一对应。

NumPy 中单条记录通常是形状 `(2,)` 的一维数组，它没有显式的行列方向，`.T` 仍是 `(2,)`；`x[:, None]` 才生成形状 `(2,1)` 的列。公式里的列向量约定用于推导，代码里的实际形状还要单独检查。

## 点积：一组权重怎样产生一个输出

让第一组权重为 $w_1=(1,-1)^\top$。第二条记录的第一个输出先不加偏置，逐元素算为 $1\cdot3+(-1)\cdot4=-1$。这种把对应分量相乘再求和的运算叫点积：

<Definition term="点积" source="https://zh.wikipedia.org/wiki/点积">
  同维实向量 $u,v\in\mathbb R^d$ 的点积是标量 $u^\top v=\sum_{j=1}^{d}u_jv_j$。两个向量的特征顺序必须对应。
</Definition>

所以 $w_1^\top x_2=-1$。如果另一组权重是 $w_2=(2,0)^\top$，它给出 $w_2^\top x_2=6$：第二组权重只使用第一个输入特征。不同输出可以读取同一个输入，但各自有一组权重；这正是后面把权重排成矩阵的理由。

### 点积与长度各回答什么问题

向量的欧氏长度是 $\|x\|_2=\sqrt{\sum_jx_j^2}$。对第二条记录 $x_2=(3,4)^\top$，长度为 5；把它除以 5 得到长度为 1 的 $(0.6,0.8)^\top$。两向量间的欧氏距离是 $\|u-v\|_2$，不能用两者长度的差代替：$(3,4)^\top$ 与 $(-3,4)^\top$ 长度都为 5，距离却是 6。

<Figure src="math/02-norm.svg" alt="长度相同的两个向量仍可相距 6；向量 (3,4) 除以长度后变成 (0.6,0.8)">左侧比较长度与两端点间的距离；右侧把 $(3,4)^\top$ 除以其长度 5，方向保持不变。</Figure>

点积也受长度影响。若 $y=(2,0)^\top$，则 $x_2^\top y=6$；把 $y$ 放大十倍，点积变为 60，而方向没有变。对非零向量，若只想比较方向，可除以两者长度，得到余弦相似度：

$$
\frac{x_2^\top y}{\|x_2\|_2\|y\|_2}
=\frac{6}{5\cdot2}=0.6.
$$

<Figure src="math/03-dot-product.svg" alt="两个向量的夹角与沿其中一个向量方向的投影">点积也可读成两向量长度的乘积再乘夹角余弦；垂直时点积为零。</Figure>

图中夹角解释了点积的符号：同向为正，反向为负，垂直为零。线性层用的是原始点积，不会自动除以长度；注意力中的查询和键也通常先计算原始点积，再作规定的缩放。零向量没有方向，因而不能计算它与别的向量的余弦相似度。

## 矩阵乘法：把多个输出写在一起

我们希望一条输入同时得到两个输出。把刚才的两组权重按行排起来，再给每个输出一个偏置：

$$
W=\begin{bmatrix}1&-1\\2&0\end{bmatrix}
\in\mathbb R^{2\times2},\qquad
b=\begin{bmatrix}0.5\\-1\end{bmatrix}
\in\mathbb R^2.
$$

第一行权重负责第一输出，第二行负责第二输出。对 $x_2=(3,4)^\top$，两个逐元素计算分别是 $1\cdot3-1\cdot4+0.5=-0.5$ 和 $2\cdot3+0\cdot4-1=5$。把它们合写为 $z_2=Wx_2+b=(-0.5,5)^\top$。一般情况下若输入特征数为 $d$、输出特征数为 $m$，则

<KeyEq label="单样本线性层">
$$
W\in\mathbb R^{m\times d},\quad b\in\mathbb R^m,\quad
z=Wx+b,\qquad z_k=\sum_{j=1}^{d}W_{kj}x_j+b_k.
$$
</KeyEq>

每个 $z_k$ 都是第 $k$ 行权重与同一输入的点积，再加第 $k$ 个偏置。严格地说，带偏置的映射是仿射变换，深度学习框架仍把它称为线性层。`torch.nn.Linear` 将权重存成 `(m,d)`、偏置存成 `(m,)`，正好对应这里的 $W,b$。

上式也是矩阵乘法的特例。对于 $A\in\mathbb R^{p\times q}$、$C\in\mathbb R^{q\times r}$，相乘时沿共同的 $q$ 轴逐项相乘并求和，结果的行轴来自 $A$，列轴来自 $C$：

<Definition term="矩阵乘法" source="https://zh.wikipedia.org/wiki/矩陣乘法">
  当左矩阵的列数等于右矩阵的行数时，乘积 $AC\in\mathbb R^{p\times r}$ 存在，其元素为 $(AC)_{ij}=\sum_{k=1}^{q}A_{ik}C_{kj}$。这个运算与逐元素乘法 $A\odot C$ 不同。
</Definition>

例如 $W$ 的第一行与 $x_2$ 的点积给出 $Wx_2$ 的第一项 $-1$。矩阵的另一种读法是列的线性组合：$Wx_2=3W_{:,1}+4W_{:,2}=3(1,2)^\top+4(-1,0)^\top=(-1,6)^\top$。逐行读解释“每个输出怎样取输入特征”，逐列读解释“每个输入特征怎样贡献给全部输出”；两种读法给出同一个结果。

矩阵相乘的顺序有意义：先做 $C$ 再做 $A$ 才是 $ACx$。代码中 `@` 表示矩阵乘法，`*` 表示逐元素乘法；即使两个矩阵都是 `(2,2)`，也不能用 `*` 代替 `@`。

## batch 计算：同一权重怎样处理所有记录

逐条处理时，三条记录分别得到 $z_i=Wx_i+b$。要一次计算三条记录，输入矩阵 $X$ 的每行是一条记录，而 $W$ 的每行是一组输出权重。因此先交换 $W$ 的行列，令 $W^\top\in\mathbb R^{d\times m}$，再相乘：

<KeyEq label="共享权重的 batch 线性层">
$$
Z=XW^\top+b\in\mathbb R^{B\times m},\qquad
Z_{ik}=\sum_{j=1}^{d}X_{ij}W_{kj}+b_k.
$$
</KeyEq>

这里 $+b$ 约定沿批次轴把同一个偏置加到每一行，完整的数学写法是 $Z=XW^\top+\mathbf1_Bb^\top$。每个 $Z_{ik}$ 只读第 $i$ 条记录的特征和共享的 $W,b$；公式里没有其他记录的下标。因此一次矩阵乘法打包了重复计算，但没有让记录之间交换信息。

<Figure src="math/linear-shapes.svg" alt="批输入 B×d 与转置权重 d×m 相乘得到 B×m，长度 m 的偏置加到每一行">中间相同的 $d$ 是逐项相乘并求和的特征轴；输出保留 $B$ 条记录与 $m$ 个输出特征。</Figure>

代入开头的三条记录，得到

$$
Z=\begin{bmatrix}
-0.5&1\\
-0.5&5\\
-0.5&-3
\end{bmatrix}.
$$

第一行可核对为 $(1-2+0.5,\,2-1)=(-0.5,1)$；第二行正是上一节算出的 $(-0.5,5)$。若以后把 batch size 从 3 改成 8，$W,b$ 的形状不变，输出从 `(3,2)` 变为 `(8,2)`。对于非方阵也同理：`X:(8,5)`、`W:(3,5)`、`b:(3,)` 给出 `Z:(8,3)`，这时漏写转置就会暴露形状错误。

下面的实验用从 0 开始的数组下标。先保持记录 i=1、输出特征 k=0，即第二条记录的第一个输出。手算 $3\times1+4\times(-1)+0.5$，再核对输出 $Z[1,0]=-0.5$。

只把 k 改为 1，先预测新的输出，再看高亮行。X 中选中的行应保持不变，W 中选中的行应改变。随后保持 k=1，把 i 从 1 改为 2：这次应换输入行，仍使用同一行权重。这两次比较分别检查“多个输出读取同一输入”和“多条记录共用同一权重”。

### 广播会成功，但结果仍可能是错的

广播从最右侧开始对齐轴，长度相同或其中一个为 1 才兼容。这里 `Z:(3,2)` 加 `b:(2,)`，偏置在三行各用一次。如果预测是 `(2,1)`、目标却是 `(2,)`，相减会广播成 `(2,2)`，比较了每条预测和所有目标，而不是逐条配对。例如 `[[1],[2]] - [1,2]` 得到 `[[0,-1],[1,0]]`。即使代码运行成功，语义也已经错误；计算损失前应断言预测与目标形状相同。

下面用同一组数据对照“逐行算”和“一次算”；两个结果相同才说明 batch 写法保留了单样本语义。

```python
import numpy as np

X = np.array([[1., 2.], [3., 4.], [-1., 0.]], dtype=np.float64)
W = np.array([[1., -1.], [2., 0.]], dtype=np.float64)
b = np.array([0.5, -1.], dtype=np.float64)

Z = X @ W.T + b
by_record = np.stack([W @ x + b for x in X])
assert Z.shape == (3, 2)
np.testing.assert_allclose(Z, by_record)
np.testing.assert_allclose(Z, [[-.5, 1.], [-.5, 5.], [-.5, -3.]])

prediction = np.array([[1.], [2.]])
target = np.array([1., 2.])
assert (prediction - target).shape == (2, 2)  # 错误配对仍能运行
assert (prediction - target[:, None]).shape == (2, 1)
```

## 多一个轴：每个序列位置也能共享权重

若一个 batch 有 $B$ 条序列、每条有 $T$ 个位置、每个位置有 $d$ 个特征，输入形状变成 `(B,T,d)`。同一组 `W:(m,d)` 对最后的特征轴工作，输出是 `(B,T,m)`：每个 batch、每个位置都独立执行刚才的 $Wx+b$。位置轴 $T$ 被保留；这个运算本身不会混合不同位置。

embedding 是另一种常见的取向量操作：它用 token ID 从词表矩阵中选一行，并非拿 ID 与任意权重做线性投影。具体的 token、ID 和 embedding 查表会在 [P1 分词与词表](/principles/tokenization/) 串起来。

需要位置之间相互比较时，必须额外指定位置轴怎样参与运算。例如注意力把查询 $Q$ 与键 $K$ 都排成 `(B,T,d)`，交换 $K$ 的最后两个轴得到 `(B,d,T)`，于是 `Q @ K.swapaxes(-1,-2)` 的形状是 `(B,T,T)`：中间的特征轴 $d$ 被求和，保留的是两条位置轴，分别表示查询位置与键位置。直接对三维数组使用 NumPy 的 `.T` 会反转所有轴成 `(d,T,B)`，不能代替交换最后两轴。具体注意力含义将在 [P3 注意力](/principles/attention/) 展开。

用与前面相同的权重，把两个三位置序列排成 `(2,3,2)`，可检查线性层保留位置轴，注意力式乘法则产生两个位置轴：

```python
import numpy as np

X = np.array([[1., 2.], [3., 4.], [-1., 0.]], dtype=np.float64)
W = np.array([[1., -1.], [2., 0.]], dtype=np.float64)
b = np.array([0.5, -1.], dtype=np.float64)
Z = X @ W.T + b
sequences = np.stack([X, X + 1.])       # (B,T,d) = (2,3,2)
position_output = sequences @ W.T + b   # (B,T,m) = (2,3,2)
assert position_output.shape == (2, 3, 2)
np.testing.assert_allclose(position_output[0], Z)
position_scores = sequences @ sequences.swapaxes(-1, -2)
assert position_scores.shape == (2, 3, 3)
np.testing.assert_allclose(position_scores[0, 0, 1], X[0] @ X[1])
```

## 选读：秩与正交分别限制什么

主问题至此已经解决：形状决定每一步在哪个轴求和、哪些轴保留，也能检查 batch 与序列计算是否仍在使用同一组参数。接下来两个概念讨论线性映射能保留多少方向，以及何时保留长度；理解下一章的梯度计算暂不需要它们。

<Definition term="矩阵的秩" source="https://zh.wikipedia.org/wiki/矩阵的秩">
  矩阵的秩是其列向量中最多能选出多少个线性无关的向量，等于输出能够覆盖的独立方向数；$W\in\mathbb R^{m\times d}$ 的秩不超过 $\min(m,d)$。
</Definition>

例子 $A=\left[\begin{smallmatrix}1&2\\2&4\end{smallmatrix}\right]$ 的第二列是第一列的两倍。它将 $(u,v)^\top$ 映为 $(u+2v)(1,2)^\top$，输出总在一条直线上，故秩为 1；$(2,-1)^\top$ 和 $(0,0)^\top$ 都映为零，原输入无法仅凭输出恢复。若写成 $A=UV$，其中 $U$ 为 `(m,r)`、$V$ 为 `(r,d)`，映射先经过 $r$ 维中间表示，秩至多为 $r$。这只说明乘积矩阵的限制；[T6 LoRA](/training/lora/) 限制的是增量矩阵的 rank，不能据此说原有权重本身低秩。较完整的谱分解留到 [M11](/math/spectral/)。

<Definition term="正交矩阵" source="https://zh.wikipedia.org/wiki/正交矩阵">
  实方阵 $Q$ 若满足 $Q^\top Q=I$，便是正交矩阵；它保持任意两个向量的点积，因此也保持长度与距离。
</Definition>

例如 $Q=\left[\begin{smallmatrix}0&-1\\1&0\end{smallmatrix}\right]$ 将 $(3,4)^\top$ 转成 $(-4,3)^\top$，前后长度都是 5，因为

$$
\|Qx\|_2^2=(Qx)^\top(Qx)=x^\top Q^\top Qx=x^\top x.
$$

旋转是正交变换的一种，反射也可以正交；[P7 RoPE](/principles/rope/) 用到的是旋转。一般线性层的 $W$ 不满足 $W^\top W=I$，不保证保长。这里的“正交”指向量整体的点积为零，不能从某个坐标是否为零判断。

## 常见误区：形状相同不等于意义相同

- 数学上的列向量与代码中的一维数组都能存两个数，但 `(2,)`、`(2,1)`、`(1,2)` 的广播和矩阵乘法规则不同。
- 点积大可能只是某个向量更长；想比较方向时，先检查非零，再除以各自长度。
- `W:(m,d)` 的第一轴是输出特征，不是 batch；增加样本数不会增加权重行数。
- 转置交换行列，不等于求逆；正交方阵才有 $Q^{-1}=Q^\top$。

## 练习与核对：换数据后还能推出来吗

<details>
<summary>1. X:(8,5) 要得到每条记录 3 个输出，权重、偏置和输出各是什么形状？为什么？</summary>

每个输出需要 5 个输入权重，共 3 组，所以 `W:(3,5)`、`b:(3,)`。代码算 `X @ W.T + b`，对应 `(8,5) @ (5,3)`，结果 `(8,3)`。8 是记录数，不属于参数的轴。

</details>

<details>
<summary>2. 保留本章的 X,W，把偏置改成 (0,0)，第二条记录的输出是多少？batch 结果哪一轴会改变长度？</summary>

第二条记录是 $(3,4)^\top$，故 $Wx=(-1,6)^\top$。偏置改变输出数值，不改变轴长度；$Z$ 仍是 `(3,2)`。若增加或删除记录，只改变第一轴 $B$，权重和输出特征轴都不变。

</details>

<details>
<summary>3. X:(2,4,5) 经 W:(3,5) 的共享线性层后是什么形状？它会混合四个位置吗？</summary>

每个位置的 5 个特征映到 3 个输出，故结果 `(2,4,3)`。运算只沿最后的特征轴求和，批轴和位置轴都保留，因此不会混合四个位置；位置之间要交换信息，需要另外定义跨位置运算。

</details>

<details>
<summary>4. prediction:(2,1) 与 target:(2,) 数值看起来一一对应，为什么直接相减仍不对？</summary>

广播从右对齐，`(2,1)` 与 `(2,)` 变成 `(2,2)`，每条预测都与两个目标相减。应把目标变成 `(2,1)` 或把预测变成 `(2,)`，然后断言形状一致；只比较元素总数会漏掉这个错误。

</details>
