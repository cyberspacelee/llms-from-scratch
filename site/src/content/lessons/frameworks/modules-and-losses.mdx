[F3 张量](/frameworks/torch-tensors/) 已经讲过轴，[F4 自动微分](/frameworks/autograd/) 已经讲过计算图。现在把这些计算放进一个能训练和保存的模型：输入是两条长度为 3 的 token ID 序列，输出每个位置对四个类别的 logits（softmax 前的原始分数），其中两个目标位置不参与损失。读完本章，你应能从模块树列出全部参数、手算一个位置的分数，并说明损失为什么除以 4。

本章的目标是核对 **PyTorch 的层与损失接口**。这里的目标 ID 已直接给定，只是逐位置分类；构造“当前位置预测下一 token”的移位目标见 [P2](/principles/language-modeling/)。模型没有注意力，所以每个位置单独经过同一组参数。记批大小 $B=2$、序列长度 $T=3$、词表大小 $V=4$、隐藏宽度 $d=2$：

| 样本 | 输入 ID | 目标 ID |
| --- | --- | --- |
| 0 | `[0,1,2]` | `[0,1,-100]` |
| 1 | `[1,0,0]` | `[1,0,-100]` |

`-100` 是本例的 `ignore_index`，表示这个位置不计入交叉熵；它不是词表中的第五类。输入与目标形状都是 `(2,3)`，但承担不同工作：输入索引查 embedding，目标索引选正确类别。

## 建立一个能遍历参数的模型

`nn.Module` 的 `__init__` 在调用 `super().__init__()` 后，把子层赋给属性，便将它们登记在模块树中。`forward` 规定数据如何流经这些层。模型调用写 `model(ids)`，它会执行模块调用流程和 `forward`；不要为了运行模型而直接调用 `model.forward(ids)`。

```python
class TinyWords(nn.Module):
    def __init__(self):
        super().__init__()
        self.embedding = nn.Embedding(4, 2, dtype=torch.float64)
        self.norm = nn.LayerNorm(2, eps=1.0, dtype=torch.float64)
        self.dropout = nn.Dropout(0.5)
        self.head = nn.Linear(2, 4, bias=False, dtype=torch.float64)

    def forward(self, ids):
        x = self.embedding(ids)  # (B,T,2)
        x = self.norm(x)         # (B,T,2)
        x = self.dropout(x)      # (B,T,2)
        return self.head(x)      # (B,T,4)
```

这是一个逐位置模型：`Linear` 只改变最后一个轴，不把三个位置接成一个长向量。为便于手算，脚本在 `torch.no_grad()` 下给参数写入固定值，并使用 float64。`eps=1` 比常见配置大，只是让数字简洁；这里不讨论哪组配置训练效果好。

<Figure src="frameworks/module-tree.svg" alt="TinyWords 的登记树依次包含 embedding、norm、dropout 和 head；各节点标出参数形状与数量">沿连接线读模块树：前三个带参数节点分别贡献 8、4、8 个标量，Dropout 不贡献参数；整棵树共 20 个参数标量。</Figure>

`model.named_parameters()` 给出的名字为 `embedding.weight`、`norm.weight`、`norm.bias`、`head.weight`。形状依次是 `(4,2)`、`(2,)`、`(2,)`、`(4,2)`，所以参数数目是 $8+2+2+8=20$。`model.parameters()` 返回这四个参数对象，供优化器使用；`model.state_dict()` 给出这四个名字与对应张量，供保存或加载状态。当前模型没有 buffer；若有需要随模型迁移、保存但不训练的张量，可用 `register_buffer` 登记，它会进入默认的 `state_dict`，不会进入 `parameters()`。训练/评估模式标志本身不在本例的 `state_dict` 里，加载后还要明确设置模式。

为什么不能只依赖 `backward()` 是否成功来判断参数登记？自动微分根据**这次执行的张量计算图**求导，模块树则决定父模型能遍历哪些对象。把层存进普通 Python list，前向仍能调用、权重仍能得到 `.grad`，但父模型的 `parameters()` 和 `state_dict()` 不会递归找到它，父模型 `eval()` 也不会切换这个子层。需要可索引的子层集合时用 `nn.ModuleList`；纯顺序链条可用 `nn.Sequential`。两者都负责登记，只有 Sequential 自带顺序前向。`nn.Parameter` 赋给模块属性会登记为参数；一个普通 `Tensor` 即使 `requires_grad=True` 也不会自动登记。

## 查表并按最后一轴做 LayerNorm

`nn.Embedding(4,2)` 的参数表有四行、每行两个数。输入是整数 ID，输出是相应行，不是把 ID 的数字大小当连续特征。本例固定表为

$$
E=\begin{bmatrix}
2&0\\
0&2\\
2&0\\
0&0
\end{bmatrix}.
$$

于是样本 0 的三个位置先得到 $(2,0),(0,2),(2,0)$；样本 1 得到 $(0,2),(2,0),(2,0)$。第一行和第三行数值相同，但仍是**不同参数行**。两个样本里重复的 ID 0 都读取同一行；反向传播时，来自这些使用位置的梯度会相加。没有读取的第 3 行不会因查表而得到梯度；只在本例被忽略位置读取的第 2 行也没有来自本损失的梯度，因为本模型没有跨位置混合。若加上注意力，这一推断就需重新检查依赖路径。

`nn.LayerNorm(2)` 对每个 $(b,t)$ 的两个**特征**分别求均值和方差，不跨样本或位置求统计量。对 $x=(x_1,x_2)$，本例默认缩放 $\gamma=(1,1)$、偏移 $\beta=(0,0)$，定义为

$$
\mu=\frac{x_1+x_2}{2},\qquad
v=\frac{(x_1-\mu)^2+(x_2-\mu)^2}{2},\qquad
y_j=\gamma_j\frac{x_j-\mu}{\sqrt{v+\epsilon}}+\beta_j.
$$

$x=(2,0)$ 时 $\mu=1,v=1,\epsilon=1$，所以 $y=(s,-s)$，$s=1/\sqrt2\approx0.707107$；$(0,2)$ 得 $(-s,s)$。方差分母是特征数 2，对应 `correction=0`，不是统计估计时的样本方差修正。可学习的 $\gamma,\beta$ 分别是刚才登记的 `norm.weight`、`norm.bias`。加上 $\epsilon$ 和 affine 后，输出一般不能声称精确零均值、单位方差；常量输入的归一化部分为零。

此处输入 ID 的 dtype 是 `torch.long`，因为 Embedding 要索引；输出 dtype 跟随参数，本例是 float64。不要把输入 ID 转成 float64 来追求“精度一致”。若设置 `padding_idx`，它只改变指定 embedding 行的梯度行为，不会自动令这个位置的目标被交叉熵忽略；损失仍须单独设置 `ignore_index`。

## Dropout 的模式决定使用哪条数值路径

训练模式下，`nn.Dropout(p=0.5)` 对输入每个元素随机输出 0 或保留值的两倍，保留值乘 $1/(1-p)$ 使单元素期望不变；它不保证每次恰好丢掉一半。这样 logits 每次可能变化，不方便核对手算。下面先调用 `model.eval()`：Dropout 成为恒等映射，上一节的 $(s,-s)$ 原样进入输出层。

`eval()` 只是递归设置已登记模块的 `training=False`，没有关闭 autograd。脚本在 eval 模式下对损失执行 `backward()`，仍得到参数梯度；真正只做推理时再用 `torch.no_grad()` 等梯度上下文。[F4](/frameworks/autograd/) 解释后者的计算图边界。切回 `model.train()` 后，Dropout 再启用；脚本用固定种子核对 1 的输出只可能是 0 或 2。若在 `forward` 中改用函数式 `F.dropout(x)`，必须显式传 `training=self.training`，否则它不会读取父模块的模式。

## Linear 把每个隐藏向量映到四类 logits

输出头的固定权重没有 bias，形状为 `(out_features,in_features)=(4,2)`：

$$
W=\begin{bmatrix}
1&0\\
0&1\\
0&0\\
0&0
\end{bmatrix},\qquad z=Wy.
$$

对列向量 $y=(s,-s)$，得到 $z=(s,-s,0,0)$；对 $y=(-s,s)$，得到 $(-s,s,0,0)$。批输入按行排，所以代码中的输出是 `x @ head.weight.T`，形状从 `(2,3,2)` 变成 `(2,3,4)`。$W$ 对全部六个位置共享，参数数目不会乘以 $B T$。[M3](/math/linear-algebra/) 推导了这一批行布局。

把固定模型输出与目标并排看，便能检查后续损失到底读取哪一项：

| $(b,t)$ | 输入 ID | 四个 logits | 目标 |
| --- | --- | --- | --- |
| (0,0) | 0 | $(s,-s,0,0)$ | 0 |
| (0,1) | 1 | $(-s,s,0,0)$ | 1 |
| (0,2) | 2 | $(s,-s,0,0)$ | 忽略 |
| (1,0) | 1 | $(-s,s,0,0)$ | 1 |
| (1,1) | 0 | $(s,-s,0,0)$ | 0 |
| (1,2) | 0 | $(s,-s,0,0)$ | 忽略 |

这些 logits 不是概率，也不需要每行和为 1。例子里目标 0、1 恰好是最高分，但其预测概率仍小于 1，损失仍大于零。

## 从类别轴到有效目标平均

对一个有效位置，类别索引目标 $y$ 的交叉熵先在四个 logits 上做 softmax，再取正确类别的负对数：

<KeyEq label="单个位置的类别索引交叉熵">
$$
p_c=\frac{e^{z_c}}{\sum_{r=0}^{V-1}e^{z_r}},\qquad
\ell=-\log p_y=\log\sum_{c=0}^{V-1}e^{z_c}-z_y.
$$
</KeyEq>

以 $(0,0)$ 为例，四个指数的和是 $e^s+e^{-s}+2\approx4.521184$；正确类别概率 $e^s/(e^s+e^{-s}+2)\approx0.448581$，所以 $\ell\approx0.801667$。其余三个有效位置仅交换前两类，正确类别分数仍为 $s$，损失相同。实现时将**logits** 直接交给 `F.cross_entropy`；API 内部使用稳定的等价计算。先对 logits 做 softmax 再传进去，会把概率数值当成一组新 logits，算的是另一个损失。

`F.cross_entropy` 对多维索引目标把第 1 轴当类别轴。模型给的是 `(B,T,V)=(2,3,4)`，直接传入会把长度为 3 的 $T$ 误认成类别数。可将每个位置展平成一行 `(B*T,V)`，目标展平为 `(B*T,)`：

```python
flat_logits = logits.reshape(-1, logits.shape[-1])
flat_targets = targets.reshape(-1)
loss = F.cross_entropy(flat_logits, flat_targets, ignore_index=-100)
```

也可以将类别轴移到第 1 轴，调用 `F.cross_entropy(logits.transpose(1, 2), targets, ignore_index=-100)`，此时输入是 `(2,4,3)`，目标仍是 `(2,3)`。脚本核对两种调用相等。若恰巧 $T=V$，某些错误轴排列可能通过形状检查，因此还应追踪某个位置手算的 logits 与目标。不能仅凭“代码没报错”判定监督对齐。

本例有效位置集合是 $(0,0),(0,1),(1,0),(1,1)$，共四个。无类别权重、无标签平滑时，`reduction='none'` 给六个逐位置损失，忽略位置返回零；`sum` 是四项相加；`mean` 用**四个有效目标**做分母：

$$
L=\frac{\sum_{(b,t):\,y_{bt}\ne-100}\ell_{bt}}{4}
\approx0.801667.
$$

把两个零也计入分母 6，会错误地得到约 $0.534445$，并缩小梯度。忽略位置只取消这个位置的损失项；有效位置的 softmax 仍在全部四个类别上求和。`ignore_index=-100` 不是删除一个类别，也不自动决定注意力 mask。若使用类别权重，索引目标的 mean 分母还会变为有效目标权重之和；本例明确没有类别权重。下一 token 任务还须先按 [P2](/principles/language-modeling/) 的定义移位输入与目标，交叉熵不会替你移位。

### 全部忽略时先定义训练代码的行为

若一批目标全是 `-100`，有效数量为零，数学上的有效平均没有定义；直接用 `reduction='mean'` 会得到 NaN。这个示例选择返回**与 logits 计算图相连的零损失**，使该项的梯度为零。做法是先以 `reduction='sum'` 求有效和，再除以 `valid.sum().clamp_min(1)`；有有效目标时与通常 mean 相同，全忽略时为 $0/1=0$。它不代表训练循环应照常做优化器更新：若还有其他损失或权重衰减，整步行为要另行决定。

完整脚本的 `token_loss` 还检查目标形状、long dtype、设备和有效类别范围。训练数据进入信任边界后，这些错误应尽早报出，而不是等到框架在错误轴上计算。这里没有把概率目标、类别权重、标签平滑或空 batch 混入示例；需要这些功能时先明确新的目标和分母。

## 运行核对与常见错误

<CodeFile path="code/frameworks/modules_and_losses.py" />

在仓库根运行 `python code/frameworks/modules_and_losses.py`。脚本核对 20 个参数、六行固定 logits、四个有效损失、两种类别轴调用、eval 仍可求导、train 的 Dropout 行为，以及全忽略零梯度。它也构造普通 list 持有层的反例：子层得到梯度，父模块却没有登记任何参数。即使当前模型的单个损失数值正确，仍需分别核对这些结构和轴契约。

<details>
<summary>把第 (0,1) 个目标从 1 改为 0，损失会怎样变？</summary>

该位置 logits 是 $(-s,s,0,0)$，分母仍是 $e^s+e^{-s}+2$，目标分数从 $s$ 变为 $-s$，所以这一项增加 $2s$。四个有效目标的平均损失增加 $2s/4=s/2\approx0.353553$。分数不变，改变的是选取哪一类的对数概率。

</details>

<details>
<summary>若把 (0,2) 的目标从 -100 改成 0，新的有效平均怎样写？</summary>

它的 logits 是 $(s,-s,0,0)$，目标 0 的损失也为 $0.801667$。有效和增加这一项，分母从 4 变 5，因此本组固定参数的平均数恰好不变。一般数据中恢复一个目标会同时改变分子和分母，不能只把 4 改为 5。

</details>

<details>
<summary>为什么同一 ID 0 在输入中出现三次，却不能说它的 embedding 梯度等于三份有效贡献？</summary>

位置 (0,0) 和 (1,1) 有损失，位置 (1,2) 被忽略。本模型逐位置独立，所以最后一个位置没有通向有效损失的路径，只有前两个位置对同一参数行贡献梯度。若模型有跨位置注意力，被忽略位置仍可能影响其他位置的预测，届时必须按计算图重新判断。

</details>
