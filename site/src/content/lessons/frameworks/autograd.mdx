同一段代码 `y=x*x+3*x`，当 x 为 2 时，y 是 10，导数是 7。为什么调用两次 `backward()` 后，x 的梯度有时变成 14，有时却直接报错？为什么 `clone()` 复制了数据却仍把梯度传回原变量，而 `detach()` 没复制数据却让某条求导路径停止？这些现象来自三个相互独立的关系：数值与存储关系、计算历史、梯度缓冲区。

先读 [F3 张量与轴](/frameworks/torch-tensors/) 与 [M6 反向传播](/math/backprop/)。数学章解释链式法则，本章将它对应到 PyTorch API：谁参与记录、反向从哪个种子开始、结果放在哪里、哪些状态在一次迭代后仍存活。CPU 脚本使用 float64，验证版本为 PyTorch 2.14.0+cpu；不依赖 GPU，不涉及自定义求导函数或高阶自动微分。

## 记录计算：requires_grad 与叶子各管什么

自动微分（automatic differentiation）在执行前向时记录可求导操作及其依赖，再按链式法则传播反向信息。它不是把你的 Python 文件完整保存一遍，也不是先展开所有可能分支。动态图（dynamic graph）跟随本次实际执行路径构建：这次没有执行的分支，不出现在这次图中。

`requires_grad=True` 表示张量需要参与求导。对一般默认梯度模式中的可微操作，只要有需要求导的输入，输出就会记录相应求导关系。普通整数或 bool 张量不能作为浮点参数那样开启梯度。输入是否需要导数与数值是否会被用于计算是两件事：常量也影响结果，只是不接收该路径的梯度。

```python
x = torch.tensor(2., dtype=torch.float64, requires_grad=True)
y = x * x + 3 * x
assert x.is_leaf
assert not y.is_leaf
assert y.grad_fn is not None
```

叶子（leaf）是求导图中按框架规则作为源头的张量。用户直接创建并要求求导的 x 是典型叶子；由可微操作产生的 y 是非叶子，`grad_fn` 指向产生它的反向节点。所有 `requires_grad=False` 的张量按惯例也是叶子，但这不意味着它们会获得梯度。不要把“叶子”单独看成“可训练”的同义词。

`grad_fn` 是计算历史的入口，不是已经算好的导数；前向刚完成时，x 的 `.grad` 仍然是 None。`is_leaf` 也不等于“数据是独立副本”。F3 中的连续视图、设备转换和 clone，都可能保留历史并成为非叶子。若先创建需要求导的 CPU 张量，再对它做一次可微的设备转换，新的结果不一定是你希望优化器直接持有的叶子参数。通常在目标 dtype/device 上直接创建参数更明确。

### 为什么中间结果默认没有 .grad

反向会计算经过中间节点的梯度贡献，但默认只把结果累计到需要求导的叶子 `.grad`。中间 y 不自动保留一个长期可读的梯度缓冲区，避免为所有中间张量都持有额外结果。想观察中间量可调用它的 `retain_grad()`，或直接请求 `autograd.grad`；这与保留计算图的 `retain_graph` 是两个不同接口。

观察 `.grad` 前先问三个问题：张量是否要求梯度，它是不是默认累计的叶子，本次反向是否真的经过它。看到 None 不等于导数数学上为零；它可能还没有执行反向、没有参与这次损失，或者只是没有要求保留中间结果。将 None 和零混在一起，会让参数遗漏和正常稀疏参与变得难以区分。

## 标量反向：同一变量的多条路径要相加

令 $y=x^2+3x$。在前向图中，x 经过平方分支与线性分支，最后相加。输出变化一个单位，对两条输入分支各提供一个单位的反向种子；平方分支传回 $2x$，线性分支传回 3。因此

$$
\frac{dy}{dx}=2x+3.
$$

当 x=2，平方贡献 4，线性贡献 3，总导数是 7。变量重复出现不是选择其中一条贡献，也不是对两个贡献取平均。它们共同解释 x 对输出的影响，必须在汇合位置相加。这种**一次反向中的分支相加**和后面**多次 backward 的缓冲累积**是不同层次。

<AutogradBranchLab client:visible />

实线从叶子流向两条分支，再到 y；虚线逆着依赖传播，旁边显示两条路径的贡献。默认 x=2、种子 g=1，当前 `.grad` 初始为零的教学显示；按一次“重新前向并 backward”后为 7，再按一次为 14。按钮每次先建立新的前向图，才做反向，不是对已经释放保存值的同一个 y 硬调第二次。

把种子 g 改成 2，这次平方贡献变为 8，线性贡献变为 6，总增量为 14；把 x 改成 -2，种子仍为 1，导数是 -1。改变输入或种子不会自动删除已经存下来的旧 `.grad`，所以交互特意让清空作为独立命令。图是显式手算模型，不在浏览器里执行 Torch。

```python
y.backward()
assert x.grad.item() == 7
```

单元素、实数输出可不提供参数，框架使用数值为一的反向种子。它对应“求这个标量本身对叶子的导数”。如果你想求 $2y$ 对 x 的导数，也可以给 y 传一个同形状的种子 2；不是把学习率当作种子随便修改，种子定义的是本次要求的导数对象。

## 向量输出：backward 传播的是 VJP

多元素输出没有唯一的“一个梯度”，每个输出分量都对应一行雅可比矩阵。设输入 $x\in\mathbb R^n$，输出 $y\in\mathbb R^m$，雅可比矩阵为 $J\in\mathbb R^{m\times n}$。反向接口给输出一个同形状向量 $g$，返回的是向量雅可比积（vector-Jacobian product，VJP）：

<KeyEq label="反向种子定义本次要求的导数">
$$
\nabla_x(g^\top y)=J^\top g.
$$
</KeyEq>

这里沿用本讲义列向量记法，结果是 $J^\top g$。它不要求把整个 J 显式存出来，也不表示对 y 每个元素分别做一次独立 backward。若把 g 当作常量，上式就是加权标量输出对 x 的梯度。种子 shape 必须与输出匹配，dtype/device 也要满足接口；本章使用同设备同 dtype，避免隐含转换。

具体取

$$
y_0=x_0^2+x_1,\qquad y_1=x_0x_1,\qquad x=(2,-1),\quad g=(2,3).
$$

此时 $y=(3,-2)$，雅可比为

$$
J=\begin{bmatrix}2x_0&1\\x_1&x_0\end{bmatrix}
=\begin{bmatrix}4&1\\-1&2\end{bmatrix},\qquad
J^\top g=\begin{bmatrix}5\\8\end{bmatrix}.
$$

第一输入收到 $4\cdot2+(-1)\cdot3=5$，第二输入收到 $1\cdot2+2\cdot3=8$。`y.backward(torch.ones_like(y))` 求的是各输出之和的梯度；如果种子是 `(2,3)`，求的是 $2y_0+3y_1$。两者都合法，但问题不同。输出没有缩成标量时省略种子会报错，这是在要求你明确导数对象。

```python
x = torch.tensor([2., -1.], dtype=torch.float64, requires_grad=True)
y = torch.stack([x[0]**2 + x[1], x[0]*x[1]])
g = torch.tensor([2., 3.], dtype=torch.float64)
gradient, = torch.autograd.grad(y, x, grad_outputs=g)
assert gradient.tolist() == [5., 8.]
assert x.grad is None
```

`autograd.grad` 返回指定输入的梯度，不像 `backward` 那样把这些返回结果累计到输入 `.grad`。它适合局部数学核对或需要直接使用梯度值的算法。返回的是元组，所以 `gradient, = ...` 解包唯一输入的结果。被请求输入必须满足求导契约；未使用输入的处理由 `allow_unused` 等参数决定，不能拿空结果伪装成一条实际执行的依赖。

有限差分也能检验这个 VJP。先构造标量 $f(x)=2y_0+3y_1$，分别沿 x 的两个坐标加减一个小量，再用中心差分近似偏导。要核对的是同一个标量函数，不能用一个输出的差分去比较另一个种子的 VJP。float64 与合适步长能降低舍入和截断的干扰，但有限差分本身仍是近似，不适合盲目使用极小步长。

## 梯度缓冲：为什么两批数据会留下相加的结果

一次 `backward` 完成后，叶子的 `.grad` 保留结果，下一次反向默认继续相加。假设两次都在 x=2 重新计算 $x^2+3x$，每次贡献 7，那么第二次之后 `.grad` 是 14。这允许把几个小批量的损失梯度积累起来，再执行一次更新；但如果本来想让每一步独立，它也会造成意外叠加。

```python
x = torch.tensor(2., dtype=torch.float64, requires_grad=True)
(x*x + 3*x).backward()
assert x.grad.item() == 7
(x*x + 3*x).backward()  # 新的前向图
assert x.grad.item() == 14
x.grad = None
(x*x + 3*x).backward()
assert x.grad.item() == 7
```

清空的方法可以是把 `.grad` 设为 None，也可以对已有梯度张量清零。优化器常用 `zero_grad(set_to_none=True)` 管理所有参数，完整训练循环见 [F6](/frameworks/data-and-training/)。None 表示尚没有本轮保存的梯度，零表示已有缓冲区且数值是零；有些优化器对参数梯度 None 与零的行为不同，尤其涉及是否跳过参数以及状态更新时，因此不要把二者当作完全相同的状态。

梯度积累还需要损失尺度正确。假设两个等大小小批量的平均损失分别为 $L_1,L_2$，直接各 backward 一次得到 $\nabla L_1+\nabla L_2$；若目标是合并大批量平均损失，应该对应 $\nabla(L_1+L_2)/2$。最后一个小批量更小时还要按样本数加权。autograd 会忠实求出你写下的标量，不会自动猜测你想平均多少样本。

`backward` 本身不更新参数，也不读取学习率。优化器的 `step()` 才按梯度与状态执行更新。把清空、前向、反向、更新四个动作分开，才能解释参数为什么变化、梯度为什么累积。需要多次积累时延后更新；需要独立步骤时在适当位置清空。这属于训练协议，不能通过在某个张量上设置一个标志自动完成。

## 图的生命周期：保存值释放不等于梯度清空

反向节点可能需要前向值。例如平方的局部导数依赖 x，乘法导数依赖另一输入。为了反向，框架保存必要数据；默认反向完成后，会释放相关保存值以节省内存。Python 变量 y 仍然存在，甚至还能看到 `grad_fn`，也不意味着所有求导所需数据仍可再次使用。

<Figure src="frameworks/autograd-lifetime.svg" alt="前向保存值、反向传播并累加叶子梯度、释放保存值，再建立下一次前向图">顺着三个框看一次迭代；底部箭头表示下一次重做前向。释放保存值与清空叶子梯度是两个独立动作，叶子 .grad 可以跨多次前向累积。</Figure>

对同一个平方结果 y 连续反向，第二次一般会报“再次经过已释放的图”一类错误。有些简单图不保存需要释放的值，第二次可能碰巧成功，也不能据此把复用旧图当成普通训练协议。最清楚的循环是在每批数据上重做前向，产生本次的新图，再反向。

`retain_graph=True` 保留图的必要保存状态，用于确实需要多次访问同一前向图的场景，代价是延长内存生命周期。它不是“梯度要积累”的必要条件，更不是发现第二次 backward 报错后就应加入的通用修复。梯度积累可以在多个新图之间自然发生。如果训练循环把旧损失或中间张量无限装进列表，保留历史还可能让内存持续增长；记录数值时应按目的使用 `item()` 或脱离历史的结果。

本章不使用 `create_graph=True`。这个参数涉及把求导过程本身纳入新的可微关系，以便进一步求高阶导数；它与保存同一前向的 `retain_graph` 又是不同目的。先把一阶 VJP、保存值与叶子缓冲理解清楚，才能安全引入更复杂的生命周期。

## Detach 与 clone：历史和存储可以分别选择

`detach()` 返回脱离当前求导历史的张量，**与原张量共享存储**。它不会复制数值，也不会使原张量从此失去 `requires_grad`。`clone()` 则复制数据，在默认梯度模式下仍是可微操作；若输入要求梯度，clone 的输出可以把梯度传回源输入。

| 操作 | 是否独立存储 | 是否保留到源输入的求导路径 |
| --- | --- | --- |
| `x` 的普通引用 | 否 | 与原对象相同 |
| `x.clone()` | 是 | 是，输入需要梯度时 |
| `x.detach()` | 否 | 否 |
| `x.detach().clone()` | 是 | 否 |

例如 `clone.sum().backward()` 会给原 x 的每个元素贡献一。复制解决的是别人修改数据会不会传播，求导路径解决的是输出依赖哪一个输入；二者不冲突。若需要一个与旧图无关、数据也独立的新可求导输入，可以 `x.detach().clone().requires_grad_()`，得到新叶子。

detach 的共享性尤其影响原地写入：对 detached 结果改一个数，也改了原张量对应的存储。如果旧图保存了这个值以便求导，后续反向可能触发版本检查错误。不要将 detach 理解为“随便修改而不影响训练”。用于独立日志或缓存时，若后续存在可变写入需求，就把共享关系也明确切开。

## 梯度模式与 eval：三种开关控制不同层次

默认梯度模式（grad mode）根据输入的 `requires_grad` 记录可微操作。`torch.no_grad()` 在其上下文中关闭反向图记录，常用于参数更新或不需要梯度的前向。离开上下文后，原参数仍可求导；模式是执行上下文，不是永久把所有参数改成常量。

```python
x = torch.tensor(2., dtype=torch.float64, requires_grad=True)
with torch.no_grad():
    y = 3*x
assert not y.requires_grad
assert x.requires_grad
```

还有一个容易忽略的例外：创建新张量的工厂函数若显式传入 `requires_grad=True`，不按一般算术的方式受 no_grad 覆盖。所以理解规则时区分“已有张量执行运算”与“显式创建新的需要求导对象”。用上下文包住整个模块构造，也不表示新建的 Parameter 永远不训练。

`torch.inference_mode()` 除了关闭反向记录，还减少视图跟踪和版本计数等开销。它有更强的限制：其中创建的 inference tensor 不能任意拿到后续记录梯度的计算中作为求导保存对象。若输出还要回到训练路径，应核对用途并选择 no_grad 或在模式外建立普通独立张量，而不是把两者当作可以不加思考互换的提速开关。

`model.eval()` 则切换模块的训练行为，例如 Dropout 与 BatchNorm，**不会关闭 autograd**。一个处于 eval 的线性模块，其参数仍可要求梯度，前向输出仍可带 `grad_fn`；反过来，在 no_grad 下执行一个 train 模式模块，Dropout 仍按训练规则随机丢弃。模块行为与记录梯度分别设置，推理常同时使用 eval 和相应梯度模式，但它们各有职责。更多模块细节见 [F5](/frameworks/modules-and-losses/)。

## 原地操作：版本检查保护哪些依赖

带下划线的操作通常原地改张量，例如 `add_`、`copy_`。对要求梯度的叶子在默认模式中直接原地更新通常会被拒绝；正确参数更新可放在 no_grad 下，但仍必须处在本轮反向完成之后。no_grad 不会让数据依赖消失，只是不建立这次更新的求导图。

设 `saved=x*x` 保存了 x，随后通过 `x.detach().add_(1)` 改了共享存储。反向要计算 $2x$，需要前向时的 x，不能静默使用已经改过的值。框架用版本计数检测许多这样的修改并报错，告诉你保存值不再匹配。这个报错是正确性保护，不应通过 `.data` 或额外 `retain_graph` 绕开。

有的原地操作在特定依赖下合法，不能简单宣称所有原地都禁用；但对初学实现，优先用返回新结果的普通运算，等确实测到内存压力再分析修改时序。外部 NumPy 共享写入等路径也不应指望 autograd 捕获所有错误，所以 F3 中的别名生命周期仍然重要。程序正确不能只建立在“框架没报错”上。

### 先检查无效计算，再决定是否屏蔽输出

自动微分跟随已执行的算术。若先算 `x/0`，然后用 mask 把结果从损失里排除，并不保证反向就能安全忽略除零。无效操作已经进入图，局部导数可能产生无穷或 NaN，与来自后续的零贡献相乘仍可能污染梯度。更可靠的做法是让无效分支根本不执行该算术，或先构造数学上有定义的安全分母，再对有效位置计算。

同样，张量里只要某个位置出现 NaN，就不能仅因为最后损失是有限数而断言所有参数梯度有限。前向值、目标定义与反向值都应按需求检查。这里的原则与全屏蔽 softmax 相同：先定义边界处的计算，再写掩码表达，而不是让未定义中间值进入历史后希望最后一步清理干净。

需要定位复杂训练中的无效反向时，可以在小输入上使用 autograd 的异常检测辅助寻找产生错误的节点，代价是额外运行开销。它不应被当作常规性能模式，也不替代手算和有限差分。先缩小输入、重做一次前向与反向，检查第一个不满足数学契约的位置，比对所有参数统一放宽容差更有解释力。

还要区分“没有梯度”与“梯度暂时没有保存”。一个与损失完全断开的输入，不会因为需要梯度就自动得到这次贡献；一个非叶子中间量则可能确实参与反向，只是没有 retain_grad。排查时从损失沿依赖往回追踪到目标输入，再检查保存策略，不能看到 .grad 为 None 就给所有中间张量都开保留。

如果新版本改变了分支条件，计算图也可能随本轮输入改变。这是动态图的正常行为，要求测试覆盖会执行的路径。不要拿另一次输入的 grad_fn 或旧梯度推断当前前向的依赖，日志记录应同时标明本轮输入与是否已经清空缓冲。

## 常见误区

- `.grad=None` 不等于数学梯度零，先核对叶子、参与路径与反向是否执行。
- 一次图内多路贡献相加与多次 backward 跨图累积属于不同层次。
- `backward` 不更新参数，`step` 不自动清空梯度，`eval` 不自动关闭记录。
- 复制数据不自动停止梯度，停止梯度不自动复制数据。
- 保留旧图不是普通梯度积累的必要条件，重做前向与清空梯度要分别决定。
- 版本检查报错要求重新安排写入时序，不能用 `.data` 隐藏依赖。

## 练习与核对

<details>
<summary>x=2 时，y=x²+3x 的两条反向贡献是什么？种子改成2后呢？</summary>

种子一时是 4 与 3，总和 7；种子二时是 8 与 6，总和 14。种子定义输出标量的权重，所以所有经过该输出的反向贡献一起缩放。
</details>

<details>
<summary>同一个 y 第二次 backward 报错，为什么梯度积累例子却能得到14？</summary>

积累例子第二次先重做前向，产生新的保存值和新图。两次反向都向同一叶子 .grad 加贡献，旧图的保存值释放不影响这种跨新图累积。
</details>

<details>
<summary>autograd.grad 返回 (5,8) 后，为什么 x.grad 仍然为None？</summary>

该接口把指定输入的梯度作为返回值交给调用者，不把它累计到叶子的 .grad。若需要 .grad 累积，使用相应 backward 路径；不要把返回值与状态缓冲混用。
</details>

<details>
<summary>为了修改一份缓存而不影响源张量，也不保留旧图，选择clone还是detach？</summary>

单独 clone 复制存储但保留可微路径，单独 detach 停止路径但共享存储。两项需求都满足时用 detach().clone()；若还要新变量可求导，再对它 requires_grad_()，它成为独立叶子。
</details>

<details>
<summary>eval 下的模型能不能计算梯度？no_grad 下 train 模型的Dropout是否关闭？</summary>

eval 不关闭 autograd，所以参数可继续接收梯度。no_grad 只关闭该上下文中的反向记录，train 模式的 Dropout 仍按训练行为工作。两个开关控制不同问题。
</details>

<details>
<summary>反向前通过detach结果修改原输入，为什么也可能报版本错误？</summary>

detach 与原输入共享数据。旧图可能保存了原输入用于局部导数，修改后它不再是前向时的值。停止新路径求导不意味着可以改写已有路径需要的保存值。
</details>
