在 [M9 反向传播](/math/backprop/) 中，我们沿计算图手算过梯度；[F3 张量与轴](/frameworks/torch-tensors/) 又说明了张量可能共享存储。本章把两件事接到 PyTorch：同一个损失为什么能求出多个参数的梯度，为什么再次反向可能报错，以及 `detach()`、`clone()`、`no_grad()` 分别改变了什么。读完后，你应能先手算一个小图，再预测每个 API 调用后的 `.grad` 和数据共享关系。

以下始终使用同一组数。输入 $x=(2,-1)$ 是固定数据，参数 $w=(1,2)$ 与共享偏置 $b=1$ 需要求导。先算两个中间值，再让第一个中间值进入两条分支：

$$
u=w\odot x+b=(3,-1),\qquad
s=u_0^2+u_0u_1=9-3=6,\qquad
L=\tfrac12(s-2)^2=8.
$$

$\odot$ 是逐元素乘，标量 $b$ 广播到 $u$ 的两个坐标；目标值固定为 2。这里 $u_0$ 被平方项和乘积项各使用一次，$b$ 也进入了两个坐标。这个小图足以显示分支汇合、向量反向和广播归约。

## 前向记录：哪些张量是叶子

PyTorch 在本次前向执行可微操作时建立计算图，反向时沿已执行的依赖使用局部导数。它不会提前记录未走过的 Python 分支。`requires_grad=True` 表示我们要追踪某个浮点张量的梯度；它并不表示该张量的数值已被更新。

```python
import torch

dtype = torch.float64
x = torch.tensor([2., -1.], dtype=dtype)
w = torch.tensor([1., 2.], dtype=dtype, requires_grad=True)
b = torch.tensor(1., dtype=dtype, requires_grad=True)
u = w * x + b
s = u[0]**2 + u[0] * u[1]
loss = 0.5 * (s - 2)**2
assert u.tolist() == [3., -1.] and loss.item() == 8.
```

直接创建的 `w`、`b` 是需要求导的叶子（leaf）；`u` 和 `loss` 是运算产生的非叶子，`grad_fn` 指向它们的反向关系。前向结束时 `w.grad` 与 `b.grad` 都是 `None`，因为导数还未传播。`u.grad` 默认也不会被长期保存：中间节点参与计算，不等于框架要为它留一个公开的梯度缓冲区。想在这次反向后观察 $\partial L/\partial u$，须在反向前调用 `u.retain_grad()`。

这里 `x.requires_grad=False`，反向不会在 `x.grad` 保存结果；数学上仍可求 $\partial L/\partial x$。这说明“数值影响损失”和“要求保存该输入的梯度”是两项选择。整数 token ID 也可影响模型结果，但不按浮点参数的方式开启梯度。

## 手算反向：两条贡献在哪里相加

先从标量损失返回 $s$：$\partial L/\partial s=s-2=4$。平方分支对 $u_0$ 的局部导数是 $2u_0=6$，乘积分支对 $u_0$ 是 $u_1=-1$，对 $u_1$ 是 $u_0=3$。因此两条到 $u_0$ 的贡献为 $4\cdot6=24$ 与 $4\cdot(-1)=-4$；到 $u_1$ 的贡献为 $4\cdot3=12$。

<KeyEq label="分支求和与广播归约">
$$
g_u=\nabla_u L=(24-4,12)=(20,12),\qquad
g_w=g_u\odot x=(40,-12),\qquad
g_b=20+12=32.
$$
</KeyEq>

两个 $b$ 是同一个叶子参数，不是两份偏置，所以其梯度是两个坐标的贡献之和。若也要求输入梯度，则 $g_x=g_u\odot w=(20,24)$；本例的 `x` 不存它。分支内求和与批次之间的梯度累积都用加法，但发生在不同位置：前者是在**一次图的反向**中汇合，后者是把**多次反向**写入同一个叶子缓冲区。

这个计算也说明反向为什么常被称为 VJP（vector-Jacobian product）。从 $u$ 到 $s$ 的雅可比矩阵在本例只有一行，$J_{s,u}=(2u_0+u_1,u_0)=(5,3)$；上游种子 $g_s=4$，所以 $J_{s,u}^{\top}g_s=(20,12)$。若中间输出有更多坐标，反向仍逐节点计算这种乘积，无须先存出完整雅可比矩阵。

对于向量输出，种子还定义了你要对哪个标量求导。若单独调用 `torch.autograd.grad(u, (w,b), grad_outputs=torch.tensor([20.,12.], dtype=dtype))`，它求的是 $20u_0+12u_1$ 对 `(w,b)` 的梯度，返回 `((40,-12), 32)`。这是另一轮新前向的核对，不能在下文的 `loss.backward()` 后复用旧 `u`。不提供种子并直接对多元素 `u` 调用 `backward()`，并没有唯一的标量目标；本例真正训练的目标是 `loss`。

## backward：结果写到哪里

对上述前向结果调用一次：

```python
u.retain_grad()
loss.backward()
assert u.grad.tolist() == [20., 12.]
assert w.grad.tolist() == [40., -12.]
assert b.grad.item() == 32.
assert x.grad is None
```

`loss` 是单元素实数，`backward()` 默认从数值 1 的种子开始；它按照刚才的链式计算得到各叶子的梯度。它**不更新** `w` 或 `b`，也不读取学习率。`u.retain_grad()` 只让我们查看本次经过中间量的梯度；常规训练不需要对每个中间量都调用它。

`torch.autograd.grad(loss, (w,b))` 则直接返回所选输入的梯度元组，不把结果写入这两个叶子的 `.grad`。当你需要核对局部公式或在程序里直接使用梯度值时，这个接口很方便。脚本用一次新的前向核对返回值，再用中心有限差分核对同一个 $L(w,b)$：分别扰动一个参数，比较 $[L(\theta+\epsilon)-L(\theta-\epsilon)]/(2\epsilon)$ 与自动微分。有限差分是近似检查，不能把步长无限缩小，也不能换一个损失后仍比较旧梯度。

## 下一次反向：梯度缓冲与图的寿命

第一次反向后，`w.grad=(40,-12)`、`b.grad=32` 保留在叶子上。若用同一组参数重新执行上述前向，再 `backward()` 一次，缓冲区默认**加上**新的梯度，变为 `(80,-24)` 与 `64`。`w.grad=None; b.grad=None` 后再做一次新前向与反向，结果又是 `(40,-12)` 与 `32`。优化器通常用 `zero_grad(set_to_none=True)` 清理所有已登记参数；`None` 表示没有当前保存的梯度，和数值为零的缓冲区并非同一状态。完整训练次序见 [F6 数据与训练](/frameworks/data-and-training/)。

重做前向很关键。反向节点可能要用前向保存的值：这里平方项求导需要前向的 $u_0=3$。PyTorch 默认在反向后释放这类保存值。Python 名字 `loss` 和它的 `grad_fn` 可能还在，原图却未必还能再次反向；本例对同一个 `loss.backward()` 调第二次会报错。

<Figure src="frameworks/autograd-lifetime.svg" alt="新前向保存反向所需值，backward 累加叶子梯度并释放保存值，下一次重新前向">沿左到右读一次计算，再沿底部箭头建立下一次图。保存值是否释放与叶子 `.grad` 是否清空是两个独立决定。</Figure>

`retain_graph=True` 让同一前向的必要保存值继续存活，适用于确实要反向多次的特殊计算，也增加内存占用；普通梯度积累只需每批重新前向。`retain_grad()` 则只要求保留中间张量的 `.grad`，两者不能互换。某些简单算子在第二次反向时可能恰好不需要已释放的保存值；不能用这种偶然成功来设计训练循环。记录损失值时用 `loss.item()`，避免将整串历史挂在日志列表中。

如果连续两批的损失各自已经求了平均，直接分别反向得到的是两个平均梯度之和。若目标是合并后的大批平均，两个等大小批次各应乘 $1/2$；大小不同则按各批样本数占总数的比例。autograd 只计算你写出的标量，不猜测训练目标的分母。

下面的实验仍使用正文的向量损失。先清空梯度，保持 $w=(1,2),b=1$。预测两次重新前向并反向后，`w.grad` 与 `b.grad` 分别为多少，再操作核对 $(40,-12),32$ 与 $(80,-24),64$。把反向种子改为 0.5 后再执行一次，新增贡献应减半，已有缓冲区保持到显式清空为止。

实验的每次操作都会创建一张新图。默认反向后旧图保存值已释放的报错，在下方 Python 脚本中核对。改参数与改种子影响下一次计算，不能自动清除过去的梯度。

## detach 与 clone：求导历史和数据存储是两条关系

有时需要保留一份数值用于日志、缓存或新的计算，同时控制它是否仍连着旧图。`clone()` 复制数据，但在默认梯度模式中保留从副本回到源张量的可微关系；`detach()` 切断该关系，却与源张量共享存储。对本例的 `w`：

| 写法 | 独立存储 | 梯度还能回到原 `w` |
| --- | --- | --- |
| `w` 的普通引用 | 否 | 是，同一对象 |
| `w.clone()` | 是 | 是 |
| `w.detach()` | 否 | 否 |
| `w.detach().clone()` | 是 | 否 |

若要把当前参数数值变成与旧图无关、数据也独立的新可求导叶子，写 `w.detach().clone().requires_grad_()`；新的 `.grad` 留在新叶子，不会回到旧 `w`。这不是常规参数更新的方法，常规更新应在本轮反向完成后操作原参数。

存储共享会影响已经建好的图。在本例先算 `u=w*x+b` 和 `loss`，再对 `u.detach()` 原地改写一个值，原来的 `u` 也随之改变；平方项反向需要前向时的 $u_0$，因此版本检查会拒绝这次反向。`detach()` 停止从新结果沿旧历史求导，**不会保护旧图所需的前向数值**。`clone()` 可以让缓存独立修改；不要用 `.data` 绕过版本检查。

原地操作如 `add_`、`copy_` 通常会修改现有存储。直接在默认梯度模式下原地改需要求导的叶子通常会被拒绝；参数更新应在反向后、`torch.no_grad()` 内执行。不是所有原地操作都非法，判断依据是有没有破坏反向所需的值和张量规则，而不是方法名里是否有下划线。

## no_grad、inference_mode 与 eval：分别控制什么

正常模式按 `requires_grad` 记录可微运算。`torch.no_grad()` 在其上下文中停止记录通常的张量运算，离开后原参数仍可求导。例如更新已算出梯度的 `w` 时，可在 `with torch.no_grad(): w -= eta * w.grad` 中修改数值，再重新前向；更新本身不是要反向穿过的训练图。显式创建带 `requires_grad=True` 的新张量是这个模式的工厂函数例外。

`torch.inference_mode()` 也停止记录，并进一步减少跟踪开销；其中创建的 inference tensor 带有更严格的后续求导使用限制。若数值还要进入后续训练图，先明确是否需要普通张量，不能仅因为它更快就替换 `no_grad()`。本章脚本只检验模式的求导边界，不把速度差当成保证。

`model.eval()` 控制模块行为，例如 Dropout 停止随机丢弃、BatchNorm 使用相应评估行为；它**不关闭 autograd**。处于 eval 的线性层仍能生成求导图；处于 train 的 Dropout 即使在 `no_grad` 下也仍按训练模式工作。这两种开关在推理时常同时使用，但解决的是不同问题。[F5 模块与损失](/frameworks/modules-and-losses/) 将说明模块如何递归切换模式。

还有一个边界：先执行 `x/0` 等未定义算术，再用 mask 从损失中删掉该位置，反向仍可能出现 NaN。无效算术已经进入图，应在前向先定义安全分母或只对有效项执行运算。看到 `.grad is None` 也不要直接判成数值零：先检查输入是否参与本次损失、是否要求梯度、是否为默认保存梯度的叶子。

## 用脚本核对数值与状态

脚本用固定的 float64 参数复现 $u=(3,-1)$、$L=8$、$g_w=(40,-12)$ 和 $g_b=32$。它还断言新的前向会累积梯度、同一损失重复反向会失败、`detach()` 共享存储、`clone()` 保留求导路径、原地改写保存值会触发错误，并分别检查 `no_grad` 与 `eval`。运行于仓库根目录：`uv run python -m examples.frameworks.autograd`。

## 常见误区

- 分支汇合时取一条路径，或把两条贡献平均。对同一个参数的贡献应相加；只有损失定义了平均时才除以相应分母。
- 把 `.grad is None` 当成零。它可能意味着没有参与图、没有反向或该非叶子默认不保留结果。
- 为了积累梯度给每次 `backward` 都加 `retain_graph=True`。多次新前向自然可以累积到同一叶子。
- 认为 `clone` 停止求导，或 `detach` 复制数据。两者控制的关系不同。
- 认为 `model.eval()` 已关闭求导，或 `backward()` 已改变参数。模块行为、记录和更新各有独立调用。

## 练习与核对

<details>
<summary>只把本例输入的第二个数从 -1 改成 0，其余不变。手算新的损失和两个参数的梯度。</summary>

现在 $u=(3,1)$，$s=9+3=12$，$L=\tfrac12(12-2)^2=50$，上游梯度 $g_s=10$。到 $u_0$ 的局部导数是 $2\cdot3+1=7$，到 $u_1$ 是 3，所以 $g_u=(70,30)$。新输入 $x=(2,0)$，故 $g_w=(140,0)$，$g_b=100$。第二个权重本次梯度为零，是因为对应输入为零，并不表示其分支没有影响损失。
</details>

<details>
<summary>本例只对向量 u 以种子 (1,0) 调用 autograd.grad，返回的 w、b 梯度是什么？它是否等于损失 L 的梯度？</summary>

种子选择的标量是 $u_0$，所以对 $w$ 的梯度为 $(x_0,0)=(2,0)$，对共享偏置为 1。它不等于 $L$ 的梯度，因为后者的上游种子是 $g_u=(20,12)$。种子不是任意缩放按钮，而是定义被求导的标量。
</details>

<details>
<summary>两次都用原输入和参数重新前向，每次完整 backward；第一次后不清空 .grad。第二次的 w.grad、b.grad 是多少？若第二次复用同一个 loss 又怎样？</summary>

两次新图分别贡献 $(40,-12)$ 和 32，所以缓冲区变为 $(80,-24)$ 和 64。若直接复用第一次的 `loss`，本例平方项需要的保存值已经在第一次反向后释放，第二次会报错；它不是一次有效的新前向。
</details>

<details>
<summary>要保存可修改的参数快照用于对照，同时保证快照的计算不回到旧参数，选哪种表达式？</summary>

用 `w.detach().clone()`：detach 切断旧求导路径，clone 给快照独立存储。只用 detach 会共享数据，只用 clone 则保留可微路径。若把快照作为新待优化参数，再显式调用 `requires_grad_()`。
</details>
