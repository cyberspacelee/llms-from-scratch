手里有六个数 `0,1,2,3,4,5`。现在把它们作为两个样本，每个样本三个特征，取每个样本的后两项交给下一步计算。你还需要知道：修改选出的数据会不会同时改掉原输入？仅看打印出来的四个数，无法回答这个问题。本章用同一张小表追踪**坐标、值和存储**，直到能预判每次操作的结果。只需 Python 列表和索引知识；矩阵的含义见 [M3 线性代数](/math/linear-algebra/)。

## 建立输入：一个坐标对应哪个数

NumPy 的 `ndarray` 把数字组织在有轴的数组里。我们先创建后续所有操作的原输入 `A`：

```python
import numpy as np
A = np.arange(6, dtype=np.float64).reshape(2, 3)
print(A)
# [[0. 1. 2.]
#  [3. 4. 5.]]
```

`np.arange(6)` 按停止值之前生成 0 到 5。`reshape(2,3)` 将这六个值分成两行三列；两轴长度的乘积必须仍是 6。`A.shape==(2,3)`，`A.ndim==2`，`A.size==6`。我们约定轴 0 表示样本、轴 1 表示特征；这些名字是**本例的约定**，不储存在 shape 里。例如 `A[1,2]` 指第二个样本的第三项，值为 5。

`dtype` 决定每项如何编码。这里显式选 `float64`，每项 8 字节，因此 `A.itemsize==8`、`A.nbytes==48`。`nbytes` 只计当前数组的逻辑元素字节数，不能证明它独占底层存储。若误用整型，写入 `0.5` 等小数可能失去小数部分；轴和 dtype 都是计算输入的一部分。本章用 `float64` 让小例子可核对，不代表模型总该使用它。

## 选后两项：索引会保留还是删去轴

任务要求两个样本都留下后两项，所以沿轴 0 保留全部位置，沿轴 1 取索引 1 起的部分：`A[:,1:]`。冒号 `:` 保留整条轴，切片 `1:` 从 1 开始到末尾；结果值为 `[[1,2],[4,5]]`、shape 为 `(2,2)`。若写 `A[1:]`，取到的是第二个**样本**，而非每行后两项。

整数索引选一个位置并删去对应轴，切片则保留它。因此 `A[1]` 得 `(3,)`，而 `A[1:2]` 得 `(1,3)`；`A[:,1]` 得 `(2,)`，而 `A[:,1:2]` 得 `(2,1)`。数值相同也不能省略形状：下一章的广播会按这些轴决定计算对象。

```python
assert A[1].shape == (3,)
assert A[1:2].shape == (1, 3)
assert A[:, 1].shape == (2,)
assert A[:, 1:2].shape == (2, 1)
```

完整的切片形式是 `start:stop:step`，stop 不包含在内，step 不可为零。`A[:,::2]` 得 `[[0,2],[3,5]]`；`A[:,::-1]` 得 `[[2,1,0],[5,4,3]]`。负索引从末尾数，因此 `A[1,-1]==5`。使用具体整数越界会报错，超出长度的切片端点通常截断；写错轴时可能不报错，所以还要检查结果 shape。

## 要修改选区吗：先查是否共享存储

`v=A[:,1:]` 的数字是 `[[1,2],[4,5]]`。它是基础切片得到的 **view**：一个新数组对象用新的起点和形状解释原有数据，没有复制四个元素。于是 `v[0,0]=9` 会把 `A[0,1]` 改成 9。若任务要求保留原输入，先取 `c=v.copy()`；修改 `c[0,0]` 不会改变 A。我们先把 A 复位，分别验证这两种要求：

```python
A = np.arange(6, dtype=np.float64).reshape(2, 3)
v = A[:, 1:]
c = v.copy()
assert np.array_equal(v, c)                  # 值相同
assert np.shares_memory(A, v)                 # 共享原存储
assert not np.shares_memory(A, c)             # 副本独立
v[0, 0] = 9
assert A[0, 1] == 9 and c[0, 0] == 1
```

**值相同**是元素比较；**共享内存**是存储关系，二者不能互相推断。`v.base is A` 也不是可靠的重叠测试：A 可能本身就是另一个数组的 view，`base` 指向更早的对象。此处用 `np.shares_memory` 核对实际重叠。只有在确实需要独立修改时才复制；保留 view 可省去复制，但修改会传回原数组。

## 为什么 view 不必复制：stride 定位元素

每个 `float64` 占 8 字节。A 的行长是三项，因此从 `A[r,c]` 移到下一行需跨 24 字节，下一列需跨 8 字节：`A.strides==(24,8)`。view 的起点移到 `A[0,1]`，但跨到下一行仍要跳过原数组完整的三项，所以 `v.strides==(24,8)`，而不是 `(16,8)`。shape 告诉我们可用哪些坐标，stride 告诉我们每个坐标变化移动多少**字节**。

<Figure src="frameworks/numpy-storage.svg" alt="原数组 A 与后两列 view 使用同一份六元素数据，copy 使用独立存储" minWidth="30rem">沿上方 A 与 v 的连线追踪到同一排六个元素；v 从 1 开始，换行跨过未选中的 3。下方 copy 单独保存 1、2、4、5。</Figure>

图中的 view 只有四个逻辑元素，却跨越原数组中六个元素的缓冲区。`A[:,::-1]` 甚至能通过起点与负列 stride 反向阅读每行。因此“连续的 `(2,2)` 形状”不等于“数据在内存里紧挨着”。留着一个大数组的小 view，也可能让其底层存储继续存活；长期只需小选区时可复制。

## 若用列号列表选择：为何修改不传回

现在把切片 `1:` 改为显式列号 `[1,2]`。`picked=A[:,[1,2]]` 得到的**值和 shape 与 v 相同**，但整数列表触发 NumPy 的高级索引，取值会创建副本。重新从最初的 A 开始，`picked[0,0]=9` 只改 picked，不改 `A[0,1]`。这就是为什么只比较数字、shape 的测试会漏掉副作用差异。

```python
A = np.arange(6, dtype=np.float64).reshape(2, 3)
picked = A[:, [1, 2]]
assert np.array_equal(picked, A[:, 1:])
assert not np.shares_memory(A, picked)
picked[0, 0] = 9
assert A[0, 1] == 1
A[:, [1, 2]] = [[9, 2], [4, 5]]
assert A[0, 1] == 9
```

最后一行之前的赋值目标是 A 本身，NumPy 直接把右侧值写进所选位置。这不改变“高级索引**取值**得到副本”的规则。相反，`A[:,[1,2]][0,0]=9` 先取临时副本，再修改这个副本，A 不变；要写回 A，应把完整索引放在一次赋值的左侧。

### 选读：非矩形选择与重复索引

若选区来自条件 `mask=A>2`，`A[mask]` 会取出 `[3,4,5]`，shape 为 `(3,)` 且不共享存储；`A[mask]=-1` 则直接写回对应三格。若想保留原形状并按条件选值，下一章使用 `np.where`。两组整数索引 `A[[0,1],[1,2]]` 按位置配对，取 `(0,1)` 和 `(1,2)` 两个元素，结果 `[1,5]`；要取两行与两列的四种组合，使用 `A[np.ix_([0,1],[1,2])]`。

重复索引的更新还需额外小心：`x[[0,0]]+=1` 不等于对 `x[0]` 加两次。先取值、计算、写回时，两次同位置写入可能只留下一个增量。需要重复累计时使用 `np.add.at(x,[0,0],1)` 等明确支持重复位置的操作。

## 把同样六个数改成三行两列：换分组还是换轴

假设下游要求 shape `(3,2)`。有两个看似合格的写法，但问题不同。`reshape(3,2)` 按 A 的逻辑 C 顺序重新分组，得到 `[[0,1],[2,3],[4,5]]`；`A.T` 交换两轴，得到 `[[0,3],[1,4],[2,5]]`。二者 shape 相同、值的对应关系不同。若原轴 0 是样本、轴 1 是特征，转置后轴 0 成为特征，不能还把它当作三个样本。

对转置可以逐格检查：`A.T[c,r]==A[r,c]`，例如新位置 `[1,0]` 等于旧位置 `[0,1]`，即 1。转置的 stride 是 `(8,24)`，只交换了两个坐标的字节移动规则，所以本例与 A 共享存储。`reshape` 只要求新 shape 的元素数仍为 6；`A.reshape(3,-1)` 可推得第二轴长度 2，但 reshape **不保证**通过共享存储完成。

```python
A = np.arange(6, dtype=np.float64).reshape(2, 3)
grouped = A.reshape(3, 2)
swapped = A.T
assert grouped.shape == swapped.shape == (3, 2)
assert grouped[0, 1] == 1 and swapped[0, 1] == 3
assert swapped.strides == (8, 24)
assert np.shares_memory(A, swapped)
```

为什么不能一概说 reshape 会创建 view？把转置后的逻辑顺序排成一行，`A.T.reshape(6)` 得 `[0,3,1,4,2,5]`。本例的这六个元素无法靠 A 中一条固定字节步幅顺次访问，所以 NumPy 为结果复制数据；`np.shares_memory(A,A.T.reshape(6))` 是 False。是否复制由输入布局、目标形状和顺序共同决定，需要独立数据时应显式 `copy()`，需要验证共享时应测具体结果。

更高阶的 `transpose(axes)` 明确指定新轴依次对应哪些旧轴，如 `(B,T,d)` 经 `(0,2,1)` 变 `(B,d,T)`。一维数组的 `.T` 不会增加列轴；需要 `(d,1)` 时写 `x[:,None]` 或 `reshape(-1,1)`。

## 把选区交给函数：声明修改与转换边界

假设函数接收 `(B,3)` 的浮点输入，取后两项返回。若它承诺不修改输入，`return A[:,1:]` 仍把共享数据交给调用方；对方修改返回值会改 A。需要独立结果时写 `return A[:,1:].copy()`，并在测试中检查 shape、值和 `not np.shares_memory(A,result)`。若函数故意返回 view，就把共享关系写在契约里。

输入从 Python 列表或其他数组来时，`np.array(data,dtype=np.float64)` 创建数组并在默认条件下复制；`np.asarray(data,dtype=np.float64)` 尽量复用符合要求的 ndarray，但 dtype 不符时仍会转换并可能复制。`np.asarray(A) is A` 对本例成立，不能据此假设所有 `asarray` 都返回原对象。`y=A` 只是另一个变量名，也不会复制。若要保证独立工作区，明确用 `A.copy()`。

函数入口至少确认轴语义与 dtype：`A.ndim==2`、`A.shape[1]==3`、`np.issubdtype(A.dtype,np.floating)`。不要用 `reshape(-1,3)` 静默接受错误的 `(3,B)` 输入：元素数可能恰好吻合，样本和特征却被错认。空输入也须按任务决定：`(0,3)` 是零样本且每样本三特征，`(2,0)` 是两样本但没有特征；二者 `size` 都是 0，语义不同。

### 选读：创建工作区与添加轴

`np.zeros((2,3),dtype=np.float64)` 和 `np.ones` 生成已知初值；`np.empty` 只分配，不初始化，读取前必须写满。本章脚本先 `scratch.fill(7)` 再读取。`np.linspace(0,1,5)` 指定恰好五个等间隔点并默认包含端点，适合“需要五个点”的任务；浮点步长的 `arange` 不能替代固定点数契约。`astype` 可以转换 dtype，但浮点变整数会丢小数。

`A[None]` 添加长度一的前导轴，shape `(1,2,3)`；`A[:,:,None]` 在末尾加轴，shape `(2,3,1)`。它们不添加数值，下一章用这种轴表达广播方向。`A[...,1]` 在二维例子等价于 `A[:,1]`，先知道省略了哪些轴再使用。`np.array(7)` 是 shape `()` 的标量数组、size 1，不是空数组；一维 `(6,)` 的逗号属于 Python 元组语法。

## 常见误区

- **相同值与相同 shape 就有相同的修改行为。** `A[:,1:]` 和 `A[:,[1,2]]` 的值与 shape 相同；前者取 view，后者取副本。
- **高级索引不会修改 A。** 取值结果不共享存储，但直接写 `A[:,[1,2]]=...` 会更新 A；链式索引先得到副本则不会。
- **目标 shape 相同就是同一种变换。** `A.reshape(3,2)` 与 `A.T` 在 `[0,1]` 处分别为 1、3，表示的轴也不同。
- **`empty` 默认清零。** 它不保证初值，读取前必须把要读的位置完整写入。

## 练习与核对

<details>
<summary>A 的 shape 为 (2,3)，A[1]、A[1:2]、A[:,1:2] 分别保留哪些轴？</summary>

`A[1]` 用整数选择轴 0 的位置并删除该轴，剩下 `(3,)`。`A[1:2]` 用切片保留轴 0，长度变成 1，得到 `(1,3)`。`A[:,1:2]` 保留两轴，把特征轴长度变成 1，得到 `(2,1)`。比较数字之外还应比较 shape。
</details>

<details>
<summary>v=A[:,1:] 与 p=A[:,[1,2]] 数值相同，为什么修改 v[0,0] 与 p[0,0] 的后果不同？</summary>

前者是基础切片视图，写到原数据中的 `A[0,1]`。后者是高级索引取值副本，修改发生在独立数据里。`A[:,[1,2]]=values` 又是直接下标赋值，不经过“取副本后修改”的路径，因而能写回。
</details>

<details>
<summary>为什么 A[[0,1],[1,2]] 不是两行两列子矩阵？</summary>

两组索引按位置组成坐标对 `(0,1)` 和 `(1,2)`，只选择两个元素。需要四个组合时，用 `np.ix_` 构造网格式索引，其输出明确展开两轴选择范围。
</details>

<details>
<summary>把 A 转置再 reshape 成长度 6，为什么得到 0、3、1、4、2、5？</summary>

转置后的逻辑行依次是 `[0,3]`、`[1,4]`、`[2,5]`，默认 C 顺序 reshape 按这些行遍历。这个顺序与原存储的 0–5 不同，对本例需要复制才能形成目标连续序列。转置本身仍可共享原数据。
</details>

<details>
<summary>大数组的一个很小切片还在使用，删除大数组变量一定会释放底层存储吗？</summary>

不一定。切片视图仍持有对原存储的引用，存储必须继续有效。若只需长期保留小部分独立数据，可复制切片，再让原视图与原数组的引用结束；这会增加一次复制，但改变后续存储生命周期。
</details>

<details>
<summary>变式：令 B=np.arange(12,dtype=np.float64).reshape(3,4)，取每行索引 1 到 2 的两列。用切片和整数列表各写一次；给两种结果的 [2,0] 赋值 99，哪一种会修改 B 的哪一格？</summary>

切片写 `B[:,1:3]`，整数列表写 `B[:,[1,2]]`，二者起初都是 `[[1,2],[5,6],[9,10]]`、shape `(3,2)`。分别从未改过的 B 开始做实验：切片是 view，`[2,0]` 对应 `B[2,1]`，所以 B 的 9 变 99；整数列表取值是副本，改它的 `[2,0]` 不影响 B。若直接写 `B[:,[1,2]]=...`，那是另一种直接赋值操作。

</details>
