你有六个数 0、1、2、3、4、5，希望把它们解释成两个样本、每个样本三个特征。数学上这是一张 $2\times3$ 表，代码里却可能是一维列表、二维数组、转置后的视图，或者另一个数组的切片。数值相同不代表形状相同，形状相同也不代表彼此独立。一次看似无害的赋值，可能悄悄改掉后续计算的输入。

本章从 `np.arange(6).reshape(2,3)` 出发，先回答数组怎样描述数字，再回答索引怎样选择它们，最后回答不同数组对象怎样共享存储。只需要 Python 列表和基础下标知识；矩阵的数学含义可回读 [M3 线性代数](/math/linear-algebra/)。这里用 CPU 和 float64 核对小数值，不把这种精度当作大型模型的默认选择。

## 数组契约：值之外还要知道形状与类型

NumPy 的主要对象是多维数组 `ndarray`。它用形状描述每个轴有多少位置，用数据类型描述每个元素怎样编码，并通过布局信息把坐标映射到实际存储。可以先把它理解为“有统一元素类型、有坐标系统的一组数据”，而不是若干层 Python 列表的简称。

```python
import numpy as np
A = np.arange(6, dtype=np.float64).reshape(2, 3)
print(A)
# [[0. 1. 2.]
#  [3. 4. 5.]]
```

`arange` 生成六个数，`reshape` 把它们解释成两行三列。`A.shape` 是元组 `(2,3)`，第一项对应轴 0，第二项对应轴 1；`A.ndim` 是轴数 2；`A.size` 是元素总数 6。轴的名字不由 NumPy 自动赋予。我们约定轴 0 是样本、轴 1 是特征，这属于程序的数据契约，交换两轴后必须同时改变解释。

形状 `(6,)` 有一个轴，形状 `(2,3)` 有两个轴，形状 `(1,2,3)` 有三个轴，但三者都有六个元素。括号中的逗号尤其重要：Python 的 `(6)` 是整数，`(6,)` 才是单元素元组。`ndim` 在这里指数组轴数，不能直接等同于数学里的向量维度。一个三维向量可以存成 shape `(3,)`，数组的 `ndim` 仍是 1。

标量也可以放进数组：`np.array(7).shape` 是 `()`，`ndim` 为 0，`size` 为 1。这不是空数组。相反，`np.zeros((0,3))` 有两个轴，但第一个轴长度为零，元素总数为零。以后遇到空批或筛选结果为空，应根据 `size` 与轴长度处理，不能把 `ndim==0` 当作没有数据。

`A.dtype` 是 `float64`，表示每元素用 64 位浮点编码；`itemsize` 是 8 字节，`nbytes` 为 $6\times8=48$ 字节。`nbytes` 统计该数组的元素字节数，不包含 Python 对象的所有开销，也不保证数组独占这 48 字节。一个小视图可能仍引用更大的原始存储，这将在后面解释。

如果函数声明输入是 $(B,d)$ 的浮点数组，那么样本数 $B$、特征数 $d$、dtype、是否允许修改都属于契约。只写“接收一个数组”太模糊：传来整数数组时小数赋值可能被截断；传来 shape `(d,B)` 时按错误轴计算仍可能返回数值；传来视图时原地修改可能影响调用方。接口入口应先验证这些真正影响结果的条件。

## 创建数组：数据来源与初始化目的分别选择

`np.array` 把已有序列转成数组，默认复制输入；给定 `dtype` 可以明确数值编码。`np.asarray` 则尽量把输入当作数组使用，对于类型、布局等要求已满足的普通 ndarray，通常直接返回同一个对象或共享其数据。它不是“保证独立存储”的 API。

```python
x = np.array([1, 2, 3], dtype=np.float64)
y = np.asarray(x)
z = np.array(x)
assert y is x
assert not np.shares_memory(x, z)
```

这里 `is` 检查 Python 对象身份，`shares_memory` 检查实际数据重叠，是两个问题。不同对象仍然可以指向同一块存储；对象相同则自然共享数据。若要求把输入作为独立工作区修改，应显式复制，不要因为变量名变成 `y` 就认为已经隔离。

需要等步长整数索引时用 `arange`，停止值不包含在结果里。`np.arange(1,7,2)` 得到 `[1,3,5]`。需要在两个端点之间取固定数量的采样点时用 `linspace`，例如 `np.linspace(0,1,5)` 得到 `[0,.25,.5,.75,1]`，默认包含两端。浮点步长的 `arange` 可能受舍入影响，若你的需求是“恰好五个点”，`linspace` 更直接表达契约。

`zeros(shape)` 和 `ones(shape)` 按形状创建全零与全一数组。`empty(shape)` 只申请空间，不保证里面是零，也不保证是有限值。它适合之后会覆盖每个元素的工作区；如果算法仅写部分位置就开始读取，未初始化的内容会污染结果。不要把某一次打印出来的零当作 `empty` 的约定。

```python
buffer = np.empty((2, 3), dtype=np.float64)
buffer.fill(7)
assert buffer.sum() == 42
```

这一段先完整写入，再使用所有位置。对于教学脚本或要求确定初值的状态，直接使用 `zeros` 往往更清楚。`zeros_like(A)` 等函数沿用输入的形状与类型，因此也要检查是否无意沿用了整数 dtype。

整数、浮点与布尔数组各有用途。token 编号、类别索引通常用整数；激活与权重用浮点；筛选条件用布尔。整数类型能表示的范围有限，`np.array([255],dtype=np.uint8)+1` 不应该被当作任意精度整数加法。Python 的整数可以扩大精度，NumPy 的固定宽度整数有具体编码范围，这个差异需要在计数与索引算法中牢记。

转换类型使用 `astype`，例如 `x.astype(np.float64)`。从浮点转成整数会丢失小数，不是数值不变的存储优化。仅创建 `np.asarray(x,dtype=np.float64)` 也可能为了满足新类型而复制数据。判断别名要看实际结果，不要把“尽量避免复制”误读成“永远不复制”。

## 坐标与切片：选择元素时也在改变轴

二维数组 `A[r,c]` 使用零起始行列坐标。当前 $A_{1,2}=5$，`A[1,-1]` 同样得到 5，负下标从末尾计数。越界整数下标会报错；普通切片的端点则按切片规则截断，不会因为停止值超过长度就一定报错。二者的错误边界不同。

使用整数选择一个轴上的单个位置，会删除这个轴；使用切片保留这个轴。所以 `A[1]` 的 shape 是 `(3,)`，`A[1:2]` 的 shape 是 `(1,3)`；`A[:,1]` 是 `(2,)`，`A[:,1:2]` 是 `(2,1)`。它们可以含相同数字，却在后续广播中扮演不同角色。

```python
assert A[1].shape == (3,)
assert A[1:2].shape == (1, 3)
assert A[:, 1].shape == (2,)
assert A[:, 1:2].shape == (2, 1)
```

`:` 表示保留整个轴。`start:stop:step` 表示从 start 起、在 stop 前停止、按 step 移动，step 不能为零。`A[:,::2]` 取每行的第 0、2 列，结果是 `[[0,2],[3,5]]`；`A[:,::-1]` 反向取列，结果为 `[[2,1,0],[5,4,3]]`。反向视图可以有负步幅，逻辑上的第一个元素未必是原存储的最前面。

`None` 或 `np.newaxis` 添加长度为一的轴，不添加新数字。例如 `A[None].shape` 为 `(1,2,3)`，`A[:,:,None].shape` 为 `(2,3,1)`。这常用于明确广播方向。省略号 `...` 代表足够多的完整轴切片，`A[...,1]` 在当前二维例子中等价于 `A[:,1]`。先明确轴语义，再使用省略号，避免代码短了却难以辨认选择了什么。

这里的坐标操作与 [G1 GPU 执行模型](/gpu/execution-model/) 的线程坐标不是同一层。NumPy 索引说明要访问哪些数组元素，并不承诺一个坐标由哪个 GPU 线程执行。即使两者都出现行列编号，也不能把数组 API 的二维形状直接当成硬件布局。

## 视图与副本：两个对象是否改同一份数据

视图（view）通过新的形状、步幅或起点解释已有数据；副本（copy）持有复制后的数据。对于本章的普通数值 ndarray，基础切片产生共享数据的视图。`v=A[:,1:]` 选择每行后两列，没有把四个数搬到一个独立数组中。`v[0,0]=9` 写到的是 `A[0,1]`。

<Figure src="frameworks/numpy-storage.svg" alt="原数组与切片共享同一组六个float64元素，切片副本另有四个元素的存储" minWidth="30rem">上方两个数组对象拥有各自的形状解释，却访问同一份数据。下方显式 copy 后的数据独立，连线不代表实际内存地址。</Figure>

图中每个元素为 8 字节，原数组换行移动 24 字节、换列移动 8 字节。切片仍然沿原来的两行取数据，因此换行也是 24 字节，而不是两列乘 8 得到的 16。没有被选中的第 0 列仍存在于原存储里，选区只跳过它。形状 `(2,2)` 并不意味着四个元素一定紧挨着存放。

```python
A = np.arange(6, dtype=np.float64).reshape(2,3)
v = A[:,1:]
c = v.copy()
v[0,0] = 9
assert A[0,1] == 9
c[0,0] = 8
assert A[0,1] == 9
```

`copy` 让最后一次写入与原数组隔离。检查时用 `np.shares_memory(A,v)`，不要只看 `v.base is A`：多次 reshape 和切片后，`base` 可能指向更早的底层对象，而不是你手上的直接父数组。`np.may_share_memory` 则是保守的可能重叠检查，不一定精确证明当前元素实际重叠。小例子使用 `shares_memory` 就能直接核对。

视图有两个实际用途。第一，避免复制很大的数据，仅创建不同坐标解释；第二，允许通过选区更新已有数组。但同样的共享也意味着副作用：函数修改输入视图会传播到原数组。若只保留大数组的一小段视图，底层大存储可能因仍被引用而不能释放。想保留一小段独立数据并释放大输入时，显式 `copy` 可以改变这个生命周期。

本章不讨论 `object` 数组中 Python 对象的深复制。对 float64 等普通数值数组，独立的数据缓冲区已经能解释修改隔离；装有可变 Python 对象的数组，复制元素引用与复制对象内部状态是另一个问题。优先使用统一数值类型来表达模型数据，避免把对象引用问题带进数值程序。

## 高级索引：取值是副本，直接赋值仍写回

整数数组与布尔数组可以选择非连续位置，这称为高级索引（advanced indexing）。`A[:,[1,2]]` 取两列，形状与 `A[:,1:]` 一样，但取出的数据是副本。因此 `picked=A[:,[1,2]]; picked[0,0]=9` 不改变 `A`。相同的数字与形状，不能证明存储关系相同。

直接赋值 `A[:,[1,2]]=values` 的语义不同：它对 A 的指定位置执行写入，并不是先拿到一个副本再丢掉。这里要区分取值表达式与赋值目标。在 Python 中，下标赋值由容器的赋值操作处理；NumPy 依据索引把右侧值写回原数组。

<NumpyStorageLab client:visible />

实验始终从同一个 $2\times3$ 原数组开始，再修改选区的一格。选“基础切片视图”时上下两幅一起变；选“切片后显式 copy”或“高级索引取值副本”时原数组保持不变；选“高级索引直接赋值”时通过赋值目标写回原数组。最后一种有写回行为，但不能据此称高级索引的取值结果为视图。

链式索引尤其容易混淆：`A[:,[1,2]][0,0]=9` 中，第一步先取出一个副本，第二步修改该临时副本，不会写回 A。应使用一次明确的赋值目标，如 `A[0,1]=9`，或者先构造完整右侧，再执行 `A[:,[1,2]]=values`。代码里的方括号越多，越需要追踪每一步产生的是哪个对象。

两个整数索引数组通常按位置配对，而不是自动取笛卡尔积。`A[[0,1],[1,2]]` 选择 `(0,1)` 与 `(1,2)`，得到 `[1,5]`。若要两行与两列的全部组合，可以写 `A[np.ix_([0,1],[1,2])]`，得到 `[[1,2],[4,5]]`。把“按坐标对取值”和“取一个子矩阵”混用，是结果形状突然少一轴的常见原因。

布尔索引来自条件，例如 `mask=A>2`。同形状 mask 选择所有 True 位置，`A[mask]` 得到一维 `[3,4,5]`，不保留原来的矩形网格；取值也不共享数据。`A[mask]=-1` 则把原数组对应位置写成 -1。若希望保留原形状，只在条件不满足的格子填入一个值，用 [F2](/frameworks/numpy-computation/) 的 `np.where` 更合适。

重复整数索引还有一个重要边界：`x[[0,0]]+=1` 不能被理解成对 `x[0]` 连续做两次加一。高级取值与缓冲写回可能让结果只增加一次。若任务确实是按重复索引累计，需要有明确的重复累计语义，例如 `np.add.at(x,[0,0],1)`。索引表达式能重复选择元素，不等于更新语句会自动实现你希望的归约。

## Reshape 与 transpose：重新分组和交换轴不同

`reshape` 改变元素分组，不改变元素总数。对连续的 A，`A.reshape(3,2)` 得到 `[[0,1],[2,3],[4,5]]`。它把同一逻辑顺序按新的行宽解释。目标形状各维乘积必须等于原 `size`；可以用一个 `-1` 自动推断缺失维度，如 `A.reshape(3,-1)` 推出第二维为 2。

`transpose` 交换轴的解释。二维的 `A.T` 变成 `[[0,3],[1,4],[2,5]]`，shape 同样可以是 `(3,2)`，但元素对应关系与 reshape 不同。转置满足新数组位置 $(c,r)$ 对应旧数组位置 $(r,c)$；reshape 不承担这个交换行列的数学含义。仅比较目标 shape 无法区分这两种操作。

对于连续行主序 float64 数组，元素偏移可以写成 $3r+c$，字节移动为 $24r+8c$。转置后形状是 `(3,2)`，两个步幅交换成 `(8,24)`。沿新数组的一行读取 0、3，不是读取存储中相邻的两个数。转置可以通过改变元数据共享原数据，所以交换轴并不一定执行真实的数据搬运。

`A.T.reshape(6)` 默认按转置后数组的 C 顺序读取，得到 `[0,3,1,4,2,5]`。对这个具体布局，无法只用一条固定步幅直接表达全部连续输出，因此 NumPy 会复制，输出不与 A 共享。`reshape` 是否复制要由输入布局与目标顺序决定，不能统一承诺“reshape 是视图”或“reshape 一定复制”。

```python
A = np.arange(6, dtype=np.float64).reshape(2,3)
assert np.shares_memory(A, A.T)
flat = A.T.reshape(6)
assert not np.shares_memory(A, flat)
assert flat.tolist() == [0,3,1,4,2,5]
```

这里只验证这个已知布局，不把它推广到任意转置。某些退化轴或特定形状仍可以无复制重排。查看 `strides` 和 `flags.c_contiguous` 可以帮助分析；真正依赖共享关系时，再做实际重叠核对或显式选择 copy。性能代码还应说明是否允许复制，否则“看起来只是改 shape”的操作可能带来未预期的工作量。

对高阶数组，`transpose(axes)` 明确写出新轴顺序，例如 shape `(B,T,d)` 使用 `(0,2,1)` 变成 `(B,d,T)`。原轴 0 留在新轴 0，原轴 2 移到新轴 1，原轴 1 移到新轴 2。只对一维数组使用 `.T` 不会自动把它变成列向量；需要列轴时显式使用 `x[:,None]` 或 `reshape(-1,1)`。

## 数组接口：让调用者知道能否修改与复制

假设有一个函数接收 `(B,d)` 的输入，并把每个样本最后一项设为零。如果函数里面先写 `work=np.asarray(input)`，再修改 `work[:,-1]`，调用者提供 ndarray 时原输入也可能改变。函数名里只有“准备数据”并不能让人预料到这个副作用。更清晰的契约有两种：明确声明原地修改，或者先显式复制工作区，再返回独立结果。选哪一种取决于实际任务，不需要同时设计一套庞大的复制配置。

反过来，函数声明返回视图时，也应该说明结果依赖输入的生命周期，且修改能传播。一个调用者先把返回值当作自己的工作区写入，另一个调用者还把原数组作为参考答案，两者就会互相影响。因为错误源头是共享存储，重复打印 shape 很难定位；先核对哪一次操作改变了哪个缓冲区，才是直接的排查方法。

需要固定特征数时，可以在入口检查 `ndim==2` 与 `shape[1]==d`，需要浮点时检查 dtype 或显式转换，需要独立存储时显式 copy。每项检查都应该对应一个会改变结果的真实条件。不能用 `reshape(-1,d)` 静默“修复”任意输入，因为它可能把错误批次与错误轴顺序重新解释成一个能运行的形状，从而把上游数据问题藏起来。

空数组也必须走同一个契约。shape `(0,3)` 表示有三项特征但没有样本，shape `(2,0)` 表示两个样本各没有特征。二者 `size` 同为零，后续按样本统计与按特征统计却不同。对空输入允许返回空输出，还是认为缺少所需数据而报错，应由函数任务决定。不要仅看总元素数就删除所有轴信息。

把 shape 与存储关系写进测试，可以使之后的优化有明确边界。例如原实现返回独立结果，优化后换成视图，即使数字与速度都符合预期，也改变了调用契约；测试应能发现修改传播。原实现接受非连续切片，优化后却假定连续布局，同样不能只用连续整数组做验证。本章的反向切片、转置与高级索引提供了几组很小却能区分这些问题的输入。

## 配套核对：把存储契约写进断言

## 常见误区

| 操作 | 形状契约 | 本章的存储与初始化边界 |
| --- | --- | --- |
| `array / asarray` | 由输入与转换要求确定 | array 默认复制；asarray 不保证独立数据 |
| `zeros / ones / empty` | 明确传入各轴长度 | empty 不初始化，读取前必须完整写入 |
| `A[r] / A[r:r+1]` | 整数删轴，切片保留轴 | 基础切片共享数据 |
| `A[:, indices]` | 按整数索引选择 | 取值复制，直接赋值写回原数组 |
| `reshape` | 元素总数不变 | 能否共享取决于实际布局与顺序 |
| `transpose / copy` | 前者换轴，后者保留形状 | 换轴可共享数据；数值 copy 隔离修改 |

- **两个数组有相同数字，就有相同语义。** shape、轴含义与 dtype 仍可能不同；后续操作可以得到完全不同的输出。
- **换个变量名就复制了数据。** `y=x` 是别名，切片可以是不同对象共享存储，需要独立修改时显式 copy。
- **高级索引永远不改原数组。** 取值是副本，作为直接赋值目标时仍写回；链式取值后修改又是另一条路径。
- **Transpose 就是 reshape 成相反的 shape。** 两者形状可能相同，元素对应关系不同，逐个值检查即可发现。
- **Empty 先清零，之后随意填几格即可。** 它不保证初值，使用前必须初始化将要读取的所有位置。
- **Stride 描述数组的抽象行列数。** 它以字节表达坐标移动，视图可以有间隔或负步幅，形状本身不决定连续性。

## 练习与核对

<details>
<summary>A 的 shape 为 (2,3)，A[1]、A[1:2]、A[:,1:2] 分别保留哪些轴？</summary>

`A[1]` 用整数选择轴 0 的位置并删除该轴，剩下 `(3,)`。`A[1:2]` 用切片保留轴 0，长度变成 1，得到 `(1,3)`。`A[:,1:2]` 保留两轴，把特征轴长度变成 1，得到 `(2,1)`。比较数字之外还应比较 shape。
</details>

<details>
<summary>v=A[:,1:] 与 p=A[:,[1,2]] 数值相同，为什么修改 v[0,0] 与 p[0,0] 的后果不同？</summary>

前者是基础切片视图，写到原数据中的 `A[0,1]`。后者是高级索引取值副本，修改发生在独立数据里。`A[:,[1,2]]=values` 又是直接下标赋值，不经过“取副本后修改”的路径，因而能写回。
</details>

<details>
<summary>为什么 A[[0,1],[1,2]] 不是两行两列子矩阵？</summary>

两组索引按位置组成坐标对 `(0,1)` 和 `(1,2)`，只选择两个元素。需要四个组合时，用 `np.ix_` 构造网格式索引，其输出明确展开两轴选择范围。
</details>

<details>
<summary>把 A 转置再 reshape 成长度 6，为什么得到 0、3、1、4、2、5？</summary>

转置后的逻辑行依次是 `[0,3]`、`[1,4]`、`[2,5]`，默认 C 顺序 reshape 按这些行遍历。这个顺序与原存储的 0–5 不同，对本例需要复制才能形成目标连续序列。转置本身仍可共享原数据。
</details>

<details>
<summary>大数组的一个很小切片还在使用，删除大数组变量一定会释放底层存储吗？</summary>

不一定。切片视图仍持有对原存储的引用，存储必须继续有效。若只需长期保留小部分独立数据，可复制切片，再让原视图与原数组的引用结束；这会增加一次复制，但改变后续存储生命周期。
</details>
