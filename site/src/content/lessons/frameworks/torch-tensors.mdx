[F1](/frameworks/numpy-arrays/) 把六个数排成 `2×3` 数组，[F2](/frameworks/numpy-computation/) 用轴完成广播和矩阵计算。现在要把同一批数交给 PyTorch，并准备形状为 `(B,T,d)` 的输入，供 [P3 多头注意力](/principles/attention/) 使用。本章要解决一件具体的事：**把每个时间位置的四个通道分给两个头，再把头的输出按原时间位置拼回去**。只检查最终 shape 不够，时间和头互换后，即使元素总数不变，也可能读错位置。

开始时沿用 F1 的数值 `A=[[0,1,2],[3,4,5]]`。F1 把两行解释为两个样本；**从这里开始，把同样的数值作为一条序列的两个时间位置，并在构造模型输入时另记为 `X`**。数值没变，轴语义变了。随后给每个位置添一个零通道，得到 `B=1,T=2,d=4`，以便分成 `n_q=2` 个头，每头 `d_h=2`。这些是教学用的已知向量；真实模型通常先通过可训练投影产生 Q、K、V。

## 进入 Torch：数值相同不等于独立存储

`torch.Tensor` 是带形状、dtype、device 和存储信息的数组对象。下例的 NumPy `float64` 输入在 CPU 上；`torch.from_numpy` 与它共享数据，`torch.tensor` 则复制数据：

```python
import numpy as np
import torch

A = np.arange(6, dtype=np.float64).reshape(2, 3)
shared = torch.from_numpy(A)
snapshot = torch.tensor(A)
shared[0, 1] = 9
assert A[0, 1] == 9 and snapshot[0, 1].item() == 1
A[0, 1] = 1  # 复原主例
```

`shared` 的一次写入传回 A，是因为两个对象指向同一缓冲区；`snapshot` 仍保存构造时的值。`torch.as_tensor(A)` 在 dtype/device 允许时也尽量共享，转换要求不匹配时会建立新数据。`from_numpy` 只接受受支持的 NumPy dtype 和布局；例如负 stride 的反向切片需先复制。共享可写缓冲区在求导期间被外部修改也有风险，F4 会讨论计算历史。

本章统一在 CPU 上用 `float64`，让小数值检查稳定；这不是模型训练的默认精度。张量的 `stride()` 以**元素**为单位，F1 的 NumPy `strides` 以**字节**为单位。设备也属于运算契约：普通 CPU 张量不能直接与 CUDA 上的数据按预想做逐元素运算。搬设备或改 dtype 用 `x.to(device=..., dtype=...)`，返回新绑定；目标已相同时默认可能直接返回 x，需要独立存储时明确 `clone()` 或 `to(copy=True)`。索引张量稍后用 `torch.long`，mask 用 `torch.bool`，两者不是可互换的“数字”。

## 加上 batch 和通道：先给每条轴命名

`shared` 的 shape 是 `(2,3)`。在最前面加一条长度为一的 batch 轴，再在末尾补一列零：

```python
X3 = shared.unsqueeze(0)             # (B,T,3) = (1,2,3)
zero = torch.zeros((1, 2, 1), dtype=X3.dtype, device=X3.device)
X = torch.cat([X3, zero], dim=-1)     # (B,T,d) = (1,2,4)
assert X.tolist() == [[[0., 1., 2., 0.], [3., 4., 5., 0.]]]
```

`unsqueeze(0)` 只新增长度一的轴，不添加数值；X3 因而还与 A 共享数据。`cat` 沿现有通道轴拼接，产生新的四通道结果。若用 `stack`，它会新增一条轴，而非把三个通道变成四个。这里的零列只为可整除的形状服务，不是假装它代表模型学出的特征。

现在 `X[b,t,c]` 中，b 选序列，t 选时间位置，c 选通道；`X[0,1,2]=5`。条件 `d=n_q d_h=2×2=4` 是拆头的前提。这个条件只描述本例的完整等分，不应被当作所有现代模型 Q/KV 维度的普遍公式。

## 从通道拆出头：reshape 再 permute

每个时间位置的四个通道，按相邻两项分给头 0、头 1。先让通道轴 `d=4` 变成 `(n_q,d_h)=(2,2)`，再将头轴移到时间轴前面，供每个头独立地对两个位置做注意力：

```python
by_position = X.reshape(1, 2, 2, 2)  # (B,T,n_q,d_h)
Q = by_position.permute(0, 2, 1, 3)  # (B,n_q,T,d_h)
assert Q[0, 1, 1, 0].item() == X[0, 1, 2].item() == 5
```

`reshape` 在这里**只拆一条通道轴**，没有改变时间和头的先后；`permute(0,2,1,3)` 才交换它们。输出轴 1 来自原轴 2，输出轴 2 来自原轴 1。固定一个带坐标的数 5，比只看 `Q.shape==(1,2,2,2)` 更有力：它必须仍属于时间 1、头 1、头内通道 0。

<Figure src="frameworks/torch-axis-layout.svg" alt="数值 5 从批时间头通道坐标 (0,1,1,0) 变成批头时间通道坐标 (0,1,1,0)，时间与头的轴身份交换">左边的 Y 是 `by_position=reshape(X)`，按时间收纳各头；右边的 Q 按头收纳各时间位置。两处的数值 5 来自原输入 A[1,2]；下方 stride 随轴顺序换位，底层数值没有被重排。</Figure>

这个例子里两个轴的长度都为 2，所以前后坐标数字碰巧一样；**轴名不同**，不能凭 `(0,1,1,0)` 猜映射。脚本另用 `T=3,n_q=2` 的非方形例子检查轴交换，避免等长轴掩盖错误。

### stride 怎样解释这次交换

X 连续存放八个元素，shape `(1,2,4)`，stride `(8,4,1)`；拆头后的 stride 是 `(8,4,2,1)`，交换时间与头后 Q 的 stride 是 `(8,2,4,1)`。张量坐标的存储位置由起点偏移和各轴 stride 决定；对 Q，`(0,1,1,0)` 的元素偏移为 `0×8+1×2+1×4+0=6`，即值 5。Q 是共享 X 存储的视图，`permute` 没有按新轴顺序复制数据。

实验沿用原 `2×3` 数组：转置只交换 shape 与 stride，移动逻辑坐标时仍读取同一缓冲区。它还展示了为何“逻辑顺序”与“物理顺序”不能混写。若切 `x[:,1:]`，起点还会移到原存储偏移 1，行 stride 仍是 3；用新 shape `(2,2)` 误算为行 stride 2，会在第二行读错。

## 做一次头内读取：mask、广播和 gather

为展示轴顺序的用途，暂时把 Q 同时当作 K 和 V；这只是在固定输入上做一次可计算的注意力，并非训练过的投影。矩阵乘在最后两轴发生，前两轴分别保留 batch 和头：

```python
scores = Q @ Q.transpose(-2, -1) / (2 ** 0.5)
assert scores.shape == (1, 2, 2, 2)  # (B,n_q,T_query,T_key)
```

最后两个 T 有不同身份：倒数第二轴选择哪个位置**发问**，最后一轴选择可读的**键位置**。causal mask 要遮住将来的键。对 T=2，查询 0 不能读取键 1；查询 1 可以读取键 0 和 1：

```python
future = torch.triu(torch.ones((2, 2), dtype=torch.bool), diagonal=1)
weights = scores.masked_fill(future, -torch.inf).softmax(dim=-1)
assert weights.shape == (1, 2, 2, 2)
assert torch.all(weights[..., 0, 1] == 0)
context = weights @ Q                    # (B,n_q,T,d_h)
```

mask 的 `True` 表示**填掉**该分数；`(T,T)` 从尾轴广播到每个 batch、每个头。`softmax(dim=-1)` 沿候选键归一化，不能沿头或查询轴。这里每行至少有一个允许的键；整行都填成负无穷时，普通 softmax 无法给出有效概率，不能直接沿用这一写法。

若只想查看每个查询选定的一项权重，可以用 `gather`；索引沿键轴选择，形状要显式保留其他轴：

```python
key_index = torch.zeros((1, 2, 2, 1), dtype=torch.long)
first_key_weight = weights.gather(-1, key_index)
assert first_key_weight.shape == (1, 2, 2, 1)
assert torch.equal(first_key_weight[..., 0], weights[..., 0])
```

`gather` 的结果 shape 跟索引相同；它是逐位置读取，不会替我们把整数索引广播成所有头。代码里重复给出两头、两查询的索引，是为了让目标轴明确。布尔索引可能压平所选元素，而 `masked_fill` 保留原 shape；两者用途不同。

## 合并回时间序列：先换轴，再合并

`context` 仍为 `(B,n_q,T,d_h)`。下一层需要每个时间位置的一行四通道向量，因此必须先恢复 `(B,T,n_q,d_h)`，再把相邻的头、头内通道合并：

```python
restored = context.permute(0, 2, 1, 3).reshape(1, 2, 4)
assert restored.shape == X.shape
```

若直接 `context.reshape(1,2,4)`，元素个数和 shape 都对，但逻辑遍历先走完头 0 的两个时间位置，再走头 1；它会把时间和头混在一起。取未经过注意力的 Q 做对照最清楚：

```python
correct = Q.permute(0, 2, 1, 3).reshape(1, 2, 4)
wrong = Q.reshape(1, 2, 4)
assert torch.equal(correct, X)
assert not torch.equal(wrong, X)
```

真实注意力输出通常还会经过输出投影；本章只负责保证交给投影的轴和数值顺序正确。下一章 [F4 自动微分](/frameworks/autograd/) 再追问：这条前向路径被记录后，梯度怎样回到输入和参数。

## 存储边界：view、reshape 与 expand 不能互换

`permute` 是视图，改变坐标解释而不重排存储；`view` 也只能在 stride 兼容时改变形状。`reshape` 保证逻辑值和目标形状，但**可能返回视图，也可能复制**。例如连续的 `x=torch.arange(6).reshape(2,3)` 可 `view(6)`；`x.T` 的逻辑展平顺序为 `[0,3,1,4,2,5]`，无法直接 `view(6)`，而 `reshape(6)` 会为本例复制。若运算明确需要连续布局，`contiguous()` 可以整理；输入已连续时它可能返回自身。把它塞进每个 reshape 前既不修正轴错误，也可能增加搬运。

`unsqueeze` 添加长度一的轴；`expand` 可让这条轴用零 stride 表现为多个位置。比如 `[[1,2,3]].expand(2,3)` 两行共享原存储，修改源值会同时反映在两行。`repeat(2,1)` 则实际复制数值，但仍可把梯度传回源张量。零 stride 的扩展结果有重叠地址，不应按独立格子批量原地写；需独立修改时先 `clone()`。`squeeze()` 无参数会删除**所有**长度一的轴，B=1 时可能误删 batch，最好指定确实要删的轴。

从 NumPy 到 Torch 后，F1 的判断仍适用：检查值、shape、轴身份和共享关系，别让其中一项代替其余项。Torch 还增加 dtype、device 与自动微分历史这几层契约；`clone` 只保证新存储，是否停止求导要另行决定。脚本把同一份六个数走完整条路径，并用非方形轴、共享/复制与 mask 断言检查常见错位：

## 常见误区

- `reshape(B,T,n_q*d_h)` 能自动交换头和时间。它只按当前逻辑顺序分组；必须先 `permute` 回 `(B,T,n_q,d_h)`。
- `reshape` 总是复制，或总是共享。两者都不成立；需要独立存储时明确 `clone()`。
- mask 的 `True` 是保留位。本章的 `masked_fill` 在 True 处填负无穷；候选全部被遮住还会产生未定义归一化。
- `B=1` 时随意 `squeeze()` 不影响接口。它会删除 batch 轴，后续矩阵乘与广播的含义都可能变化。

## 练习与核对

<details>
<summary>为何 X3 与 A 会互相影响，而 X 与 A 不会？</summary>

`from_numpy(A)` 共享 A 的缓冲区，`unsqueeze(0)` 只在同一缓冲区上加轴，所以 X3 的元素写入会传回 A。`cat([X3,zero],dim=-1)` 生成新的四通道结果；随后改 A 不会改已创建的 X。这里的结论针对本例构造，不由 shape 单独推出。
</details>

<details>
<summary>本例 Q[0,1,1,0] 为什么是 5？若直接把 Q reshape 成 (1,2,4)，第二行仍会是 [3,4,5,0] 吗？</summary>

原数 `A[1,2]=5` 对应 X 的时间 1、通道 2；每头两通道，通道 2 是头 1 的头内通道 0，因此 Q[0,1,1,0]=5。直接 reshape 的第二行会从当前 `(头,时间,通道)` 遍历顺序取数，成为 `[2,0,5,0]`；正确合并先交换回时间优先，得到 `[3,4,5,0]`。
</details>

<details>
<summary>变式：输入 shape 为 (2,3,8)，分成 4 个头。写出拆头、注意力分数与合并后的 shape，并指出哪一步不能省。</summary>

每头宽度为 2：`reshape(2,3,4,2).permute(0,2,1,3)` 得 `(2,4,3,2)`；与键转置矩阵乘，分数为 `(2,4,3,3)`。头内输出仍是 `(2,4,3,2)`，先 `permute(0,2,1,3)` 再 `reshape(2,3,8)`。合并前交换轴不能省，否则时间与头错位；可以用给每个元素不同编号的输入检查。
</details>

<details>
<summary>为什么不能把形状为 (2,2) 的 future mask 直接理解为整个 scores 的四条轴？</summary>

scores 是 `(B,n_q,T_query,T_key)=(1,2,2,2)`，mask 的两轴从尾部对齐，只表示查询和键，不指定 batch 或头。它被广播到每个头；若想让不同头有不同规则，须显式加入头轴并检查广播结果。
</details>
