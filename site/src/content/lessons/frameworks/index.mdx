数学公式里的 $XW+b$ 没有告诉程序哪条轴是样本、哪些对象共享存储，也没有说明梯度存在哪里。假设输入是两行、每行三个数：`[[0,1,2],[3,4,5]]`。取出两列后修改它，原输入会变吗？给每行加上同一个向量，哪条轴被复用？这两个问题若答错，即使输出 shape 看起来正确，后面的模型也可能算错。

这条路线先让每一步的**值和轴**可核对，再加入**梯度、参数和训练状态**。你需要 Python 基础；矩阵乘法可参照 [M3 向量与矩阵](/math/linear-algebra/)，手算反向传播可参照 [M6](/math/backprop/)。刚接触数组时可以先读 F1–F3，学过 M6 后再继续 F4。

## 从六个数走到一次更新

<ChapterList track="frameworks" />

[F1 NumPy 数组与存储](/frameworks/numpy-arrays/) 从上面的 `2×3` 数组出发，逐格追踪索引、切片、stride 和视图与副本。知道取出的四个数来自哪里后，[F2 NumPy 的轴与计算](/frameworks/numpy-computation/) 把两条三特征记录用于广播、归约、矩阵乘和 softmax。此时要同时检查一个具体元素的值，以及哪条轴被保留或消去。

[F3 PyTorch 张量与轴](/frameworks/torch-tensors/) 沿用 F1 的六个数，先辨认 NumPy 与 Torch 的共享存储，再有意把两行解释为序列的两个位置，拆成注意力头、读取并合并。这个解释变化会在正文标明；相同的数字不意味着相同的轴含义。准备实现 [P3 多头注意力](/principles/attention/) 时，F3 是直接的接口先修。

有了张量，[F4 自动微分与梯度状态](/frameworks/autograd/) 用一个带分支的损失核对 `.backward()`：哪些叶子张量得到梯度、两条路径的贡献怎样相加，以及为什么重复反向和重复前向不同。[F5 模块、参数与损失](/frameworks/modules-and-losses/) 随后把层登记成模型，用两条短序列追踪 embedding、输出 logits（softmax 前的类别分数）和有效目标交叉熵。到这里，已经能说明一次前向的参数与损失从哪里来。

[F6 数据、更新与训练状态](/frameworks/data-and-training/) 换用五个可手算的样本，把单次前向放进 `2+2+1` 的批次、梯度更新和 checkpoint（保存的训练状态）中。重点是尾批的分母，以及暂停后如何读到同一批数据并做出同一次更新。接下来可进入 [P1 文本、token 与 embedding](/principles/tokenization/) 构造语言模型输入，再沿 [训练路线](/training/) 完成文档处理和实验评估。

## 重复运行同一计算时

如果模型已经能正确运行，需要判断重复执行的开销，再读 [F7 torch.compile](/frameworks/torch-compile/)。它用同一个三元素函数比较普通执行与编译执行，解释首次调用、guard、图中断和重新编译；先核对结果与梯度，再计算编译成本需要运行多少次才能收回。F7 不要求先学 GPU kernel；要研究底层执行和测量，可继续读 [GPU 路线](/gpu/)。

从 [F1](/frameworks/numpy-arrays/) 开始，每章都先对一个小输入写出预期值和形状，再运行配套脚本核对。只看 shape 无法发现错轴；只看一次前向也无法确认梯度与恢复状态。
