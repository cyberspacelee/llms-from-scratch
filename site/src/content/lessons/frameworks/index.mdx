把 $Y=XW^\top+b$ 写成程序时，必须知道 `X.shape` 的轴、`X.T` 的存储关系，以及偏置沿哪个轴广播。训练还要追踪 `loss.backward()` 后的梯度和模型保存的状态。本路线用具体数组和小模型核对这些 API 的行为。

本路线放在数学与模型原理之间，使用已有 NumPy 与 PyTorch 依赖，回答数组操作和训练对象的常见问题。章节代码 F 表示框架路线，代码里的 `torch.nn.functional as F` 是 Python 模块别名，二者由上下文区分。已经熟悉这些 API 可以直接进入 P；第一次接触数组的人，可在 M3 后先读前三章，再随着数学路线学自动求导与训练接口。

## 七章：从轴与状态走到编译执行

<ChapterList track="frameworks" />

| 章 | 从什么问题进入 | 读完应能解释 |
| --- | --- | --- |
| F1 数组 | 六个数字组成 2×3 表 | 索引、轴、dtype、视图/副本与修改传播 |
| F2 计算 | 一批样本加偏置，再沿轴求统计量 | 广播、归约分母、矩阵乘法与元素选择 |
| F3 张量 | 从 NumPy 进入 Torch，并重排多头轴 | 存储共享、设备、stride、view/reshape 和 gather |
| F4 求导 | 一个输入经过分支，梯度回到哪里 | 叶子张量、VJP、梯度累积、detach 与求导模式 |
| F5 模块 | 多个运算怎样成为可训练的网络对象 | 参数登记、线性权重、嵌入、归一化与损失契约 |
| F6 状态 | 五个样本怎样形成三批并恢复训练 | 尾批、有效分母、优化器、随机状态与 checkpoint |
| F7 编译 | 同一段张量程序怎样被捕获和重复执行 | Dynamo、AOTAutograd、Inductor、guards、图中断与重编译 |

同一组数值可以有不同形状，两个数组对象也可能共享存储；前向结果相同的运算可能处在不同的求导模式中，加载同一份权重也不能恢复优化器历史。遇到结果异常时，按值、轴、存储、梯度和状态逐项检查。

## 阅读路径：就近补齐正在使用的 API

- 学 [M3](/math/linear-algebra/) 时遇到一维数组转置、广播或 `@`，回读 F1/F2；继续研究轴重排时再读 F3。
- 学 [M6](/math/backprop/) 时已经会手算链式法则，再读 F4，解释 `.grad` 与图记录的实际行为。
- 写 [P1 嵌入](/principles/tokenization/) 与 [P4 Decoder](/principles/decoder/) 前，读 F3/F5，对齐 token 索引、模块参数和各个张量轴。
- 在 [T1 数据](/training/data/)、[T2 优化](/training/optimization/) 与 [T3 完整训练](/training/pretraining/) 之前，读 F6，分清加载器、优化器和状态文件。
- 进入 [G1 GPU 执行模型](/gpu/execution-model/) 时，数组地址与 stride 可回读 F1/F3；框架的 device 与底层线程分工属于不同层次。
- 给训练或推理程序加 `torch.compile` 前，读 [F7](/frameworks/torch-compile/)；性能部分结合 G3/G4，CUDA Graph 再连接 S6。

M 解释数学原因，F 解释接口契约，P 解释模型结构，T 解释训练算法和实验。新路线不会用 `softmax` 这个函数名代替概率推导，也不会用一个 checkpoint 示例代替完整恢复协议。

## 一次操作的核对清单

| 维度 | 核对的问题 | 常见例子 |
| --- | --- | --- |
| 值 | 结果与手算是否一致，是否有限 | stable softmax、归约与交叉熵 |
| 轴 | 输入输出形状和各轴身份是什么 | batch、时间、头、特征、类别 |
| 存储 | 返回对象共享数据还是独立复制 | 基础切片、转置、from_numpy、clone |
| 类型与设备 | dtype/device 是否符合接口 | token long、float64 核对、CPU/GPU |
| 梯度 | 操作是否记录，谁的 grad 会累积 | leaf、detach、no_grad、backward |
| 状态 | 操作读取或改变哪些长期状态 | RNG、optimizer.step、train/eval、state_dict |

例如 `.reshape` 只改数值组织这一句话不够：还要问新布局能否由原 stride 表示，必要时是否复制。`.eval()` 也只说明模块模式，不能推断没有计算图。每章会用短代码和图，让这些问题对应到实际对象，完整脚本再以断言核对。

## 运行与可视化的边界

全部七章的 CPU 示例位于 `code/frameworks/`，安装使用仓库统一的 `code/requirements.txt`。数学核对优先 float64，token 索引用 int64/long；这不是建议大型 GPU 模型全部用 float64。实际验证版本记录在验收文档，本轮使用 NumPy 2.5.2 与 PyTorch 2.14.0+cpu。F7 默认核对捕获、缓存与 AOT 求导，额外的 `--inductor` 检查需要兼容的本地 C++ 编译器；CPU 结果不代表 GPU 性能。
