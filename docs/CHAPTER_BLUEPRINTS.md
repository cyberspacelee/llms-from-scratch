# 章节内容设计卡

对应 [课程大纲与审计](CURRICULUM_PLAN.md)，研究日期 2026-09-27。下面保留逐章内容设计依据；实际正文位于站点内容集合，实施与验收记录见 [课程进度](CURRICULUM_PROGRESS.md)。

编号采用规划编号：M1-M7、P1-P10、T1-T6、S1-S10，以及 A1-A9。每章按一个核心问题组织；“先修”是进入主线的必要条件，选读另列。来源与旧文迁移见大纲，本文补充具体讲解顺序、算例和验收。

## M：数学基础

### M1 概率与统计

- 问题与先修：怎样从观测估计整体规律；Python、四则运算、求和符号。
- 顺序：随机结果和变量 → 条件与联合 → 加权期望 → 方差与协方差 → 估计量 → 批大小和统计轴。保持现有算例；语言模型只作动机，不提前引入 token 的技术细节。
- 算例：保留四条损失记录、来源计数表和 `(B,d)` 标准化；与后续文档级数据切分建立简短联系。
- 验收：手算条件概率、两种方差和相关样本均值波动；复用 `code/math/probability.py`。区分分布假设与有限抽样结果。

### M2 分布与信息量

- 问题与先修：预测概率怎样变成损失；M1，指数与对数规则在章内解释。
- 顺序：伯努利/类别 → logits 到概率 → 正态密度 → 似然/NLL → 熵/CE/KL → 稳定 log-softmax。最大似然极值和熵二阶导数标为 M4 后回读，不作为继续学习的门槛。
- 算例：`[0,log 2,log 3]` 的三类概率、独热 NLL、极端 logits；序列乘积只说明条件结构，P2 再完成标签组织。
- 验收：区别密度和概率、CE 和熵、sum 和 mean；复用现有脚本与小数组核对。不要要求读者提前计算未定义的导数。

### M3 向量与矩阵

- 问题与先修：形状怎样决定共享计算；实数运算，不依赖微积分。
- 顺序：坐标与轴 → 长度/距离/点积 → 矩阵乘法 → 转置 → 单样本与批线性层 → 高阶批乘 → 秩与正交。先逐元素，再用矩阵简写。
- 算例：保留轴长互不相同的广播例子；补一句 embedding 是选行而不是任意线性投影，完整介绍放 P1。
- 验收：独立解释 `(B,T,d)` 的运算轴；复用 `code/math/linear_algebra.py`。低秩分解链接 T6，不把低秩更新与原矩阵分解混为一谈。

### M4 微积分与梯度

- 问题与先修：小变化怎样影响损失；M3，函数和代数。
- 顺序：极限/导数 → 基本规则与简单复合 → 偏导/梯度 → 一阶近似 → 梯度下降 → 对角二次函数的步长。积分、二阶分析和谱推广作为可回读分支。
- 算例：保留 `(2,1)` 起点的二次损失与学习率对照；选读特征值时先定义 `Av=lambda v`，用对角矩阵演示，再引入正定。
- 验收：手算一步更新、区分振荡和发散；复用 `code/math/calculus.py`。有限阶 Taylor 不能在导读中被等同为已教授完整幂级数。

### M5 矩阵求导

- 问题与先修：怎样组织所有参数的偏导；M3/M4 的局部链式规则。
- 顺序：标量目标的梯度形状 → 向量输出的雅可比 → 单样本线性层 → 批梯度 → 广播归约 → 手算/自动微分/差分核对。迹记法和一般微分形式放选读，先给逐元素依据。
- 算例：继续用已有平方误差例子，输出维和批大小不相等，暴露误把所有轴平均的错误。
- 验收：公式、PyTorch 和中心差分比较同一目标；复用 `code/math/linear_algebra.py`。清楚说明这里仅提供局部规则，M6 才完成整图传播。

### M6 链式法则与反向传播

- 问题与先修：共享节点怎样汇总来自损失的影响；M4/M5。
- 顺序：标量复合 → 分支累加 → 逆依赖顺序 → 向量 VJP → 两层网络 → 共享偏置。微批累积与图资源 API 独立回读，主线先完成一次反向。
- 算例：保留共享平方节点和两层手算；残差的恒等分支作为 P4 的先修。保留大小不同的微批例子，T2 扩展为有效 token 加权。
- 验收：会解释为何梯度相乘或相加，以及 `backward` 不更新参数；复用 `code/math/calculus.py`，不复制求导框架。

### M7 神经网络训练

- 问题与先修：预测怎样闭合为更新；M2、M5/M6。
- 顺序：非线性表达能力 → 参数初始化 → 前向概率与 CE → 反向 → SGD 循环 → eval 与求导边界 → 训练/验证/测试。保留 XOR 的完整闭环。
- 算例：继续四个 XOR 样本；结尾比较“固定输入预测两类”和“每个位置在上下文下预测词表一类”，只说明任务变化，不直接跳 Q/K/V。
- 验收：复用 `code/math/neural_network.py`；区分能表示、能拟合、能泛化。进入 P1 前，读者已懂可训练向量与查表所需的形状。

## P：模型原理

### P1 文本、token 与嵌入

- 问题与先修：字符串怎样成为网络输入；M2/M3/M7。
- 顺序：字符/字节/子词的区别 → 词表与 ID → encode/decode → 特殊 token → 手算 BPE 合并 → 固定分词规则 → embedding 查表 → 重复 ID 的梯度相加。
- 算例：一段含中文和英文的短文本，先字符级，再展示 UTF-8 字节；极小训练词串手算一次 BPE。嵌入用词表 8、维度 4，核对 `E[ids]` 与独热选择。说明教学 BPE 未覆盖生产预分词全部细节。
- 验收：受控文本编码解码往返，词表 ID 与尺寸检查；重复 token 的嵌入梯度与手算相等。未知字符策略显式定义。BPE 依据 [原论文](https://aclanthology.org/P16-1162/)，不把字符级算法宣称为 byte-level BPE。

### P2 下一 token 预测

- 问题与先修：怎样用分类预测一段文本；P1、M1/M2/M7。
- 顺序：序列链式概率 → 给定上下文的类别分布 → input/target 错位一格 → teacher forcing → 每位置 NLL → 有效位置平均 → bigram 表模型 → 训练与生成数据的区别。
- 算例：`[BOS,A,B,EOS]` 的输入 `[BOS,A,B]` 与标签 `[A,B,EOS]`；bigram logits 表逐行 softmax，手算三项损失与一次 SGD。位置使用 0 起点，明确 BOS 的任务。
- 验收：手算与交叉熵一致；增加 padding 不改变有效位置平均；故意不移位的标签失败。此处可以有基础一步采样来观察模型，但完整生成策略在 P9。

### P3 注意力与多头

- 问题与先修：一个位置怎样读取其他位置；P1/P2、M2/M3。
- 顺序：内容加权读取 → 查询/键/值 → 单头数值 → 点积方差与缩放 → softmax 与加权和 → 批计算 → causal/padding mask → 分头和拼接 → 输出投影。
- 算例：保留旧 P1 的单查询例子；扩展为 `B=2,T=4,d=4,n_q=2,d_h=2`，单独画头轴。展示 causal mask 只允许历史，不把 loss mask 当注意力 mask。
- 验收：逐查询参考与矩阵实现相等；未来 token 改动不影响过去输出；不同样本不串扰；全屏蔽行显式处理。GQA 留 P8，不提前假设头数不同。

### P4 一个完整的 Decoder

- 问题与先修：注意力如何构成预测词表的模型；P2/P3、M6/M7。
- 顺序：embedding 和学习式位置表 → 一个 Pre-LayerNorm Decoder 块 → 残差 → 两层 GELU FFN → 多层堆叠 → 最终归一化与 LM head → logits/损失/反向 → 三种 Transformer 架构的小图比较。
- 算例：手算案例只跟一个位置的局部值，完整前向在 CPU 上跑；逐层打印 `(B,T,d)`，末端 `(B,T,n_vocab)`。这里明说采用教学 Pre-Norm 变体，2017 原始模型的 Post-Norm 与结构差异另示小图。
- 验收：完整模型前向和反向、因果性、参数计数；随机权重可以输出 token，但尚不能称为训练成功。位置表的意义先直观定义，P5 再证明为何需要它，避免循环先修。

### P5 注意力为什么需要位置

- 问题与先修：哪些运算携带顺序信息；P3/P4、M3。
- 顺序：去掉位置的受控对照 → 双向单层注意力置换等变 → token-wise 模块保留性质 → 因果掩码的边界 → 学习式绝对位置 → 内容/位置交叉项 → 表外位置问题。
- 算例：复用旧 P1 置换例子；对照“同时重排 mask”和“保留固定 causal mask”，让证明假设可见。
- 验收：置换等变与因果反例均可运行；不能把双向证明扩展成“因果模型完全不知道顺序”。原 DotProductLab 留在点积动机附近，并链接 M3。

### P6 从旋转到 sin/cos

- 问题与先修：有界位置函数如何表示固定偏移；P5、M3，弧度和三角规则就地说明。
- 顺序：编码要求 → 二维旋转 → 长度与相对角 → 极坐标 → sin/cos 排列 → 几何频率 → 完整位置编码 → 相对核与一般投影反例。完成主线后再读生成元/矩阵指数。
- 算例：复用 `(3,4)` 旋转和 `d=8` 频率表；图、FrequencyLab 与脚本保持同一频率编号。
- 验收：复用 `code/principles/position_encoding.py`；说明周期、非单调与 sin/cos 加法 PE 的边界。矩阵指数选读先补级数收敛的必要说明和线性微分方程解的依据，不将其设为 RoPE 的硬先修。

### P7 相对位置与 RoPE

- 问题与先修：怎样使显式位置项依赖相对位移；P3/P6、M3，梯度部分需 M6。
- 顺序：目标点积 → 二维旋转主等式 → 高维分块 → 幅度和相位 → 实数代码 → 梯度 → 与 Shaw/T5/ALiBi 比较。复数、欧拉展开和范数语义研究是回读分支。
- 算例：复用四维旋转与 q/k 手算；补 interleaved 与 half-split 配对的排列桥，核对实际模型的布局，不认为所有模型都按相邻两维实现。
- 验收：已有相对关系/共同平移/梯度检查保留；配对布局先排列再比较。把“固定内容下的位置算子性质”与整模上下文行为分开。

### P8 现代稠密 Decoder

- 问题与先修：现代 Llama/Qwen 对教学块改变了什么；P4/P7、M1/M3。
- 顺序：基础块结构图 → LayerNorm 与 RMSNorm → Pre-Norm 的残差路径 → SiLU/SwiGLU 三矩阵 → MHA/MQA/GQA → QK-Norm 所在位置 → embedding/LM head 共享 → 公开配置差分。
- 算例：一行向量手算 LN/RMSNorm，4 个查询头共享 2 个 KV 头的小例子，SwiGLU gate/up/down 的形状。使用 Llama 3 8B 和 Qwen3-0.6B 的命名配置；不假设 `d=n_q*d_h` 对所有模型都成立。
- 验收：各模块与明确的参考表达式一致，数出参数和 KV 状态；共享权重按实际对象去重。QK-Norm 不是单位化。依据 [Qwen3 架构](https://arxiv.org/html/2505.09388v1#S2)；正式写作再锁定官方配置与 nano-vLLM 快照的兼容边界。

### P9 生成、采样与对话输入

- 问题与先修：一次前向如何扩展为一段回答；P2/P4，现代模型例需 P8。
- 顺序：无缓存完整重算 → 取最后有效位置 → greedy 与类别采样 → 温度 → top-k/top-p → EOS/长度终止 → 左填充与每请求状态 → chat template → Base/Instruct 的用途差异。
- 算例：三类 logits 手算温度与截断概率；列出 prompt `[A,B,C]` 到采样 D、再输入 `[A,B,C,D]` 的两步表。对话模板展示实际特殊 token，不把角色名当新增神经层。
- 验收：概率非负且和为 1、截断保留规则明确、EOS 不越界、不同长度请求取对位置；固定随机源复现教学采样。改变采样设置不修改模型权重。推理脚本可以用随机模型验证流程，质量结论等待 T3/T4。

### P10 KV cache 的正确性

- 问题与先修：哪些历史结果追加后不变；P7/P9、P4 的完整块，GQA 对照需 P8。
- 顺序：先量化普通重算 → 单层缓存 → 绝对位置 → 矩形 mask → 多层归纳 → GQA 缓存形状 → 完整模型对照 → padding 与有效长度 → 数学等价和浮点容差。长上下文改频率迁 A4。
- 算例：复用现有预给定 Q/K/V 脚本；新增两层 Decoder 的完整 logits 对照、不同分块和不同提示长度。画出采样 token 与已缓存 token 之间的一步差。
- 验收：eval 下 full/cached 在各位置接近；错误重置位置、重复旋转和缺失一层缓存会失败。普通缓存可先 `torch.cat`，S5 再优化；同一采样种子并不保证近似 logits 下文本总相同，主要比较 logits。

## T：训练与适配

### T1 数据与样本构造

- 问题与先修：原始文本怎样成为无泄漏的训练样本；P1/P2。
- 顺序：语料与许可 → 文档身份 → 文档级划分 → 去重 → 只在训练数据拟合 tokenizer → EOS/窗口 → packing → mask → 有效 token 统计 → 数据混合。
- 算例：包含重复文档的十条小语料，展示“先切窗口再随机切分”如何泄漏；两条文档拼接时分别说明连续语料与文档隔离策略。
- 验收：划分无文档重叠，tokenizer 不读验证集，标签移位/边界/mask 与手算一致。重复、近重复与跨集污染分别解释，不把简单精确去重当作解决全部污染。

### T2 优化与训练稳定性

- 问题与先修：参数怎样更新，训练状态怎样累积；M6/M7、T1。
- 顺序：SGD 回顾 → 一阶矩/二阶原始矩 → 偏差校正 → Adam → AdamW 解耦衰减 → 学习率日程 → 全局梯度裁剪 → 按有效 token 累积 → 精度/状态与异常定位。
- 算例：两个参数、两步手算 AdamW；不等长序列用每微批有效 token 数加权，与整批梯度对照。初始优化器状态与模型参数分开画。
- 验收：与明确配置的 PyTorch 更新一致，微批与整批在固定逐样本计算条件下相等；说明 dropout 等为何影响逐次等价。FP16 loss scaling 与 bf16 分开；GPU 混合精度测量可选。参考 [AdamW](https://arxiv.org/abs/1711.05101)。

### T3 从零训练一个小语言模型

- 问题与先修：怎样完成可恢复的训练闭环；T1/T2、P4/P9/P10，现代块实验需 P8。
- 顺序：固定教学配置与基线 → 构造 batch → 初始验证 → 前向/损失/反向/更新 → 定期验证 → 保存参数、优化器、RNG、数据游标 → 恢复 → 生成 → 缓存核对。
- 算例：从字符级两层 Decoder 开始，固定小语料；与 P2 bigram 比较相同有效 token 上的验证 NLL。BPE 与现代块作为单项消融，变 tokenizer 后不直接比较 token PPL。
- 验收：在指定运行环境中中断恢复与连续运行的下一步参数一致；先对极小批过拟合定位正确性，再报告验证集表现。耗时和损失阈值在跑通后确定，不能预先编造训练曲线或保证小模型一定胜出。

### T4 模型评估与受控实验

- 问题与先修：观察到的改善是否支持结论；P9、M1/M2。可以使用 T3 的小模型或公开 checkpoint，不要求先自行完成训练。
- 顺序：固定 checkpoint/数据/tokenizer → 有效 token NLL → PPL → 有限窗口与步幅 → 微型任务评分 → 样本量/方差 → 模板与 decoding 控制 → 消融 → 数据污染与报告边界。
- 算例：手算三项 NLL 与 `exp(mean NLL)`，两种序列长度的 token 加权；短距离复制任务检验位置，延后长距专项。展示逐请求平均和逐 token 平均不一致。
- 验收：指标与手算一致，相同 token 不因窗口滑动重复计入；相同模板、提示与采样设置才作受控对照。不同 tokenizer 的 PPL 不直接排名。扩展模型预算时再引 [Chinchilla](https://arxiv.org/abs/2203.15556) 的算力/数据权衡，不把经验比例当普遍定律。

### T5 指令微调

- 问题与先修：预训练续写目标怎样用于对话；T3/T4、P9。
- 顺序：Base/Instruct → 对话序列化 → generation prompt → assistant 标签 → prompt/padding mask → SFT 更新 → 训练/评估模板一致 → 微调与遗忘。
- 算例：system/user/assistant 三轮对话逐 token 列表，计算哪些标签参与损失；一条输入有两段 assistant 输出的多轮例子。
- 验收：被屏蔽位置的直接 logits 损失梯度为零，但有效回复仍可经注意力反传到 prompt 表示；微调与预训练损失选择明确。小型格式任务与未微调模型比较，避免用背熟样例证明通用 instruction following。参考 [HF 模板文档](https://huggingface.co/docs/transformers/main/en/chat_templating)。

### T6 LoRA 与参数高效适配

- 问题与先修：怎样用低秩更新适配冻结模型；T5、M3/M5。
- 顺序：全参微调成本 → `W'=W+sBA` → 两矩阵形状与参数数 → 随机 A/零 B 初始化 → 冻结与梯度 → target modules → 保存 adapter → 合并 → 质量和内存边界。
- 算例：`W` 为 `(6,4)`、rank 2，显式更新与两次小乘法对照；列向量推导后转成 `nn.Linear` 的存储布局。明确更新限制秩，不要求预训练 W 本身低秩。
- 验收：基座无梯度且参数不变，adapter 有正确梯度；初始化时 A 的梯度可能为零，不能据此判断训练失败；关闭 LoRA dropout 后合并前后输出一致。QLoRA 仅作 [量化基座加适配](https://arxiv.org/abs/2305.14314) 的预告，S7 后回读，不暗含已经学过量化。

## S：推理系统

### S1 一次生成的账单

- 问题与先修：一次执行占多少参数、状态、运算和字节；P8/P10，优化器分支需 T2。
- 顺序：教学模型矩阵列表 → 总参数与共享 → 权重存储 → KV 容量 → prefill/decode 线性 FLOP → 注意力 FLOP → 数据流量与强度 → 公开 Llama 3 例 → 优化器状态对照。
- 算例：保留现有模型 S 与 Llama 3 8B；分开 `N_total`、块内线性参数和输出头。embedding 选行，prefill 推理只算每请求末位置输出头，不能把两块词表都按每位置 GEMM 计费。
- 验收：参数账与模型结构/去重计数一致，`2NT` 明确何种 N 和哪些运算；缓存容量和本步实际读写分开。S1 的主线保持稠密 GQA，MoE/MLA 引 A1/A2，不成为初学者门槛。

### S2 GPU 执行与单卡上限

- 问题与先修：硬件峰值为何只是上界；S1。
- 顺序：CPU/GPU 分工 → kernel 与异步提交 → thread/block/warp 基础 → 寄存器/共享内存/L2/HBM → 带宽和延迟 → FLOP/s → roofline → 输入形状/精度 → 计时误区。
- 算例：保留 H100 SXM 的有日期规格；用同一资源账画计算/带宽下界，展示发射和排队也能主导延迟。名称先定义再用，不直接跳 PTX/机器码。
- 验收：会算强度与理想下界，区分算子占用、GPU utilization 和 roofline 达成率。CPU 计时不能推 GPU 结论；实际计时要同步，专业 profiling 留后续实验。

### S3 从朴素注意力到 FlashAttention

- 问题与先修：怎样减少 IO 而计算同一注意力；P3、S2、M2。
- 顺序：显式分数矩阵 → tile 与重复读取 → stable softmax 回顾 → 分块最大值与指数和合并 → 分块输出累积 → 因果/padding tile → 融合与 IO → GPU 执行与 FlashAttention-2 分工。
- 算例：一行六个分数分成两块手算 running max、分母与加权输出；第二块含更大分数，迫使第一块重缩放。推导不直接从 Triton kernel 开始。
- 验收：CPU 在线参考与 dense softmax attention 的输出一致，极端分数和 mask 反例通过；浮点求和差异有容差。正式 GPU 实验复用已有 SDPA/FlashAttention 后端，自写 Triton 放可选，不声称 CPU 版本具有相同性能。

### S4 请求生命周期与连续批处理

- 问题与先修：每次迭代计算哪些请求；P9/P10、S1，S2 解释算力动机。
- 顺序：单请求循环 → 静态批 → 请求状态 → 迭代级调度 → token 与序列预算 → prefill/decode 竞争 → chunked prefill → 抢占与重算 → nano-vLLM 快照差异。
- 算例：复用 SchedulerLab 的请求，逐步列出已生成、已缓存、新增三个计数。说明某引擎是否允许同一步混合 prefill/decode，区分 Orca 机制与 nano-vLLM 策略。
- 验收：状态转换和预算可在 CPU 参考模拟核对，无重复处理、提前采样或遗漏结束请求。分页此时只当抽象容量和拥有关系，S5 再定义物理块映射，不形成先修循环。

### S5 分页与前缀缓存

- 问题与先修：怎样管理共享 KV 状态而不改变模型计算；P10、S4。
- 顺序：连续预留 → 碎片 → 固定块与块表 → 位置到 slot → 生命周期 → 引用计数 → 前缀链 → 可写尾块和写时复制的一般需求 → 完成/抢占释放 → 固定实现边界。
- 算例：复用块大小 4、两条共享前缀请求；手算不同尾块和最后一个可复用块，展示逻辑长度与物理容量分开。
- 验收：逻辑读取与普通缓存相等；每次 allocate/share/release 后检查引用计数、唯一可写所有权、无越界。通用写时复制原则与 nano-vLLM 的保守尾块策略分开，不能描述成它已经实现了所有共享分支。

### S6 引擎执行器与 CUDA Graph

- 问题与先修：CPU 调度决定怎样映射到 GPU 前向；P8、S3/S4/S5。先读单卡主线，多卡段在 S9 后回读。
- 顺序：调度 token 清单 → padded 与 packed → 累计长度 → 绝对位置/slot/block table → 层内 cache 写读 → 权重映射 → warmup 与内存余量 → eager → 静态缓冲与 graph 重放 → 源码追踪。
- 算例：三条不同提示长的请求，手算 packed 索引与每条最终状态；解释 Q 长与 K 长不同。保持已有 nano-vLLM 固定 commit，不为了追新版本改变案例。
- 验收：CPU 元数据与参考请求逐一对应；可选 GPU 比较 eager/graph 输出、缓存写入和边界槽。跨章节只引用采样策略定义；不在执行器重讲完整分布推导或多卡通信。

### S7 量化与精度

- 问题与先修：表示精度怎样改变容量、误差与执行；M3、T4、S1/S2。
- 顺序：fp32/fp16/bf16 与整数 → 对称/非对称量化 → scale/zero point → rounding/clipping → per-tensor/channel/group → 校准与异常值 → 权重/激活/KV 区别 → kernel 和端到端质量。
- 算例：一行权重在 INT8 与极小 bit 范围下量化/反量化；对比一个 outlier 如何影响不同粒度，加入 scale 存储开销。
- 验收：范围、饱和与反量化误差可手算；总字节含 metadata。较少 bit 不保证更快，CPU 浮点模拟不等于硬件整数 kernel。SmoothQuant/AWQ 作为已定义机制后的对照，不从名称开始。T6 的 QLoRA 分支可回读。

### S8 投机解码

- 问题与先修：怎样并行验证草稿而保持目标采样分布；P9/P10、M1/M2、S1，性能分析需 S2。
- 顺序：逐步目标生成 → 草稿多 token → 批验证各条件分布 → `min(1,p/q)` 接受 → 正部残差采样 → 首次拒绝后的截断 → 全接受额外 token → 正确性 → 接受率与真实成本。
- 算例：`p=(0.5,0.3,0.2)`、`q=(0.6,0.1,0.3)`；接受质量是逐类 min，总和 0.8，拒绝后只补第二类，枚举结果回到 p。再扩展两位置缓存提交/回滚。
- 验收：有限分布枚举证明补偿后边际等于目标；测试 q 为零、全接受和拒绝分支。统计采样只辅助，不代替推导。原常数接受率等比期望放在正确性之后，性能需算草稿与验证成本。依据 [原论文](https://arxiv.org/abs/2211.17192)。

### S9 多卡推理与通信

- 问题与先修：切哪一维，传什么，何时等待；P8、S1/S2/S6。训练状态分片需 T2，专家并行需 A1。
- 顺序：完整单卡计算 → rank 与 shard → gather/reduce 的数值含义 → 列/行 TP 手算 → vocab 并行 → 副本与请求分发 → 层切分/PP 时间线 → 拓扑/通信成本 → PD 解耦 → 可选 EP 与 ZeRO。
- 算例：两卡小矩阵分别拼接列结果、相加行部分和；4 阶段、12 微批的理想流水，区分 25% 相对有效时间开销与 20% 总时间占比。忽略通信的该模型若要求气泡占比小于 5%，至少 58 微批。
- 验收：切分前后数学输出一致；collective 选择有数值依据，带宽数字注明方向和聚合。流水例是训练微批示意，不直接当作单请求自回归的速度公式。PD 分离用传输字节、固定延迟与混部损失作取舍，不声称必然有收益。

### S10 服务评估与容量规划

- 问题与先修：怎样判断系统改动对用户请求有效；T4 的评价方法、S4/S7/S8/S9。测量可以先用模拟器，真实速度需 GPU 实验。
- 顺序：引擎与客户端事件 → 排队与执行 → TTFT/事件 ITL/请求 TPOT → 输入输出分布 → closed-loop/open-loop → warmup 与同步 → p50/p95/p99 → SLO 与有效吞吐 → 资源容量 → 取消/超时与失败协议。
- 算例：三个完成时间不同的请求，手算指标；投机一次输出多个 token 的事件与逐 token 指标对照。用预先固定的请求列表比较调度策略，避免同时改模型、长度与并发。
- 验收：指标计算与事件表相等，排除首 token、单 token 请求处理明确；负载变化与尾延迟在报告中可解释。取消请求资源必须释放。模拟结果只证明协议/算法行为，真实吞吐报告硬件与版本。参考 [vLLM 指标](https://docs.vllm.ai/en/latest/design/metrics/)。

## A：进阶专题

### A1 稀疏专家 MoE

- 问题与先修：少量活跃专家怎样形成输出；P8/T2。
- 顺序：稠密 FFN → router logits → top-k → 权重与归一化约定 → 专家输出混合 → 总/活跃参数 → 负载与容量 → 训练辅助目标 → EP 的数据移动。
- 算例：4 专家选 2，逐 token 列路由与输出；Qwen3-MoE 和 DeepSeek-V3 对照共享专家、路由和负载处理，配置逐项核对。
- 验收：稀疏 dispatch 与“计算全部专家后按同一路由取值”的参考相等；不是与普通稠密 FFN 等价。参数量、活跃 FLOP、权重搬移三本账分开。

### A2 潜在注意力 MLA

- 问题与先修：压缩 KV 后哪些计算可在潜在空间完成；M3、P7/P10。
- 顺序：MHA/GQA 的状态 → 低秩潜变量 → K/V 上投影 → 内容投影吸收 → RoPE 不交换的问题 → 解耦位置分支 → 缓存账 → 推理执行边界。
- 算例：同一组 MLA 参数下，显式恢复 K/V 与吸收后的计算对照；缓存为潜变量加位置键，不按普通双份 `n_kv*d_h` 套算。
- 验收：同一 MLA 算子的两种实现一致；不宣称把任意预训练 MHA 直接压缩后仍严格等价。依据 [DeepSeek-V3 §2.1.1](https://arxiv.org/html/2412.19437v2#S2.SS1.SSS1)。

### A3 偏好优化 DPO

- 问题与先修：成对偏好怎样构成不同于 SFT 的损失；T4/T5、M2。
- 顺序：同 prompt 的 chosen/rejected → 响应条件 log-prob → 参考策略 → 对数比差 → logistic 目标 → 温度系数 → 数据与支持范围 → 与 RLHF 流程区别。
- 算例：两条短回复逐 token 求和，手算一个 DPO 损失；明确 prompt 标签不计入响应似然，padding 不进入求和。
- 验收：手算与自动微分一致，参考模型冻结；只换 token 加权/长度归约就可能改变目标，不能未经定义混用不同变体。依据 [DPO](https://arxiv.org/abs/2305.18290)。

### A4 长上下文与窗口

- 问题与先修：更长输入为什么需要改位置、缓存或训练；P7/P10/T4。
- 顺序：训练长度与可计算位置 → 插值与分频缩放 → 动态改频率缓存失配 → 滑窗可见集合 → 局部/全局层不同缓存 → 长距能力评估。
- 算例：迁入旧 P4 插值/YaRN 内容；Gemma 3 的局部/全局层作固定模型例。窗口容量、逻辑位置、物理 ring slot 分别画轴。
- 验收：窗口前向与使用相同窗口规则的缓存一致，而非与全注意力等价；长上下文任务报告长度分布与评分，不以正弦函数可求值证明有效能力。

### A5 推理模型与 RLVR

- 问题与先修：可验证奖励怎样改变生成策略；T5/A3、M1/M2。
- 顺序：策略与轨迹 → 可验证奖励 → 期望奖励 → 小型策略梯度 → baseline/组内比较 → GRPO 的目标与约束 → R1-Zero/R1 区别 → 蒸馏 → 推理预算与评估。
- 算例：四条算术候选的规则奖励与组内优势；先定义奖励和更新对象，再介绍算法缩写。推理模型可以沿用架构，变化来自训练与生成策略。
- 验收：奖励计算可复现，零方差组与无效格式明确；不会把奖励提升等同任务全面提升。小实验不声称复现 R1，SFT 蒸馏与在线 RL 分开。依据 [R1 报告](https://arxiv.org/abs/2501.12948)。

### A6 状态空间与递归模型

- 问题与先修：序列是否必须保留每个位置的 KV；P2/P4、M3。
- 顺序：标量递推 → 状态/输入/输出 → 矩阵递推 → 选择性参数 → 并行训练与串行推理 → Mamba/Mamba-2 → 状态容量和表达限制。
- 算例：四步线性递推展开与循环对照；再用输入相关的小系数观察选择性。连续时间和离散化作为有先修说明的选读。
- 验收：相同递推参数的串行/展开结果一致，状态字节清楚；与 softmax attention 是不同模型，不能用缓存等价断言它们输出相同。依据 [Mamba-2](https://arxiv.org/abs/2405.21060)。

### A7 混合与线性注意力

- 问题与先修：不同序列算子怎样在同一模型混用；P3/A6，专家结构需 A1。
- 顺序：从显式权重矩阵到有限状态累积 → delta 更新 → gate 与遗忘 → Gated DeltaNet → 混合层列表 → 注意力层 KV 与递归层状态 → Qwen3.5 固定配置。
- 算例：二维状态手算两步更新，再构造一层递归加一层全注意力的教学混合模型；逐层统计状态，不借模型名称推断缓存形状。
- 验收：每个算子只与自己的显式参考比较；线性复杂度条件、训练分块和状态尺寸分别说明。来源 [Gated DeltaNet](https://arxiv.org/abs/2412.06464) 与 [Qwen3.5 官方实现文档](https://huggingface.co/docs/transformers/main/en/model_doc/qwen3_5)，正式案例锁定源码与配置。

### A8 稀疏注意力

- 问题与先修：少读取一些位置怎样改变成本与质量；P3/P10/A2/S3。
- 顺序：dense softmax → 固定稀疏 mask → 内容相关候选选择 → indexer → sparse gather/attention → DSA 与 MLA 分工 → 选择成本 → 质量和长上下文实验。
- 算例：8 个历史位置选 3，固定索引后与 dense+mask 比较；再改变 indexer 选择观察输出差异。
- 验收：同一选择下两种实现一致，不保证等于未稀疏化模型。MoE 的专家稀疏与注意力的 token 稀疏不是一个轴。依据 [DeepSeek-V3.2](https://arxiv.org/abs/2512.02556)，不能把 FlashAttention 归类为同样的模型稀疏化。

### A9 视觉语言模型

- 问题与先修：图像怎样进入已有文本模型；P4/P9/T5。
- 顺序：图像数组与 patch → 视觉编码器 → 投影/连接器 → 图像与文本 token 序列 → 位置 → 对话模板 → 输出任务与损失 → 对齐/指令训练。
- 算例：可分发的小图像切成 patch，展示视觉特征与文本 embedding 的维度映射；简单 LLaVA 结构先于 Qwen VL 的更复杂位置设计。
- 验收：形状、占位 token 与视觉特征数量匹配，文本损失 mask 正确；只跑形状链不宣称具有图像理解能力。来源 [LLaVA](https://arxiv.org/abs/2304.08485)，模型细节在实际写作时增加官方版本记录。

## 写作与实验的共同要求

- 每章先出现读者可理解的问题，再定义新概念；主线不依赖后面的选读内容。
- 核心推导按“逐项算 → 紧凑公式 → 形状 → 代码 → 结果”推进。可以引用已推导的公式，不再次铺开同一证明。
- 图、交互和脚本使用同一配置；公开模型、教学模型、资源账例各自命名，不暗中切换。
- 验证复用现有工具；新实验只增加表达该性质所需的参考、断言和错误对照，不引入新的测试框架。
- 训练与采样含随机性时，记录种子和版本；证明靠代数或枚举，有限样本统计只支持对应实验结论。
- 未运行的实验不写结果，未核对的公开规格不写精确数值；GPU 性能与 CPU 正确性在正文中分开。
- 每章末尾交代已经获得什么，以及下一章需要解决的具体问题。章间一致性验收优先于为了字数堆积概念。
