## 读者变式核对

主代理按“本章问题 → 关键计算 → 成立条件 → 变式结果”复读。模型原理批次的代理另行独立复核了这 16 页的 diff 与真实控件，未参与其编辑。此项不是人类新手试读；真实读者独立测试尚未开展。

| 页面 | 代理变式核对 |
| --- | --- |
| GPU 导读 | block 数由任务分块决定，SM 数属于硬件；两者相同也不保证一一绑定。 |
| G1 | N=130、每块64时，启动192个 thread；129由block 2/thread 1负责，尾部62个越界。 |
| G2 | 右下tile的(2,2)有效，(2,3)无效；三个活跃列读lane在32/33列布局下分别为3/1路冲突。 |
| G3 | tile边长4→2，K段数2→4，有效输入读取154→231；数学输出仍有30个。 |
| G4 | 假想1024-thread block每thread用64个寄存器时只驻留一块、occupancy 50%；速度仍须测量。 |
| 系统导读 | 核对前向数值不足以证明服务改善；还须固定质量、负载与客户端计时边界。 |
| S1 | B=1→2、T=5，权重容量744不变，KV80→160；B=2、T=6时KV192字节。 |
| S2 | B增大摊薄权重读取，T增大增加每请求KV读取；两者作用于强度的不同项。 |
| S3 | 位置5、块长3，读一块输出约2.57521，读两块约5.43293；改位置4后约4.45194。 |
| S4 | B的prompt分为4+1；第一块只增加K，不采样。新增流程图已补K=N判断。 |
| S5 | A复制尾块后写槽10，B独占原尾块写槽6；A退出不能释放B仍持有的块。 |
| S6 | packed下标3对应B逻辑位置4、物理槽28；decode位置3/6/4分别写11/30/40。 |
| S7 | 3 bit全矩阵/逐行/两元素组输出为(0,20)/(11/3,20)/(11/3,21)，理论存储5/7/11字节。 |
| S8 | 第二候选拒绝时ID为[1,2,0,1]、KV为[1,2,0]；全接受的额外末项仍待下一轮输入。 |
| S9 | 列切分拼接不同坐标，行切分相加同坐标部分贡献，均恢复[80,90,100,110]。 |
| S10 | 只把TTFT上限.7→.5，合格集合B/C→B；事件与原始吞吐没有改变。 |

独立复核直接调用现有 TypeScript 模型，核对地址、容量、计数、输出及边界任务。交互显示会舍入数值，正文手算与脚本保留更多位数。已有检查脚本仍是这些模型的可运行校验。
