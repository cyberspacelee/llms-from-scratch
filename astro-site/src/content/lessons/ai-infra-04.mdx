第 03 章得到两个强度：单请求线性层约 1 FLOP/byte，长上下文的 decode 注意力约 4 FLOP/byte。它们快还是慢，要看这张卡每秒能搬多少字节、每秒能做多少乘加。容量、带宽和延迟是三件不同的事：放得下，不等于搬得及；搬得及，不等于一次随机访问的等待可以忽略。

```mermaid
flowchart LR
  disk[主机存储] --> dram[主机内存]
  dram --> hbm[GPU HBM]
  hbm --> l2[L2]
  l2 --> smem[Shared memory]
  smem --> reg[寄存器]
```

权重和 KV 的大头住在 HBM。一次 kernel 如果反复从 HBM 读同一块数据，带宽就被浪费在重复搬运上。Shared memory 和寄存器小得多，但够一个 block 把正在用的 tile 留住。第 05 章专门讲这种留法。线程侧只需要先记住三层：grid 是整次启动，block 是能一起同步、能共享 shared memory 的一组线程，warp 是硬件一起调度的一组线程。定义以 [CUDA C++ Programming Guide](https://docs.nvidia.com/cuda/cuda-c-programming-guide/) 为准。

## 屋顶线把两个峰值收成一个脊点

[Williams、Waterman 和 Patterson](https://dl.acm.org/doi/10.1145/1498765.1498785) 的屋顶线说：可达性能不会超过算力峰值，也不会超过「带宽 × 算术强度」。两条线的交点叫脊点。强度在脊点左边，上限贴着带宽斜线；在右边，上限贴着算力平台。

这里用 [NVIDIA H100 产品页](https://www.nvidia.com/en-us/data-center/h100/) 上 H100 SXM 一列、2026-09-22 读到的数字：80GB 显存，带宽 3.35 TB/s，FP16 Tensor Core 1979 TFLOPS，脚注写明含稀疏。去掉稀疏后的稠密峰值取一半，即 989.5 TFLOPS。产品页会改版，引用这组数时要连同日期和 SXM 这个形态一起写。NVL 那一列是另一组内存和算力，不能混用。

脊点是

$$
989.5 / 3.35 \approx 295 \text{ FLOP/byte}.
$$

带宽按 $10^{12}$ 字节/秒理解产品页上的 TB/s。第 03 章的两个强度都远在脊点左边：

$$
\begin{aligned}
1 \times 3.35 &= 3.35 \text{ TFLOP/s},\\
4 \times 3.35 &= 13.4 \text{ TFLOP/s}.
\end{aligned}
$$

相对 989.5 的平台，它们大约是 0.3% 和 1.4%。图的右下角把 0 到 10 FLOP/byte 放大，斜线才看得见；主图里这两个点贴在原点。

## 下界用来对照实测，本身不是实测

单请求 decode 若每个 token 都把 16.06 GB 权重从 HBM 读一遍，并且带宽打满：

$$
16.06 / 3350 \approx 0.0048 \text{ 秒},
$$

大约 4.8 ms，对应每秒约 210 个 token。这是权重搬运的下界。真实一步还要读 KV、启动 kernel、做采样，只会更慢。批大小上来以后，同一份权重被多个 token 分摊，这个下界才按 $B$ 下降，直到强度靠近脊点，或者 KV 变成新的大头。

同一模型、8192 token 的 prefill，仅线性层就有约 $1.32 \times 10^{14}$ 次乘加。除以 989.5 TFLOP/s，计算下界约 0.13 秒。注意力另有约 $3.5 \times 10^{13}$ 次乘加。长提示因此更接近平台，短请求的 decode 更接近斜线。优化之前先问这次负载站在哪一侧，否则会把一个带宽问题当成算力问题去调。

编程和占用率的进一步阅读从 [CUDA Best Practices Guide](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/) 进入。[Wafer 的 GPU fundamentals](https://github.com/wafer-ai/gpu-perf-engineering-resources#1-gpu-fundamentals) 把编程模型和编译链的原始文档排在一起。其他厂商的加速器同样要分开写容量、带宽和算力，数字以各自的规格表为准，见这份清单的 [Current hardware](https://github.com/wafer-ai/gpu-perf-engineering-resources#6-current-hardware)。
